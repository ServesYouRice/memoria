# IMP-089 - Empty pages offer a next step

<objective>
An empty page explains itself and offers one useful thing to do, instead of
being a dead end.
</objective>

<context>
From the 2026-11-11 UI review. `EmptyState.tsx` already accepts an optional
`action`, but Trash, Shared with me, Notifications and Recap show only an
icon and a sentence. `EmptyState` is also used by Workspaces, Search and API
keys (`TrashContent`, `SharedCanvasesContent`, `NotificationsContent`,
`RecapContent`, `WorkspacesPageClient`, `SearchContent`,
`ApiKeysContent`).
</context>

<files>
`src/components/layout/EmptyState.tsx` and the seven content files named
above, `tests/unit/`.
</files>

<acceptance>
- Each empty page says in one plain sentence what will appear there and
  offers one next step: Trash (how long things are kept, back to the
  dashboard), Shared (how sharing works), Notifications (open notification
  settings), Recap (when the first one arrives, turn it on), Search with no
  results (try other words or open the Inbox).
- The next step is a real link or button reachable by keyboard.
- A unit test covers one empty page with its action.
</acceptance>

<verification>
`pnpm test:file <new test>`; `pnpm gate fast`; screenshots of the four empty
pages named first, light and dark.
</verification>
