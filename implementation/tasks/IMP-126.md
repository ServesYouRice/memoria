# IMP-126 - Every page can be reached from a menu

<objective>
Inbox, Reminders, Weekly recap and Help can be opened from the menus on
desktop and on a phone, and the first menu entry is named after the page
it opens.
</objective>

<context>
Found in the UI audit of 2026-11-14.
- `/reminders` and `/recap` are in no menu. Reminders is linked only from
  one dialog; the recap only from an email or notification.
- `/inbox` is reachable only through a tile on the dashboard.
- Help is only in the page footer, while the account menu spends a slot
  on "API Keys".
- The first menu entry says "Dashboard" but the page it opens is titled
  "My canvases".
- `/templates` is a page nothing links to. It repeats the template picker
  that already opens from "New canvas".
Rule used: people do not use what they cannot see; every page needs a
visible way in.
IMP-127 moves API keys into Settings. Do not move API keys in this card.
</context>

<files>
`src/components/layout/AppShell.tsx` (`NAV_ITEMS`, the account `Menu`, the
phone `Drawer` list), `src/app/templates/page.tsx`,
`src/app/templates/TemplatesContent.tsx`,
`src/features/dashboard/components/DashboardContent.tsx` (reads
`?workspace=` with `useSearchParams`), `src/app/sitemap.ts`,
tests that mention `Dashboard` as a link name (`grep -rn '"Dashboard"' tests`).
</files>

<executor_constraints>
- Do not change any page's address except `/templates` (step 5).
- Keep `aria-current="page"` on the active entry.
- Use icons from `@mui/icons-material`, outlined style, like the existing
  entries.
- On desktop the top bar must still fit at 1024px wide without wrapping or
  overlapping. If it does not fit, hide the text of "Shared with me" below
  1200px by shortening it to "Shared" (keep the full name in `aria-label`).
</executor_constraints>

<steps>
1. In `NAV_ITEMS` rename the label `Dashboard` to `Canvases` (the `href`
   stays `/dashboard`).
2. In `NAV_ITEMS` add `{ label: "Inbox", href: "/inbox", icon: <inbox
   icon> }` as the second entry, after Canvases.
3. Account menu (the `Menu` opened by the avatar). Final order:
   `Settings`, `Reminders` (`/reminders`), `Weekly recap` (`/recap`),
   `Help` (`/help`), then the existing `API Keys` entry unchanged, divider,
   `Sign out`. Each new entry is a `MenuItem component={Link}` that calls
   `closeAccountMenu` on click, like the Settings entry.
4. Phone drawer: the list is built from `NAV_ITEMS` plus Notifications.
   Add `Reminders`, `Weekly recap`, `Settings` and `Help` after
   Notifications so a phone user reaches the same places.
5. Templates: make `/templates` redirect to `/dashboard?new=1` (use
   `redirect` from `next/navigation` in `src/app/templates/page.tsx`, the
   way `src/app/profile/page.tsx` redirects). Delete
   `TemplatesContent.tsx` and `src/app/templates/loading.tsx` if nothing
   else imports them.
6. In `DashboardContent.tsx`, when the address has `new=1`, open the "New
   canvas" dialog once (`setCreateDialogOpen(true)`) and then remove the
   parameter with `router.replace("/dashboard")` so a refresh does not
   reopen it.
7. Update tests: any test that finds the link by the name `Dashboard`
   now uses `Canvases`; any test of `/templates` now expects the redirect.
   The command palette text "Go to dashboard" is not part of this card.
</steps>

<acceptance>
- Desktop top bar shows, in order: Canvases, Inbox, Shared with me,
  Workspaces, Trash.
- The account menu shows, in order: Settings, Reminders, Weekly recap,
  Help, the existing API keys entry, Sign out, and each opens the right
  page.
- The phone drawer lists Canvases, Inbox, Shared with me, Workspaces,
  Trash, Notifications, Reminders, Weekly recap, Settings, Help.
- Opening `/templates` lands on the dashboard with the "New canvas"
  dialog open.
- At 1024px and 1440px wide the top bar does not wrap or overlap.
</acceptance>
