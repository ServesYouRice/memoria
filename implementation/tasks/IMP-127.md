# IMP-127 - API keys live inside Settings

<objective>
API keys are a Settings entry at `/settings/api-keys`, the account menu no
longer lists them, and the page has one "Create API key" button.
</objective>

<context>
Found in the UI audit of 2026-11-14. "API Keys" is a developer tool but
sits in the account menu next to Settings and Sign out. The page itself
shows two "Create API key" buttons at the same time (one in the header,
one in the body). Rule used: one main button per page; put rarely used
tools where people expect settings.
Do IMP-126 first: both cards edit the account menu.
</context>

<files>
`src/app/api-keys/page.tsx`, `src/app/api-keys/ApiKeysContent.tsx`,
`src/app/settings/sections.ts`, `src/app/settings/SettingsContent.tsx`
(the "Developer settings" block inside `AiGroup`),
`src/components/layout/AppShell.tsx`,
`src/app/share-target/ShareTargetContent.tsx` (links to `/api-keys`),
`src/app/help/page.tsx` (mentions "the API Keys page").
</files>

<executor_constraints>
- Do not change the API routes under `src/app/api/` or how keys are
  created, shown once, or revoked.
- `/api-keys` must keep working as an address: it redirects.
</executor_constraints>

<steps>
1. In `src/app/settings/sections.ts` add, directly before the `data`
   entry: `{ id: "api-keys", path: "/settings/api-keys", label: "API keys",
   intro: "Create keys for browser extensions and webhooks. Keep them
   secret." }`.
2. In `SettingsContent.tsx` render the keys UI for that section:
   `{section === "api-keys" && <ApiKeysContent embedded />}`.
3. In `ApiKeysContent.tsx` add an optional prop `embedded?: boolean`. When
   it is true, do not render the page's own `PageHeader` (Settings already
   shows the title and intro) and do not wrap the content in `AppShell`
   or a page `Container` a second time.
4. One create button: keep the "Create API key" button that sits with the
   list of keys and delete the other one. When there are no keys yet, the
   empty state's button is that one button. The "Create a key for my
   iPhone" shortcut button may stay because it does a different thing.
5. Make `src/app/api-keys/page.tsx` redirect to `/settings/api-keys`
   (same pattern as `src/app/profile/page.tsx`).
6. Remove the `API Keys` entry from the account menu in `AppShell.tsx`.
7. Remove the "Developer settings" block (title, text and "Manage keys"
   button) from `AiGroup` in `SettingsContent.tsx`.
8. Point remaining links at the new address:
   `grep -rn '"/api-keys"' src` and change each to `/settings/api-keys`.
   In `src/app/help/page.tsx` change "on the API Keys page" to "in
   Settings, under API keys".
9. Update tests that open `/api-keys` or click "API Keys" in the menu.
</steps>

<acceptance>
- The Settings menu lists "API keys" before "Your data";
  `/settings/api-keys` shows the keys list and lets a person create and
  revoke a key.
- `/api-keys` redirects to `/settings/api-keys`.
- The account menu has no API keys entry.
- At any moment the page shows at most one button named "Create API key".
- `grep -rn '"/api-keys"' src` returns only the redirect page.
</acceptance>
