# IMP-056 - Deploy Memoria on the k3s cluster

<objective>
Memoria runs on the shared k3s cluster through the private `infra` repo
(`apps/memoria/`), with staging and production overlays, like the other apps.
</objective>

<context>
The manifests are drafted in ServesYouRice/Infra#4 (branch
`memoria-staging-first`): app, sync, worker, scheduler and migration Job per
environment on the shared PostgreSQL, Valkey and R2; `kustomize build` and
`kubeconform` pass. A push to infra `main` deploys, so the PR merges only
after the owner fills its secrets and `CHANGE_ME` values (DEC-004). The app
cannot use the shared Valkey until IMP-073 lands. Left to prove: staging
smoke, a long-lived collaboration socket through Traefik (its websecure
`readTimeout` is 60s), and the restore drill.
</context>

<files>
infra: `apps/memoria/`, `apps/kustomization.yaml`, `platform/databases/`;
memoria: `Dockerfile`, `docs/operations/`.
</files>

<acceptance>
- App, sync, worker and scheduler Deployments plus a migration Job per
  environment, using the shared PostgreSQL 18, Valkey and R2.
- Ingress routes `/api/collaboration/*` to the sync service with WebSocket
  support; the ingress CIDR is set in `TRUSTED_PROXY_CIDRS`.
- Secrets are SOPS-encrypted; a restore is proven before real data (infra
  `docs/recovery.md`).
</acceptance>

<verification>
`kustomize build` for both overlays; staging smoke (`pnpm smoke` against
staging); restore drill.
</verification>
