# IMP-018 — Enforced launch limits and retention

<objective>
Apply DEC-008 as atomic server-side policy before expensive work begins.
</objective>

<steps>
1. Centralize limits for canvases, items/canvas, workspaces, shares, upload
   count/bytes, payload dimensions/points/options, versions, and AI spend/
   concurrency. Expose safe usage to clients.
2. Enforce durable user/tenant counters transactionally; IP limits are only the
   anonymous outer layer.
3. Add version-history and trash retention jobs through IMP-014. Delete in
   bounded batches with restoration/grace rules.
4. Reject oversize existing/import/template data clearly; provide an operator
   report for pre-existing violations.
5. Test concurrent creates, cancellations, reset windows, retention boundaries,
   oversized nested payloads, and usage UI.
</steps>

<acceptance>
- Concurrent requests cannot exceed a selected hard limit.
- Retention deletes only eligible data and remains idempotent.
</acceptance>

<verification>
Real-DB quota/retention tests; `pnpm type-check`; `pnpm lint`.
</verification>
