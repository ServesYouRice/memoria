# IMP-145 - Mail required in production only; staging warns and carries on

<objective>
Production refuses to start without a mail provider; staging and home
copies log a warning and start (owner decision OWN-14 in the handbook).
Sharing has a path that does not depend on mail.
</objective>

<context>
Handbook ME-07 and RUN-ME-3: on the rehearsal cluster staging boots with
`NODE_ENV=production`, so `src/lib/env.ts` (production check on
`EMAIL_PROVIDER`) applies there too, and all 35 share invitations failed
without a provider. Production versus staging must come from an explicit
deployment setting, not from `NODE_ENV`.
</context>

<files>
`src/lib/env.ts`, sharing invitation routes, infra `apps/memoria/staging`.
</files>

<acceptance>
- An explicit setting tells production from staging; only production
  requires `EMAIL_PROVIDER`.
- Without mail, a share still works (for example a copyable invite link).
- Production-shaped env tests cover both cases.
</acceptance>

<verification>
`pnpm test:file` on the env and sharing tests; `pnpm gate fast`.
</verification>
