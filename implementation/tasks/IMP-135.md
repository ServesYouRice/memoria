# IMP-135 - The canvas menu is sorted into named groups

<objective>
The "More canvas options" menu shows its commands under five headings
(Canvas, View, AI, Tools, History) with a line between groups, fits
inside the screen on a phone, and the two history commands sit together
with names that say what they do.
</objective>

<context>
Found in the UI audit of 2026-11-14. Today the menu is one flat list:
13 commands on a computer and about 22 on a phone, with no headings or
dividers. On a phone it runs off the screen. "Visual history" and
"Version history" are far apart and sound like the same thing.
Rule used (Material Design, Apple): group related commands and split
long menus.
What the two history commands really do:
- "Visual history" (`onTimeMachine`) plays the canvas back through time.
- "Version history" (`onVersionHistory`) lists saved versions you can
  restore.
</context>

<files>
`src/features/canvas/components/CanvasHeader.tsx` (`secondaryActions`,
phone `entries`, desktop `moreEntries`, both `<Menu>` blocks),
`src/features/canvas/components/TimeMachineControl.tsx` (title "Time
Machine"), `src/features/canvas/components/VersionHistoryDialog.tsx`
(dialog title), `src/features/canvas/components/CanvasBoard.tsx`
(auto-organise confirmation text),
`tests/e2e/canvas-mobile-toolbar.spec.ts`, `src/app/help/page.tsx`.
</files>

<executor_constraints>
- Do not remove any command and do not change what a command does or
  who may see it (`onX &&` checks and `isArCanvasEnabled()` stay).
- Keep the menu's accessible name "More canvas options" and the buttons
  outside the menu (Back, Share, the view switch).
- Headings must not be clickable or focusable menu items.
- No sub-menus in this card. Headings and dividers only.
- If IMP-122 landed first, some old texts are already in sentence case
  (`Time machine`, `Version history`). Replace whichever form you find.
</executor_constraints>

<steps>
1. Add a `group` field to `CanvasSecondaryAction`, `MenuEntry` and
   `MoreEntry`: one of `"canvas" | "view" | "ai" | "tools" | "history"`.
2. Give every entry its group and show the groups in this order, with
   the entries in this order inside each group:
   - Canvas: `Rename canvas` (phone only, as today), `Export canvas`
   - View: the `Switch to …` entry (phone only, as today),
     `Search canvas`, `Filter canvas by tags`, `Zoom in`, `Zoom out`,
     `Fit to screen (now N%)`, `Show grid`/`Hide grid`, the snap entry
     (these five are phone only, as today), `Present`/`Exit
     presentation`, `Dark mode`/`Light mode`
   - AI: `AI assistant`, `Auto-organise canvas`, `Sort into piles`,
     `Surprise me`
   - Tools: `Quick capture`, `Shared timer`, the AR entry (only when it
     shows today), every `Follow <name>` entry (phone only, as today)
   - History: `Replay changes`, `Saved versions`
3. Wording changes (same click handlers):
   - `Visual history` -> `Replay changes`
   - `Version history` -> `Saved versions`
   - `Auto-organize canvas` -> `Auto-organise canvas` (matches
     "Organised list")
   - phone `Enter presentation` -> `Present` (matches the computer menu)
   - phone `Disable snap to grid` / `Enable snap to grid` ->
     `Turn off snap to grid` / `Turn on snap to grid`
   - `TimeMachineControl.tsx` title `Time Machine` -> `Replay changes`
   - `VersionHistoryDialog.tsx` title -> `Saved versions` (keep anything
     else shown in that title, such as the canvas name)
   - `CanvasBoard.tsx` confirmation: title `Apply automatic layout?` ->
     `Auto-organise this canvas?`; message
     `Autopilot will reorganize N items in one atomic update.` ->
     `This moves N items in one step. You can undo it.` Write "You can
     undo it." only if Undo really reverses it (check the undo code
     next to it); if not, leave that sentence out.
4. Drawing. In both `<Menu>` blocks, before the first entry of each
   group render a MUI `<ListSubheader>` with the group name (`Canvas`,
   `View`, `AI`, `Tools`, `History`), and a `<Divider>` before every
   heading except the first. Skip a heading when its group has no
   entries. The phone's status row ("Collaboration: …") stays first,
   above the Canvas heading.
5. Phone height: give both menus
   `slotProps.paper.sx = { maxHeight: "calc(100dvh - 96px)" }` so a long
   menu scrolls inside the screen instead of running off it.
6. Search the repo for the old names
   (`grep -rn "Visual history\|Version history\|Time Machine\|Auto-organize" src tests`)
   and update help text and tests that mention them.
7. Tests: update `tests/e2e/canvas-mobile-toolbar.spec.ts`
   (`Version history` -> `Saved versions`). Add
   `tests/unit/canvas-header-menu-groups.test.tsx`: render
   `CanvasHeader` with all handlers, open the menu, and check that the
   five headings appear in order, that `Replay changes` and
   `Saved versions` are next to each other, and that every command from
   step 2 is present exactly once.
</steps>

<acceptance>
- Computer and phone menus show the headings Canvas, View, AI, Tools,
  History, in that order, with a divider between groups.
- No command was lost: every label in step 2 is in the menu when its
  handler is supplied.
- `Replay changes` and `Saved versions` sit together under History;
  the words "Visual history", "Version history" and "Time Machine" are
  gone from the screens.
- At 390x844 and 320x640 the open menu stays inside the screen and
  scrolls.
- Arrow keys move through commands and skip the headings.
</acceptance>
