# IMP-050 - Make local push checks proportional and fail-safe

<objective>
The pre-push hook gives fast, change-related feedback without weakening the
repository gate: lint and type-check always run, relevant tests run for ordinary
code changes, and the full unit/API suite remains mandatory in CI and whenever
the hook cannot select tests safely.
</objective>

<files>
`.husky/pre-push`, `package.json`, and, only if selection logic cannot remain
small and testable in the hook, one narrowly named helper under `scripts/` plus
its test under `tests/unit/`. Treat `.github/workflows/ci.yml` as read-only
evidence that CI retains the full suite.
</files>

<context>
IMP-053 owns focused commands and test environments, while IMP-052 owns
first-run timeouts, mock leakage, and the three-run full-suite baseline. This
card owns only `.husky/pre-push`, which runs the complete unit/API suite
for every push, including documentation-only changes. CI already runs the full
suite. Local selection is acceptable only when it fails closed; an ambiguous
ref, unsafe input, shared test configuration change, or selector error must run
the full suite rather than silently skip tests.
</context>

<steps>
1. Preserve the hook's unconditional lint and type-check checks and their
   non-zero exit behavior.
2. Read the local/remote ref tuples supplied to a Git pre-push hook and compute
   the pushed diff without interpolating ref or path text into an evaluated
   shell command. If a trustworthy comparison base cannot be found, select the
   full unit/API suite.
3. For ordinary tracked JavaScript/TypeScript source or test changes, run
   Vitest's related-test selection through an explicit non-watch command. Pass
   filenames as argument values, not as generated shell source.
4. Run the full unit/API suite for changes that can affect global collection or
   execution, including Vitest/setup configuration, package or lock files,
   TypeScript configuration, Prisma schema/client setup, and the selector
   itself. Also fall back to the full suite if related-test selection errors.
5. Permit documentation-only pushes to omit Vitest after lint and type-check
   pass. Keep the full unit/API suite unchanged in CI.
6. If a helper script is introduced, cover base resolution, path
   classification, full-suite fallback, and paths containing spaces or shell
   metacharacters with hermetic unit tests. Do not invoke a remote or mutate Git
   history from those tests.
</steps>

<stop_conditions>
- Stop and add a `DEC-` row if changing the hook requires a product decision
  about checks other than test selection.
- Do not modify application code, relax lint/type/test failures, add retries,
  use `--no-verify`, or alter the CI full-suite command.
- Do not guess that an unresolved ref is documentation-only; run the full
  suite.
</stop_conditions>

<acceptance>
- Lint and type-check run for every push and any failure blocks the push.
- A representative source/test change runs the related unit/API tests in
  non-watch mode.
- A shared test/configuration change and every selection failure run the full
  unit/API suite.
- A documentation-only change does not pay for the full Vitest suite.
- Paths and ref input cannot inject shell commands or split a filename into
  unintended arguments.
- CI still runs the complete unit/API suite for every push and pull-request
  event configured in `.github/workflows/ci.yml`.
</acceptance>

<verification>
Run the helper's focused unit test if one exists; exercise the selector against
representative documentation, source/test, shared-config, new-branch, and
unresolvable-base inputs; then run `pnpm lint`, `pnpm type-check`, and
`pnpm test -- --run` once. Inspect `.github/workflows/ci.yml` and report its
unchanged full-suite command. Do not claim an actual push was tested unless one
was performed.
</verification>
