# IMP-050 - Make the unit and API gate deterministic

<objective>
`pnpm test -- --run` passes reproducibly on a developer machine and in CI, and a
failure in it means a behavior regression rather than harness contention.
</objective>

<files>
`vitest.config.ts`, `vitest.setup.ts`, `tests/api/auth-verification.test.ts`,
`tests/unit/search.test.ts`, `tests/api/uploads.test.ts`, the shared test
setup/import graph, `.husky/pre-push`, `.github/workflows/ci.yml`.
</files>

<context>
Confirms Codex TEST-01 and reinstates Opus PROD-02, which IMP-039 rejected on the
strength of its evidence rather than its claim. Three independent runs across
both audits and this reconciliation report the same signature: 6 files and 7
tests failing, 407 of 414 passing, every failure a 5000 ms timeout, with
`import 78.31s` against a 17.76s wall clock on the 2026-08-11 run.

The failures are environment timing and module-import cost, not product defects,
and no audit finding may be dismissed as "the tests are flaky" on the strength of
this card. The problem is that the required release gate cannot currently
distinguish a real regression from load on the machine, which makes IMP-038's
evidence unreliable and trains developers toward `--no-verify`.

Correction, 2026-08-22. The 2026-08-11 signature above no longer reproduces. A
full run on this branch, after `pnpm install --frozen-lockfile` and a Prisma
client generation, completes in under 10 seconds with no timeouts. The current
signature is 10 failing tests, 420 passing, 64 files, plus 3 suites that fail to
collect; the causes are env assignment ordering, module externalisation, stale
mocks, and bad fixtures. Do not spend time profiling dynamic route imports.

Steps 1 through 4 are superseded by IMP-052, and step 5's CI half by IMP-053.
What remains unique to this card is the pre-push hook reduction in step 5 and the
recorded three-run baseline in step 6, both of which need a green gate first.
</context>

<steps>
1. Profile why the first dynamic route import in an API test file costs tens of
   seconds, and reduce it at the source (module graph, transform, or shared
   setup) rather than by raising the global timeout.
2. Separate module loading from timed assertions so an import cost cannot consume
   a behavioral timeout budget.
3. Ensure timed-out work is cancelled or settled between tests, and reset modules
   and mocks deterministically; `tests/api/auth-verification.test.ts` currently
   leaks unresolved work into the following test and changes its mock call
   counts.
4. Keep behavioral timeouts meaningful; where a test legitimately needs longer,
   set it on that test with a comment naming the cost.
5. Reduce the pre-push hook to lint, type-check, and changed-file tests, leaving
   the full suite to CI, which already runs it on every push.
6. Record one clean full run as the baseline before IMP-038 consumes this gate.
</steps>

<acceptance>
- Three consecutive full runs pass on the same machine, including under
  concurrent load.
- No test depends on another file's leftover async work.
- Failure output distinguishes a timeout from an assertion failure at a glance.
- The pre-push hook does not fail for reasons unrelated to the change.
</acceptance>

<verification>
`pnpm test -- --run` three times consecutively; a focused
`tests/api/auth-verification.test.ts` run in isolation; `pnpm lint`;
`pnpm type-check`.
</verification>
