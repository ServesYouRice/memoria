# IMP-034 - Auth and registration client journey

<objective>
Registration, verification, resend, and login screens accurately expose the
durable auth behavior already implemented by IMP-002 and IMP-003, including
safe protected-route return.
</objective>

<context>
Backend contracts and focused tests are archived in
`../archive/2026-08-01/tasks/IMP-002.md` and `IMP-003.md`; do not
weaken their enumeration, redirect, rate-limit, or registration-mode controls.
</context>

<files>
`src/features/auth/components/LoginForm.tsx`,
`src/features/auth/components/RegisterForm.tsx`, `src/app/auth/`,
`playwright.config.ts`, `tests/`.
</files>

<steps>
1. Make registration pages reflect `open`, `invite`, and `closed` modes without
   presenting actions that the API will reject.
2. Show a truthful check-inbox/delivery state after registration and expose
   enumeration-safe resend for unverified accounts.
3. Render typed unverified, expired, failed-delivery, and verified-success
   states; retain a validated same-origin `callbackUrl` through login.
4. Add production-build browser coverage for register, verify, resend/replace,
   expiry, login, and malicious return URLs.
</steps>

<acceptance>
- The UI never invites a closed or uninvited registration attempt.
- Unverified login is distinguishable from invalid credentials without account
  enumeration.
- A verified user returns only to a validated same-origin protected URL.
- The production Playwright auth journey passes with captured test email.
</acceptance>

<verification>
Targeted auth UI tests; production Playwright auth scenario; `pnpm type-check`;
`pnpm lint`.
</verification>
