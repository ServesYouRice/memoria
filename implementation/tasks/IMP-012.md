# IMP-012 — Server-authoritative polls

<objective>
Follow DEC-005: hide polls, or make votes atomic, role-aware, and private.
</objective>

<steps>
1. If `hide`, remove creation/voting UI and reject poll creation at boundaries.
2. If `repair`, add an atomic vote/unvote endpoint keyed by authenticated user,
   item, and option. Enforce one current vote policy with database constraints.
3. Return aggregate counts and the caller's selection; never return voter ID
   arrays to other clients.
4. Bound options/text and define VIEW/COMMENT/EDIT voting capability.
5. Test concurrent votes, retries, role matrix, duplicate requests, and privacy.
</steps>

<acceptance>
- Clients cannot submit totals or other users' votes.
- Concurrent voting converges without replacing unrelated votes.
</acceptance>

<verification>
Real-DB poll concurrency tests; UI tests; `pnpm type-check`; `pnpm lint`.
</verification>
