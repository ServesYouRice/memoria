# IMP-053 - Make focused runs and CI reproducible

<objective>
The documented focused-test command runs exactly the named file, and CI can run
lint, type-check, and the unit gate from a clean checkout without a local `.env`.
</objective>

<files>
`package.json`, `AGENTS.md`, `.github/workflows/ci.yml`, `vitest.config.ts`.
</files>

<context>
Verified 2026-08-22. Both defects are why the red gate in IMP-052 went unnoticed:
the command everyone was told to use hides which file failed, and the CI job that
would have caught it cannot start.

`pnpm test -- --run tests/unit/zz-probe.test.ts` reported
`Test Files 9 failed | 56 passed (65)`; `npx vitest run` on the same path
reported `Test Files 1 passed (1)`. The filter is silently dropped. That exact
command form appears in `AGENTS.md` under Verification, in `testing/review.md`,
and at the foot of all seven `testing/0*.md` documents.

`.github/workflows/ci.yml:37` and `:68` run `pnpm db:generate` with no
`DATABASE_URL` in scope; the workflow's only global env entries are
`NODE_VERSION` and `PNPM_VERSION`. `prisma.config.ts` requires the variable
through `env("DATABASE_URL")`, so the step fails with
`PrismaConfigEnvError: Cannot resolve environment variable: DATABASE_URL`,
reproduced locally. The build job at `:132` already sets placeholder values; the
lint and unit-test jobs never received the same treatment.

Separately, no file in `tests/` declares `@vitest-environment`, so every
server-side route and library test runs under happy-dom. That produced the false
CORS failure fixed in IMP-052 step 5, and costs 25-31 seconds of environment
setup per full run.
</context>

<steps>
1. Add a script that forwards a path correctly, for example
   `"test:file": "vitest run"`, and confirm `pnpm test:file <path>` reports one
   test file.
2. Correct the focused-test command in `AGENTS.md` under Verification. Leave the
   full-suite command as it is; only the filtered form is broken.
3. Give the `lint-and-typecheck` and unit-test jobs the same placeholder `env:`
   block already used by the build job at `.github/workflows/ci.yml:132`, or
   promote that block to workflow level so every job inherits it. Prefer the
   workflow-level form unless a job needs different values.
4. Route server-side tests to the node environment with
   `test.environmentMatchGlobs`, covering `tests/api/**` and the server-side
   files under `tests/unit/**`, while leaving `.tsx` component tests on
   happy-dom. Verify the CORS file from IMP-052 step 5 still passes, whether it
   keeps its docblock or inherits from the glob.
</steps>

<acceptance>
- `pnpm db:generate && pnpm test:coverage` succeeds from a clean checkout with no
  local `.env` and no exported `DATABASE_URL`.
- The focused command named in `AGENTS.md` reports a single test file.
- The full run stays green and total environment setup time drops.
</acceptance>

<verification>
`pnpm test:file tests/unit/bounded-response.test.ts`; `pnpm test -- --run`;
`pnpm lint`; `pnpm type-check`. Confirm the CI change by reading the job
definitions, and state plainly that the workflow itself was not executed.
</verification>
