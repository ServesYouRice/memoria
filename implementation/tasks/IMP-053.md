# IMP-053 - Make focused runs and test environments reproducible

<objective>
The documented focused-test command runs exactly the named file, server tests
use Node rather than happy-dom, and DOM tests opt into happy-dom explicitly.
</objective>

<files>
`package.json`, `AGENTS.md`, `vitest.config.ts`, and the component/DOM test files
that require an explicit `@vitest-environment happy-dom` annotation.
</files>

<context>
`pnpm test -- --run <file>` forwards a literal `"--"` to Vitest and does not
reliably select one file. The repository has no supported focused-test script.

The current Vitest config defaults every test to happy-dom. A measured full run
reported 65.92 seconds of aggregate environment setup, even though nearly all
`.ts` API/library tests need only Node. Vitest 4.1.11 no longer exposes the old
`environmentMatchGlobs` option. Use a supported current mechanism: make Node the
default and annotate the small set of DOM/component tests, or define explicit
Vitest projects if that proves cleaner.

Every run also warns that `vitest.config.ts` uses `__dirname`, which is
unsupported by Vite's planned native config loader. Node 22 supports
`import.meta.dirname`.
</context>

<executor_constraints>
- Do not change test behavior, assertions, timeouts, worker counts, isolation,
  or coverage thresholds.
- Do not add `@vitest-environment happy-dom` to server-only tests merely to keep
  an accidental browser global working; fix the test to use Node APIs or an
  explicit local stub.
- Keep the full-suite command unchanged. Add a separate focused command rather
  than changing the semantics of `pnpm test`.
</executor_constraints>

<steps>
1. Add `"test:file": "vitest run"` to `package.json`. Run it against
   `tests/unit/bounded-response.test.ts` and prove the summary reports exactly
   one file. Run it against a nonexistent path and prove it fails rather than
   silently running the full suite.
2. Add `pnpm test:file <path>` to `AGENTS.md` as the documented focused command.
   Leave `pnpm test -- --run` as the documented full gate because its
   file-filter defect is irrelevant when no path is supplied.
3. Change the default Vitest environment to `node`. Add
   `// @vitest-environment happy-dom` only to `.tsx` component/hook tests and
   any `.ts` test that demonstrates a real DOM dependency. Keep `tests/setup.ts`
   safe in both environments.
4. Replace `__dirname` in `vitest.config.ts` with the supported Node 22 ESM
   equivalent so the native-config-loader warning disappears.
5. Run every DOM-annotated file and representative API/server files with
   `pnpm test:file`, then run the full gate once. Record before/after aggregate
   environment setup time without turning timing into a pass/fail assertion.
</steps>

<acceptance>
- `pnpm test:file tests/unit/bounded-response.test.ts` reports one passing file.
- A nonexistent focused path fails with no tests instead of running other files.
- Server/API tests report the Node environment; DOM/component tests pass under
  explicit happy-dom annotations.
- The full suite remains behaviorally unchanged and green.
- The Vite native-config-loader warning about `__dirname` is gone.
- Aggregate environment setup time is recorded and lower than the 65.92-second
  baseline; no fixed performance threshold is asserted.
</acceptance>

<verification>
Focused Node and happy-dom files via `pnpm test:file`; `pnpm test -- --run`;
`pnpm test:coverage`; `pnpm lint`; `pnpm type-check`.
</verification>
