# IMP-052 - Make the unit and API gate reproducibly green

<objective>
The normal unit/API command passes from a cold Vitest cache and in three
consecutive fresh processes, with no timed-out work leaking into another test.
</objective>

<files>
`tests/api/auth-helpers.test.ts`, `tests/api/auth-verification.test.ts`,
`tests/api/items.test.ts`, `tests/api/template-gating.test.ts`,
`tests/api/uploads.test.ts`, `tests/unit/auth-ordering-security.test.ts`,
`tests/unit/search.test.ts`, and `vitest.config.ts` only if profiling proves a
harness-level change is required.
</files>

<context>
The gate is order-dependent. A cold `pnpm test -- --run` process
failed 8 of 444 tests across 7 files. Seven failures were five-second timeouts
while dynamically importing server modules. The timed-out first
auth-verification test later completed inside the next test, producing the
eighth failure: `tokenCreate` was called twice. `pnpm test:coverage` then passed
444/444, and the same normal command passed 444/444 immediately afterwards.

Vitest also warns that `vi.mock("@/lib/api/auth")` is nested inside a test in
`auth-ordering-security.test.ts`; the call is hoisted today and will become an
error in a future version.

IMP-053 runs first and supplies a real focused-test command plus the correct
Node/DOM environment split. This card fixes test import and lifecycle behavior,
not production behavior.
</context>

<executor_constraints>
- Do not edit `src/`, increase global/per-test timeouts, add retries or sleeps,
  reduce workers, disable isolation, or remove assertions to obtain green.
- Keep top-level `vi.mock` calls hoist-safe. Import the production subject once
  at module scope or in `beforeAll`; do not repeat an expensive dynamic import
  inside each timed test.
- Reset mock values and call history explicitly. Do not use
  `vi.resetModules()` unless a test proves it needs a fresh module instance.
- Run one named file at a time with `pnpm test:file` while iterating. Do not use
  the broken `pnpm test -- --run <file>` form.
- If a focused test exposes a product defect, stop and add one `DEC-` row. Do
  not change production code under this harness card.
</executor_constraints>

<steps>
1. Establish the cold baseline with `pnpm exec vitest --clearCache`, followed by
   one full `pnpm test -- --run`. Retain the failing file names and durations;
   do not warm the suite before recording this run.
2. In `auth-helpers.test.ts`, import the mocked auth/Prisma modules and the real
   helpers once, then configure mock return values per test. Preserve every
   denied persona and the no-unsafe-cast assertion.
3. In `auth-verification.test.ts`, import each real POST handler once after the
   top-level mocks are registered. Ensure every request promise settles inside
   its own test and that `beforeEach` gives `tokenCreate`, token retirement, and
   outbox mocks independent state. The second test must not observe work from
   the first.
4. In `auth-ordering-security.test.ts`, move the nested API-auth mock to the
   top-level hoisted mock block and import the canvas handler once. Keep all six
   security assertions, including the Argon2 call-count and share-token
   redaction cases.
5. Remove avoidable per-test module resets/imports from `search.test.ts`, and
   hoist stable subject imports in `items.test.ts`, `template-gating.test.ts`,
   and `uploads.test.ts`. Keep dependency mocks configurable per case and prove
   that denied/invalid requests still perform no forbidden work.
6. Run every changed file with `pnpm test:file`, then clear the Vitest cache and
   run the full suite once. Run the full suite two more times in separate
   processes without a coverage warm-up.
</steps>

<acceptance>
- A cold-cache full run and the next two full runs each report every collected
  file and test passing, with zero timeouts and zero unhandled work. Record the
  counts from the first run; do not hard-code an older count after other cards
  add tests.
- `auth-verification.test.ts` passes independently and in the full suite with
  exactly one `tokenCreate` call in the replacement-token case.
- Vitest emits no nested-`vi.mock` warning for
  `auth-ordering-security.test.ts`.
- No timeout, retry, worker, isolation, or assertion was weakened.
- No production file changed.
</acceptance>

<verification>
`pnpm test:file` for each changed file; `pnpm exec vitest --clearCache`;
`pnpm test -- --run` three times in separate processes; `pnpm test:coverage`;
`pnpm lint`; `pnpm type-check`.
</verification>
