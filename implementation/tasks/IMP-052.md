# IMP-052 - Restore the unit and API gate to green

<objective>
`pnpm test -- --run` passes with zero failing tests and zero suites that fail to
collect, so that every later card can be verified against a trustworthy gate.
</objective>

<files>
`tsconfig.json`, `tests/setup.ts`, `vitest.config.ts`,
`tests/unit/auth-ordering-security.test.ts`, `tests/unit/agent-webhooks.test.ts`,
`tests/unit/ssrf-fetch-hardening.test.ts`, `tests/unit/bounded-response.test.ts`,
`tests/unit/mutation-composability.test.ts`.
</files>

<context>
Measured 2026-08-22 on this branch after `pnpm install --frozen-lockfile` and a
Prisma client generation: 10 failing tests, 420 passing, 64 files, plus 3 suites
that fail to collect. Six of the failures are inside test files added by IMP-041
through IMP-044 as their completion evidence, which means those cards were
closed against tests that never produced a passing assertion.

This is a harness and test-authoring defect list, not a product defect list. Two
of the failures are false alarms about correct production code, and no finding
here may be closed by changing `src/` except where a step says so.

The card is scoped to restoring green. Live network I/O in the SSRF suite is
IMP-054, and tests that assert nothing about the product are IMP-055; both are
real and both are deliberately out of scope here.
</context>

<steps>
1. `pnpm lint` cannot load at all: typescript-eslint 8.66.0 refuses TypeScript
   7.0, which also disables the `pre-commit` hook. This is a dependency
   decision, not a config fix, and it is recorded as DEC-015; resolve that row
   before starting, because both remaining gates depend on the answer.
2. `pnpm type-check` fails before any test runs:
   `tsconfig.json(26,5): error TS5102: Option 'baseUrl' has been removed`.
   TypeScript 7 removed the option, and the dependency bump to `^7.0.2` landed
   without the corresponding config migration. This blocks `pnpm type-check`,
   the `pre-push` hook, and the CI `lint-and-typecheck` job, so it blocks every
   other card's verification too. Remove `"baseUrl": "."` and confirm the `@/*`
   path mapping still resolves; TypeScript's suggested `"paths": {"*": ["./*"]}`
   is only needed if something depends on bare-specifier resolution from the
   project root. Verify with `pnpm type-check` and `pnpm build`.
3. `tests/setup.ts:46` assigns `DATABASE_URL`, `DEMO_USER_ID`, and `NODE_ENV`
   inside `beforeAll`. Module imports run first, so `src/lib/env.ts:284` throws
   `Invalid environment variables` before any hook fires, killing
   `tests/unit/agent-crypto.test.ts`,
   `tests/unit/verification-email-outbox.test.ts`, and part of
   `tests/api/auth-verification.test.ts`. Move the assignments to module scope
   above `beforeAll`, or declare them in a `test.env` block in
   `vitest.config.ts`. The three required names are `DATABASE_URL`, `AUTH_URL`,
   and `AUTH_SECRET`.
4. `tests/unit/auth-ordering-security.test.ts` never executes: Vitest
   externalises `next-auth`, Node then resolves its bare `next/server` specifier
   and fails with `Cannot find module`. Add
   `server: { deps: { inline: ["next-auth", "@auth/core"] } }` under `test` in
   `vitest.config.ts`. A `resolve.alias` on `next/server` does not work, because
   an externalised package never reaches the Vite resolver.
5. With step 4 applied the file collects six tests and four fail. At `:49` and
   `:70`, `vi.spyOn(argon2, "verify")` throws `Cannot redefine property` because
   ESM namespace objects are frozen; replace it with a top-level
   `vi.mock("argon2", ...)` driven per test through `vi.mocked`. That also fixes
   `:170`, which currently returns `null` because real Argon2 runs against a
   fabricated hash. At `:138`, `.rejects` is applied to a value that is not a
   promise; wrap the call so `expect` receives one. Move the nested
   `vi.mock("@/lib/api/auth")` to top level, which Vitest already warns will
   become an error.
6. `tests/unit/agent-webhooks.test.ts:12` mocks `validateUrlForSsrfWithDns` to
   return `{ valid: true }`, but after IMP-043 `src/lib/agents/webhooks.ts:139`
   also requires `pinnedIp` and `targetUrl`, so both tests take the reject branch
   and throw `Webhook destination is invalid`. Return the full shape from the
   mock. Confirm the unmasked `Invalid webhook header name` assertion then
   passes on its own merits.
7. `tests/unit/ssrf-fetch-hardening.test.ts:53-75` fails against correct
   production code. `Origin` is a forbidden header name, and the happy-dom
   `Request` implementation drops it, so `request.headers.get("origin")` is
   `null` and CORS never applies. Move the CORS block to its own file carrying
   `// @vitest-environment node` on line 1. Do not change `src/middleware/cors.ts`.
8. `tests/unit/bounded-response.test.ts:183` sets
   `userId: "u111111111111111111111111"`, which fails `z.string().cuid()`
   (`/^[cC][0-9a-z]{6,}$/`). Correct the fixture and sweep the file for the same
   mistake elsewhere.
9. `tests/unit/mutation-composability.test.ts:140` seeds the cache with
   `setQueriesData({ queryKey: canvasItemKeys.lists() }, ...)`, which only
   updates queries that already exist, so nothing is stored and the read at
   `:180` yields `undefined`. Seed with
   `setQueryData(canvasItemKeys.list(canvasId), ...)` and read the same key, as
   the passing test at `:43` already does.
</steps>
