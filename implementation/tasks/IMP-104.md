# IMP-104 - Polls with votes counted on the server

<objective>
People on a canvas can vote on a question and trust the result.
</objective>

<context>
Approved by the owner on 2026-11-11: rivals charge for voting, so it is a
small free extra. Polls are switched off in `LAUNCH_CAPABILITIES`
"until voting is server-authoritative" (`src/lib/polls/availability.ts`):
today a poll's votes are lists of user ids inside the item content
(`pollContentSchema` in `src/lib/validation/canvas-item.ts`), which any
editor's browser could change, and the sync session refuses poll items
while the switch is off (`src/lib/collaboration/sync/client-session.ts`).
</context>

<files>
`src/lib/polls/availability.ts`, `src/lib/product-surfaces.ts`,
`src/lib/validation/canvas-item.ts`,
`src/features/canvas/components/PollItem.tsx`,
`src/lib/collaboration/sync/client-session.ts`, `prisma/schema.prisma`,
`tests/integration/`, `tests/unit/launch-surface-contract.test.ts`.
</files>

<executor_constraints>
Votes are written only through an authenticated, validated HTTP route and
stored on the server with a Prisma migration; the shared document carries
the question and choices, never the tally. Switch the capability on last.
</executor_constraints>

<acceptance>
- An editor can add a poll with a question and up to 20 choices.
- Each signed-in person with access can vote once (or once per choice when
  several are allowed) and can change their vote.
- Everyone sees the same counts within a second; a changed browser or a
  hand-made request cannot add votes for someone else.
- The owner can close a poll. Exports show the question and the result.
</acceptance>
