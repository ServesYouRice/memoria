<assessment>
The Codex audit is strongest exactly where the Opus audit is thinnest: fresh
install secret handling, container configuration pass-through, ingress topology,
backup scheduling, dependency posture, and defects that only appear when a route
composes its components. Its route-composition catches are its best work: the
public status page genuinely crashes, and the accessible canvas panel is
duplicated on the editable route as well as the public one.

It is weakest on authentication and authorization logic, client state machines,
and cost control. Its security file contains no finding about credential
verification order, account lockout behavior, response field selection, rate
limit identity, CORS caching, CSP breadth, or operator-funded AI spend. It also
did not notice that the thumbnail pipeline it treats as ordinary background work
produces artifacts no surface ever renders.

Its severity vocabulary is inflated in one specific way: it labels nine items
"production blocker," including process gates (`TEST-02`), operator obligations
(`DEP-03`), and product scope decisions (`LOG-03`). Those are real work, but
calling a missing backup schedule the same class of thing as a silent data-loss
bug flattens the ordering a launch decision needs.

## Corrections owed by the Opus audit

Verified today and accepted: `useCanvasItemsWithPolling` has no caller, so
LOG-15 is void; `getRedisClient` returns a reconnecting client whenever
`REDIS_URL` is set, so LOG-16's permanent-null claim is void; all four `signOut`

## Found during this pass, in neither audit

`scripts/setup.mjs` writes `REGISTRATION_MODE` as `open` for both `dev` and
`selfhost`, so a self-host install is open-registration by construction. DEP-01
describes Compose failing to pass the operator's choice; this is worse, because
the choice is overwritten at the source. It also compounds the AI spend finding,
which assumes an authenticated attacker can self-register. Conversely, the
reference Compose passes no model provider key at all, which bounds that finding
to operator-enabled AI as IMP-039 concluded.
