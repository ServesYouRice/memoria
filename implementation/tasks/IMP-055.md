# IMP-055 - Replace test evidence that asserts nothing about the product

<objective>
Every retained regression test exercises production code, so deleting the
behavior it covers makes the test fail.
</objective>

<files>
`tests/unit/mutation-composability.test.ts`, `tests/unit/selfhost-config.test.ts`,
`tests/unit/simple.test.ts`, `src/lib/test-utils.ts`,
`src/lib/hooks/use-canvas-items.ts`, `src/lib/env.ts`, `scripts/doctor.mjs`.
</files>

<context>
`tests/unit/mutation-composability.test.ts` imports only `canvasItemKeys`, a
query-key factory, and the `CanvasItem` type. The rollback behavior it asserts
is written inline in the test body and then checked against itself. No mutation
handler, hook, or route is invoked, so per-item optimistic rollback isolation is
unproven.

`tests/unit/selfhost-config.test.ts` imports nothing from `src/`. It reads
`.env.example`, `docker-compose.yml`, and `Caddyfile` as text and asserts
substrings are present. It would still pass if every variable were ignored at
runtime.

`tests/unit/simple.test.ts` asserts `1 + 1 === 2` and imports
`src/lib/test-utils.ts`, a module whose only consumer is that test.

If a rewritten test exposes a product defect, record it and raise a `DEC-` row
rather than adjusting the assertion or changing unrelated production behavior
inside this test-truthfulness card.
</context>

<steps>
1. Rewrite the mutation evidence against the real mutation hooks in
   `src/lib/hooks/use-canvas-items.ts`, rendered under a `QueryClientProvider`
   with a mocked fetch layer, and assert cache state after a rejected mutation.
   Keep the existing invariants, which are sound; replace only the mechanism.
2. Keep the cheap self-host file-presence checks, but add real
   assertions: placeholder secrets rejected by `src/lib/env.ts` under
   `NODE_ENV=production`, required variables enforced, and `scripts/doctor.mjs`
   exiting non-zero on a placeholder.
3. Delete `tests/unit/simple.test.ts` and `src/lib/test-utils.ts` after
   confirming nothing else imports the module.
4. If either rewritten suite exposes a shipped behavior defect, stop and add one
   `DEC-` row naming the expected behavior, observed result, and proposed repair
   scope.
</steps>

<acceptance>
- Each rewritten test fails when the behavior it covers is removed from `src/`,
  demonstrated once with a temporary mutation before the card closes. Restore
  that mutation immediately and verify only the intended card changes remain.
- No assertion was relaxed to accommodate a rewrite.
- Any shipped behavior whose evidence does not survive is named explicitly,
  with a `DEC-` row.
</acceptance>

<verification>
`pnpm test:file` on each rewritten file, plus one deliberate mutation of the
covered source to confirm the test fails; `pnpm test -- --run`; `pnpm lint`;
`pnpm type-check`.
</verification>
