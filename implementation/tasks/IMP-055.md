# IMP-055 - Replace card evidence that asserts nothing about the product

<objective>
Every test cited as completion evidence for a `DONE` card exercises production
code, so that deleting the feature it covers makes the test fail.
</objective>

<files>
`tests/unit/mutation-composability.test.ts`, `tests/unit/selfhost-config.test.ts`,
`tests/unit/simple.test.ts`, `src/lib/test-utils.ts`,
`src/lib/hooks/use-canvas-items.ts`, `src/lib/env.ts`, `scripts/doctor.mjs`.
</files>

<context>
Verified 2026-08-22 by inspecting what each file imports.

`tests/unit/mutation-composability.test.ts` is the stated evidence for IMP-044.
It imports exactly two things from the application: `canvasItemKeys`, a query-key
factory, and the `CanvasItem` type. The rollback behavior it asserts is written
inline in the test body and then checked against itself. No mutation handler,
hook, or route is invoked, so the card's outcome, per-item optimistic rollback
isolation, is unproven.

`tests/unit/selfhost-config.test.ts` is the stated evidence for IMP-042. It
imports nothing from `src/`. It reads `.env.example`, `docker-compose.yml`, and
`Caddyfile` as text and asserts substrings are present. It would still pass if
every variable were ignored at runtime.

`tests/unit/simple.test.ts` asserts `1 + 1 === 2` and imports
`src/lib/test-utils.ts`, a module whose only consumer is that test.

This card decides whether IMP-042 and IMP-044 reopen. Do not make that call
alone: if the rewritten tests fail, record it and raise a `DEC-` row rather than
adjusting the assertions until they pass.
</context>

<steps>
1. Rewrite the IMP-044 evidence against the real mutation hooks in
   `src/lib/hooks/use-canvas-items.ts`, rendered under a `QueryClientProvider`
   with a mocked fetch layer, and assert cache state after a rejected mutation.
   Keep the existing invariants, which are sound; replace only the mechanism.
2. Keep the cheap file-presence checks in the IMP-042 evidence, but add real
   assertions: placeholder secrets rejected by `src/lib/env.ts` under
   `NODE_ENV=production`, required variables enforced, and `scripts/doctor.mjs`
   exiting non-zero on a placeholder.
3. Delete `tests/unit/simple.test.ts` and `src/lib/test-utils.ts` after
   confirming nothing else imports the module.
4. If either rewritten suite fails, stop. Report the failure against the owning
   card and add one `DEC-` row asking whether that card reopens.
</steps>

<acceptance>
- Each rewritten test fails when the behavior it covers is removed from `src/`,
  demonstrated once by hand before the card closes.
- No assertion was relaxed to accommodate a rewrite.
- Any card whose evidence did not survive is named explicitly, with a `DEC-` row.
</acceptance>

<verification>
`pnpm test:file` on each rewritten file, plus one deliberate mutation of the
covered source to confirm the test fails; `pnpm test -- --run`; `pnpm lint`;
`pnpm type-check`.
</verification>
