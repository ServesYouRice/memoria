# IMP-147 - Scheduler retries soon after a failed call; drop `url.parse`

<objective>
The scheduler retries a failed call within a minute instead of waiting a
full interval, and `server.ts` uses the WHATWG `URL` API.
</objective>

<context>
Handbook RUN-ME-3 and `before-production.md` memoria steps 4 and 6: the
scheduler waited 5-15 minutes after the web pod was not ready
(`scripts/scheduler.mjs`). `server.ts` imports the deprecated
`url.parse`. Jobs must stay safe to run twice.
</context>

<files>
`scripts/scheduler.mjs`, `server.ts` and their tests.
</files>

<acceptance>
- A failed call is retried with a short back-off (under 60 s), then falls
  back to the normal interval.
- `server.ts` no longer imports `parse` from `url`.
</acceptance>

<verification>
`pnpm test:file` on the scheduler and server tests; `pnpm gate fast`.
</verification>
