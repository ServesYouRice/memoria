# IMP-004 — Proxy-safe rate-limit identity

<objective>
Direct and reverse-proxy deployments identify clients without trusting spoofed
forwarding headers or collapsing every user into one bucket.
</objective>

<files>
`server.ts`, env validation/example, doctor/setup, live and dead rate-limit
modules, proxy/rate-limit tests.
</files>

<steps>
1. Add explicit trusted proxy hops/CIDRs. Derive the rightmost untrusted address
   only when the socket peer is trusted; otherwise use the socket peer.
2. Overwrite internal identity headers before Next handles the request.
3. Use authenticated user/tenant keys for costly authenticated actions where
   available; keep trusted client-IP keys for anonymous/auth admission.
4. Merge or delete `endpoint-limits.ts` so one live policy defines keys, limits,
   and response headers.
5. Add direct, spoofed, one-proxy, multi-proxy, IPv4, and IPv6 tests. Warn in
   `doctor` when HTTPS deployment has no proxy contract.
</steps>

<acceptance>
- A caller cannot select another rate-limit identity.
- Two clients behind one trusted proxy do not share all buckets.
- Misconfiguration fails safely and is diagnosable.
</acceptance>

<verification>
Targeted server/proxy/rate-limit tests; `pnpm type-check`; `pnpm lint`.
</verification>
