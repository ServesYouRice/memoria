# IMP-150 - Expand/contract rule for migrations; DEPLOYMENT.md

<objective>
Migrations follow an expand/contract rule, written down and checked, and a
`DEPLOYMENT.md` explains how a release reaches the cluster (handbook ME-04,
ME-06).
</objective>

<context>
One existing migration renames and drops in place, which breaks the old
pods during a rolling update. There is no `DEPLOYMENT.md`.
</context>

<files>
`DEPLOYMENT.md`, `AGENTS.md`, `scripts/check-schema-drift.mjs` or a new
migration lint.
</files>

<acceptance>
- New migrations that drop or rename a column or table in the same release
  that stops using it fail a check (with an explicit override).
- `DEPLOYMENT.md` covers release, migrate Job, rollout, rollback and
  restore, pointing at infra for cluster details.
</acceptance>

<verification>
`pnpm gate fast`; the check fails on a planted rename.
</verification>
