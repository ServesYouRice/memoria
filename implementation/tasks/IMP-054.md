# IMP-054 - Remove live network I/O from the unit suite

<objective>
No test in the default Vitest suite resolves DNS or opens a socket to the public
internet, and the SSRF redirect-revalidation invariant is proven against a
controlled transport.
</objective>

<files>
`src/lib/utils/ssrf-protection.ts`, `tests/unit/ssrf-hostile.test.ts`.
</files>

<context>
Verified 2026-08-22. `tests/unit/ssrf-hostile.test.ts:16` mocks
`globalThis.fetch`, but IMP-043 replaced the transport in `safeFetch` with
`pinnedHttpRequest`, which uses raw `node:http`/`node:https` sockets. The mock is
now inert, so the test resolves real DNS and performs a real HTTPS request to
`example.com`, returning `{ ok: true, status: 200 }` where `{ ok: false, status:
400 }` was expected.

Two consequences. The redirect-revalidation invariant that IMP-043 claims as
evidence is currently unproven, and the unit suite fails without an internet
connection.

`vi.mock` on the module cannot fix this: `safeFetch` calls `pinnedHttpRequest`
through a module-local binding, so a partial mock of the same module is not
observed. Closing this needs a seam in `src/`, which is why it is a separate card
from IMP-052 rather than a test edit inside it.
</context>

<steps>
1. Add an optional injected transport to `safeFetch` in
   `src/lib/utils/ssrf-protection.ts`, defaulting to `pinnedHttpRequest` so no
   caller changes. Keep the signature additive and keep the default path
   identical to today's behavior.
2. Rewrite the redirect test to inject a fake transport that returns a 302 with
   `location: http://127.0.0.1/admin`, and assert the loop revalidates the target
   and returns a bounded rejection instead of following it.
3. Assert the fake transport is called exactly once, proving the private
   redirect target was rejected before a second connection was attempted.
4. Add a guard that fails loudly if the suite ever performs real I/O again, for
   example by asserting the injected transport is the only path exercised in that
   file. Do not weaken the existing alternate-address cases at `:5-13`, which
   pass today and must keep passing.
</steps>

<acceptance>
- The full unit suite passes with networking unavailable.
- The redirect-revalidation assertion fails if the revalidation branch is removed
  from `safeFetch`.
- The default `safeFetch` call path is unchanged for every existing caller.
</acceptance>

<verification>
`npx vitest run tests/unit/ssrf-hostile.test.ts` with the network interface
disabled; `pnpm test -- --run`; `pnpm lint`; `pnpm type-check`.
</verification>
