# IMP-002 — Verification, login, and return-to journey

<objective>
A production registrant can verify or resend, sees truthful errors, and returns
to the same-origin protected URL requested before login.
</objective>

<files>
Auth config/forms/pages; register, resend, and verify routes; auth E2E tests.
</files>

<steps>
1. Surface a typed `email_not_verified` credentials error.
2. After registration show “check your inbox”; do not tell an unverified user
   to sign in. Report whether initial delivery was accepted.
3. Make resend public, enumeration-safe, rate-limited, and email-based. Replace
   old unexpired tokens instead of accumulating them.
4. Redirect successful verification to login with a success state.
5. Preserve a validated same-origin `callbackUrl` through login.
6. Add production-mode tests for delayed, failed, resent, expired, and successful
   verification plus malicious callback URLs.
</steps>

<acceptance>
- Unverified login never reports “invalid password.”
- Resend reveals no account existence and works without a session.
- External/open redirect values are rejected.
</acceptance>

<verification>
Targeted auth tests; `pnpm type-check`; `pnpm lint`; production Playwright auth
scenario.
</verification>
