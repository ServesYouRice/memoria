# IMP-066 - Cover connection authorization and canvas binding

<objective>
Canvas connections require VIEW capability for listing and EDIT capability for
creation, update, and deletion, with every item and connection query bound to
the canvas ID in the request path.
</objective>

<files>
`src/app/api/v1/canvases/[canvasId]/connections/route.ts`,
`src/app/api/v1/canvases/[canvasId]/connections/[connectionId]/route.ts`, and a
new `tests/api/connections-authorization.test.ts`.
</files>

<context>
Neither connection route is imported by an existing test. Connections are not
owner-only: `requireCanvasAccess` grants shared capabilities. The collection GET
requires VIEW, while POST, item PATCH, and item DELETE require EDIT.

Authorization alone is not sufficient. POST must prove both endpoint items are
undeleted members of the path canvas, and PATCH/DELETE must look up the
connection by both `connectionId` and `canvasId`; otherwise an authorized user
on one canvas could address a resource from another.
</context>

<executor_constraints>
- Import and call all real route exports. Mock `requireAuth`,
  `requireCanvasAccess`, and Prisma; never mock the route module.
- Model capability by making `requireCanvasAccess` resolve or reject, and assert
  the exact requested level and canvas ID for every method.
- Assert denied paths make no item/connection query or mutation after the access
  check.
- Treat production files as read-only. Stop and add one `DEC-` row if a query
  loses its canvas binding or a write-capable method accepts only VIEW.
</executor_constraints>

<steps>
1. Collection GET must request VIEW and, on denial, perform no connection list
   or count. On success, both queries use the path `canvasId`.
2. Collection POST must request EDIT. On success, both endpoint lookups use
   `{ id, canvasId, deletedAt: null }`; a missing/cross-canvas/deleted endpoint
   returns the shipped 400 and performs no connection create. A valid pair is
   created under the path canvas.
3. Item PATCH and DELETE must request EDIT and look up the existing connection
   with both path IDs. A missing or cross-canvas row performs no update/delete.
4. Cover one allowed shared-capability fixture for VIEW and one for EDIT, plus
   an owner fixture, so tests prove capability behavior rather than hard-code an
   owner-only assumption.
</steps>

<acceptance>
- GET requires VIEW; POST/PATCH/DELETE require EDIT, asserted with exact calls.
- Every connection and endpoint-item lookup retains the path canvas ID.
- Cross-canvas IDs and denied capabilities cause zero mutation.
- All four exported methods are exercised through real handlers.
- No production file changed.
</acceptance>

</verification>
