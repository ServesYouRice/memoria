# IMP-098 - Templates and "Duplicate canvas"

<objective>
A new canvas can start from a ready-made layout, and any canvas can be
copied, so nobody has to start from a blank page.
</objective>

<context>
Approved by the owner on 2026-11-11: beginners value templates most. Both
are switched off in `LAUNCH_CAPABILITIES` (`src/lib/product-surfaces.ts`)
because the server side was never built: the routes under
`/api/v1/templates` and `/api/v1/canvases/[canvasId]/duplicate` only call
`requireTemplatesEnabled` (`src/lib/templates/availability.ts`), which
answers "disabled", or an error if the switch is on without a real route.
`src/app/templates/page.tsx` returns "not found".
`src/lib/services/templates.ts` holds five built-in templates and the
helpers `applyTemplate` and `createTemplateFromItems`. The launch contract
test checks that duplication is not offered.
</context>

<files>
`src/lib/product-surfaces.ts`, `src/lib/templates/availability.ts`,
`src/lib/services/templates.ts`, `src/app/api/v1/templates/`,
`src/app/api/v1/canvases/[canvasId]/duplicate/route.ts`,
`src/app/templates/`, `src/features/dashboard/components/`,
`tests/unit/launch-surface-contract.test.ts`, `tests/integration/`.
</files>

<executor_constraints>
- Build the routes first, with authentication, Zod validation and the
  canvas and item limits, each in one transaction; switch the capability
  on last, in the same change as the updated contract test.
- Only the owner can duplicate a canvas. The copy is private: shares,
  comments and version history are not copied.
- Pictures keep working in the copy and storage use is counted correctly.
</executor_constraints>

<acceptance>
- "New canvas" offers 10 to 20 built-in templates with plain names and a
  small preview, plus "Blank canvas".
- A canvas made from a template has the template's items and is the
  person's own.
- "Duplicate" on a canvas makes a copy with every item, frame and attached
  arrow in place.
- Hitting the canvas or item limit gives a clear message and changes
  nothing.
</acceptance>

</verification>
