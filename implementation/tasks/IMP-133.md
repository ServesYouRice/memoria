# IMP-133 - Deleting a canvas says "Move to Trash", offers Undo, and Trash lists it

<objective>
On screen, deleting a canvas is clearly reversible: the dialog says the
canvas goes to Trash for 30 days, a message offers Undo, and the Trash
page lists canvases with a Restore button.
</objective>

<context>
Screen part of IMP-132 (do that card first; this one needs its API).
Today the dashboard dialog says "Delete canvases? Are you sure you want
to delete N canvas(es)? This action cannot be undone." and the Trash
page only lists single items.
After IMP-132: `DELETE /api/v1/canvases/[id]` moves the canvas to Trash;
`GET /api/v1/trash` returns `canvases: [{ id, name, deletedAt,
itemCount }]`; `POST /api/v1/canvases/[id]/restore` brings it back.
Rule used: offer Undo; name the result on the button.
</context>

<files>
`src/features/dashboard/components/DashboardContent.tsx` (dialog near
"Delete canvases?"), `src/features/dashboard/components/bulk-delete.ts`,
`src/lib/hooks/use-canvases.ts`, `src/app/trash/TrashContent.tsx`,
`tests/unit/dashboard-bulk-delete.test.tsx`,
`src/features/dashboard/components/bulk-delete.test.ts`.
</files>

<executor_constraints>
- Do not change the bulk-delete request logic (at most 4 at once, stop
  on HTTP 429). Reuse the same idea for Undo.
- Toasts use `sonner` (`toast`) like the rest of the app.
- Use the word "Trash" with a capital T, as the menu does.
</executor_constraints>

<steps>
1. Dashboard dialog text (N = number selected):
   - title: `Move 1 canvas to Trash?` / `Move N canvases to Trash?`
   - body: `You can restore it from Trash for 30 days.` (use `them` for
     more than one)
   - buttons: `Cancel` and `Move to Trash` (keep the red colour).
2. After the delete finishes, show a toast: `1 canvas moved to Trash` /
   `N canvases moved to Trash` with an action button `Undo`. Undo calls
   the restore route for each canvas that was moved (at most 4 requests
   at once), then refreshes the canvas list and shows `Restored`. If
   some restores fail, say how many and that they are still in Trash.
   Keep the toast visible for at least 8 seconds.
3. Add a hook `useRestoreCanvas()` in `src/lib/hooks/use-canvases.ts`
   that POSTs to `/api/v1/canvases/{id}/restore` and invalidates the
   `["canvases"]` queries and the Trash query.
4. Trash page (`TrashContent.tsx`):
   - subtitle under the title: `Kept for 30 days, then removed for
     good.`
   - above the item list add a section `Canvases` with one row per
     trashed canvas: its name, `Canvas · N items`, `deleted <time ago>`
     and a `Restore` button. After restoring, the row disappears and a
     toast says `Canvas restored`.
   - the existing item rows stay as they are, under a heading `Items`
     when both sections have rows.
   - the empty state shows only when there are no canvases and no items.
5. Tests: update `tests/unit/dashboard-bulk-delete.test.tsx` for the new
   words and add cases for the Undo action. Add
   `tests/unit/trash-canvases.test.tsx`: canvases render with Restore;
   clicking Restore calls the route and removes the row.
</steps>

<acceptance>
- The text "cannot be undone" no longer appears when deleting canvases.
- Deleting 2 canvases, then pressing Undo, brings both back on the
  dashboard without a reload.
- The Trash page lists a deleted canvas with its name and a Restore
  button, and restoring it returns it to the dashboard.
- At 390px wide the Trash rows and the toast are fully readable.
</acceptance>
