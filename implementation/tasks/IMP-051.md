# IMP-051 - Close the verified small-surface residue

<objective>
Public canvas assets are cacheable without weakening private-asset handling, the
service worker only deletes caches it owns, and client crash recovery does not
render raw exception text.
</objective>

<files>
`src/app/api/v1/uploads/[assetId]/route.ts`, `public/sw.js`,
`src/components/ErrorBoundary.tsx`,
`src/features/canvas/components/CanvasErrorBoundary.tsx`, and their tests.
</files>

<context>
Three confirmed findings from IMP-049 that no other card carries. Each is small,
independent, and low risk; they are grouped only because splitting them would add
board noise, not because they share a mechanism.

- Codex PERF-05. `uploads/[assetId]/route.ts` sends
  `private, max-age=0, must-revalidate` for every asset, including assets on
  public canvases. `ETag` and the 304 path exist, so the cost is a Node plus
  object-storage round trip per revisit rather than a retransfer; popular public
  links still amplify it.
- Codex LOG-06 with Opus LOG-19b. The `activate` filter in `public/sw.js` is
  `name !== CACHE_NAME || UNSAFE_LEGACY_CACHES.has(name)`, which deletes every
  non-current cache on the origin, including caches owned by a co-hosted
  application, and makes the legacy-name set unreachable.
- Codex SEC-06. Both error boundaries render `error.message`, so a third-party
  or future internal exception string reaches the user.

Cache lifetime for public assets depends on public-link revocation and object
deletion timing; do not raise it beyond what revocation can honor.
</context>

<steps>
1. Give assets on currently public canvases a short public cache lifetime with
   ETag validation, keep private-canvas assets private, and state the revocation
   window the chosen lifetime implies.
2. Restrict the service-worker activation filter to Memoria-owned cache-name
   prefixes plus an explicit legacy allowlist, and make that list reachable.
3. Show a stable recovery message plus a request or incident identifier, send the
   original exception to telemetry only, and allow a small explicit set of safe
   domain messages.
</steps>

<acceptance>
- A public-canvas asset is cacheable and a private-canvas asset is not, proven by
  a test over both paths.
- An unrelated cache name survives activation while an obsolete Memoria name does
  not.
- No error boundary renders an arbitrary exception message.
</acceptance>

<verification>
Focused route tests for both asset visibilities; a service-worker
install/upgrade test with unrelated cache names; error-boundary component tests;
`pnpm lint`; `pnpm type-check`.
</verification>
