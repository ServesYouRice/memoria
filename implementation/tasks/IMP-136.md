# IMP-136 - Dashboard: one "New canvas" button, plus sort and filter

<objective>
The dashboard has one obvious way to start a canvas, a clearly named
import button, and a "Filter by name" field and a "Sort by" menu above
the canvas cards.
</objective>

<context>
Found in the UI audit of 2026-11-14. On the dashboard today:
- two controls start a new canvas: the header button "New canvas" and
  the first-steps tile "Blank canvas" right under it;
- the button "Open file" does not open anything on screen: it imports a
  canvas file (the dialog is titled "Open a canvas file");
- canvases always come newest-edited first; there is no way to sort by
  name or to filter a long list.
Rule used (GOV.UK, IBM Carbon): one main button per page; sorting and
filters sit above the list.
The list is loaded page by page from `GET /api/v1/canvases`, so sorting
and filtering must happen on the server, not only on the cards already
loaded.
</context>

<executor_constraints>
- Keep `requireAuth` and the `userId` filter on the list route. Validate
  the new query parameters with Zod; an invalid value returns the
  route's normal validation error.
- The default result must stay exactly as today (newest edit first) so
  other callers of the route are not affected.
- Do not change the "Select" button or the multi-select flow.
- The `Canvases` menu label is IMP-126, the card "..." menu is IMP-137
  and the activity box is IMP-138. Do not do them here.
</executor_constraints>

<steps>
1. `StarterRow.tsx`: remove the `Blank canvas` tile and the
   `onBlankCanvas` prop. Two tiles stay: `Save a link` and `Open
   Inbox`. Change the grid to two columns
   (`repeat(2, minmax(0, 1fr))`). Update the comment above the
   component and the call in `DashboardContent.tsx`.
2. `DashboardContent.tsx` header: rename the button `Open file` to
   `Import`. Keep its icon and click handler. In
   `ImportCanvasDialog.tsx` change the title `Open a canvas file` to
   `Import a canvas file`.
3. API. `GET /api/v1/canvases` accepts two optional query parameters:
   - `sort`: `updated` (default, `updatedAt` newest first), `name`
     (`name` A to Z, then `updatedAt` newest first), `created`
     (`createdAt` newest first);
   - `q`: text of 1 to 100 characters after trimming; when present add
     `name: { contains: q, mode: "insensitive" }` to `where` (so the
     `total` count is filtered too).
4. Hooks. `api.listCanvases(offset, workspaceId, options)` and
   `useCanvases(workspaceId, options)` take
   `options?: { sort?: "updated" | "name" | "created"; q?: string }`,
   send them as query parameters, and include them in the query key so
   each combination is cached on its own. Calls without options behave
   as today.
5. UI. In `DashboardContent.tsx`, directly above the card grid and
   only when not in selection mode, add one row:
   - a small text field, label `Filter by name`, with a clear ("x")
     button when it has text; wait 250 ms after the last key press
     before asking the server;
   - a select, label `Sort by`, options `Recently updated`,
     `Name (A to Z)`, `Newest first`.
   On phones the two controls stack, each full width.
   Remember the chosen sort in `localStorage` under
   `memoria.dashboard.sort` (wrap reads and writes in try/catch).
   Hide the row when the person has no canvases at all and no filter
   text.
6. Empty filter result: when a filter is set and nothing matches, show
   `No canvases match "<text>"` with a button `Clear filter`, not the
   "create your first canvas" empty state.
7. The header subtitle keeps counting all canvases, not the filtered
   ones.
8. Tests:
   - update `tests/unit/dashboard-first-steps.test.tsx`: the row offers
     `Save a link` and `Open Inbox`; `Blank canvas` is not there;
   - API test: `sort=name` returns names A to Z; `q=gar` returns only
     matching names with the matching `total`; `sort=bogus` is refused;
     another user's canvases never appear;
   - `tests/unit/dashboard-sort-filter.test.tsx`: typing in the field
     calls the hook with `q`; choosing `Name (A to Z)` calls it with
     `sort: "name"`; the no-match message and `Clear filter` work.
</steps>

<acceptance>
- The dashboard shows exactly one control that starts a new canvas when
  canvases exist: the header button `New canvas`.
- The header buttons read `Select`, `Import`, `New canvas`.
- Choosing `Name (A to Z)` reorders all canvases, including ones not yet
  loaded, and the choice survives a page reload.
- Typing part of a name narrows the cards; clearing it brings all back.
- `GET /api/v1/canvases` with no parameters returns the same order as
  before this card.
- At 390px wide nothing in the new row is cut off.
</acceptance>
