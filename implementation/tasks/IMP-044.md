# IMP-044 - Make item mutations composable and recoverable

<objective>
Concurrent item mutations preserve unrelated optimistic state and relational
identity, bulk/clipboard failures are visible, and large mutation batches do
not serialize hundreds of database round trips under a canvas lock.
</objective>

<files>
`src/features/canvas/hooks/use-canvas-item-handlers.ts`,
`src/lib/hooks/use-canvas-items.ts`, item restore routes,
`src/lib/api/route-handler.ts`, batch canvas-item routes,
`src/features/dashboard/components/DashboardContent.tsx` (bulk canvas delete),
mutation UI tests and PostgreSQL integration tests.
</files>

<context>
Confirms Opus LOG-04 through LOG-07, LOG-09, LOG-17, PERF-04/07, and UI-14.
LOG-08 is deliberately excluded: current canvas deletion is explicitly
permanent and confirmed; canvas trash is a product decision. Paste of invalid
clipboard text may remain quiet, but API/permission/version failures must not.
</context>

<steps>
1. Make undo restore the original soft-deleted row and ID so comments,
   connections, embeddings, versions, and redo remain coherent.
2. Use collision-safe optimistic IDs and per-entity optimistic layers; a failed
   mutation may roll back only its own item, never a concurrent edit.
3. Remove duplicate/global invalidations, scope cancellation to the current
   canvas, and reconcile authoritative server/committed-event data without
   refetch storms.
4. Surface typed version/access/offline errors. Use `allSettled` for bulk item
   and canvas operations and report exact partial outcomes while always
   reconciling caches.
5. Give in-progress idempotency records a bounded lease/recovery state and
   schedule expired-row cleanup without replaying completed side effects.
6. Replace per-item batch layout updates/events with bounded set-based SQL and
   bulk event insertion while preserving authorization, versions, advisory
   locking, and committed-event order.
</steps>

<acceptance>
- Delete/undo preserves item IDs and relations; concurrent success/failure
  sequences converge without losing unrelated optimistic changes.
- Users receive actionable feedback for durable mutation failures and partial
  bulk outcomes.
- Stale idempotency rows recover safely, and the maximum batch completes within
  a defined transaction/lock budget on PostgreSQL.
</acceptance>

<verification>
Focused hook concurrency tests; undo/relation and batch-layout real-PostgreSQL
tests; idempotency failure/retry tests; `pnpm type-check`; `pnpm lint`.
</verification>
