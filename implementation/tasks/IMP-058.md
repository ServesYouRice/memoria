# IMP-058 - Cover operator, cron, and bootstrap endpoints

<objective>
Every unauthenticated entry point outside the session flow is proven to fail
closed, and the operations endpoint stays indistinguishable from a missing route.
</objective>

<files>
`src/app/api/cron/maintenance/route.ts`,
`src/app/api/cron/refresh-bookmarks/route.ts`,
`src/app/api/operations/outbox/route.ts`,
`src/app/api/setup/initialize/route.ts`, `src/app/api/csp-report/route.ts`,
and new tests under `tests/api/`.
</files>

<context>
None of these five routes is referenced by any existing test. They share a
property that makes them worth one card: each is reachable without a session, so
each depends entirely on its own guard.

`hasInternalOperationsAccess` already has unit coverage in
`tests/unit/operations-security.test.ts`, but the route that consumes it does
not. Its design intent is that an unauthorised caller receives a 404 rather than
a 401, so the endpoint's existence is not disclosed; that is a deliberate
behavior and needs a test that will notice if it degrades to 401.

`setup/initialize` calls `isBootstrapAvailable()`, which counts users, and then
creates the first user. That sequence is a genuine time-of-check-to-time-of-use
window: two concurrent calls can both observe zero users. Do not fix it under
this card. Characterise the current single-request behavior, then add one `DEC-`
row naming the race and asking whether it is in scope for launch.
</context>

<steps>
1. Cover both cron routes: an unset `CRON_SECRET` yields 500 rather than an open
   endpoint; a wrong or missing bearer yields 401; a correct secret enqueues with
   the documented dedupe key so a repeated call in the same window is idempotent.
2. Cover `operations/outbox`: an unauthorised `GET` and `POST` both return 404
   with no body distinguishing them from a missing route; the action schema is
   strict; `limit` clamps at 100 and rejects values outside its range.
3. Cover `setup/initialize`: bootstrap is refused once any user exists; a wrong
   token is refused; the token comparison is length-checked before
   `timingSafeEqual`, so a mismatched length cannot throw; the localhost bypass
   is unreachable when `NODE_ENV=production`.
4. Cover `csp-report`: a body over 16 KiB returns 413 before parsing; malformed
   JSON does not escape the handler; oversized fields are bounded by the schema
   rather than logged whole.
5. Add one `DEC-` row for the bootstrap race found in step 3. Do not schedule a
   fix from this card.
</steps>

<acceptance>
- Every route in this card has a proven fail-closed path for a missing credential
  and for a wrong credential, asserted separately.
- The operations endpoint returns 404, not 401, for an unauthorised caller.
- The bootstrap race is recorded as a decision, not silently fixed or ignored.
</acceptance>
