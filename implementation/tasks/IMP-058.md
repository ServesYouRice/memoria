# IMP-058 - Cover operator, cron, bootstrap, and CSP boundaries

<objective>
Privileged routes outside the normal session flow fail closed before side
effects, while the intentionally unauthenticated CSP-report route accepts only a
bounded, non-throwing payload.
</objective>

<files>
`src/app/api/cron/maintenance/route.ts`,
`src/app/api/cron/refresh-bookmarks/route.ts`,
`src/app/api/operations/outbox/route.ts`,
`src/app/api/setup/initialize/route.ts`, `src/app/api/csp-report/route.ts`, and
a new `tests/api/operator-entrypoints.test.ts`.
</files>

<context>
None of these five route modules is imported by an existing test. They are
grouped because they are reachable without a user session, but they do not all
have the same credential contract: cron uses `CRON_SECRET`, operations uses
`hasInternalOperationsAccess`, bootstrap uses a one-time token outside local
development, and CSP reports are intentionally credential-free.

The operations route deliberately returns its shipped generic JSON 404; it is
not byte-for-byte identical to a framework missing-route response. Bootstrap
repeats `user.count()` inside a `Serializable` transaction. Test those existing
safeguards rather than inventing a replacement contract.
</context>

<executor_constraints>
- Import and call every real route export. Mock Prisma, enqueue helpers,
  bootstrap/password helpers, internal authorization, and the logger; do not
  mock a route module or perform network/database work.
- Use fake time for daily and 15-minute dedupe buckets. Restore every changed
  environment variable and fake timer in `afterEach`.
- Assert the absence of transactions, writes, hashing, or logging on rejected
  paths as applicable; status alone is insufficient.
- Treat the source routes as read-only. If an assertion below exposes a product
  defect, stop and add one `DEC-` row with the exact request and side effect.
</executor_constraints>

<steps>
1. Cover both cron GET handlers. An unset/blank `CRON_SECRET` returns 500 with
   no transaction; a missing or wrong bearer returns 401 with no transaction.
   With a correct bearer, maintenance supplies the three documented daily
   dedupe keys, and refresh supplies one stable 15-minute-bucket key per
   selected bookmark. Assert stable key construction; do not claim mocked
   enqueue calls prove database-level idempotency.
2. Cover operations GET and POST with `hasInternalOperationsAccess` false:
   both return the shipped `{ status: "not_found" }` 404 and perform no Prisma
   or replay work. With access true, GET defaults to 50, accepts 100, and rejects
   zero, 101, and malformed limits before `findMany`; POST rejects unknown keys
   in its strict action schema and dispatches valid replay/cancel actions only
   for the requested CUID.
3. Cover bootstrap denial before expensive work: unavailable bootstrap, a wrong
   token, and a different-length token perform no password validation, hashing,
   or transaction, and the different-length case never calls
   `timingSafeEqual`. Prove localhost bypass works only outside production.
4. For bootstrap success, capture the real transaction callback. Assert the
   callback counts users again before creates, no row is created when that count
   is non-zero, and Prisma receives `{ isolationLevel: "Serializable" }`.
   Keep this as a mocked contract test; do not claim it proves PostgreSQL
   serialization behavior.
5. Cover CSP POST separately from credential tests. Measure UTF-8 bytes, not
   JavaScript character count: more than 16 KiB returns 413 before parsing or
   warning logs; malformed JSON is contained and returns 204; valid input logs
   only the bounded schema fields and returns 204. Unknown fields must not be
   forwarded to the warning log.
</steps>

<acceptance>
- Missing configuration and wrong credentials block every privileged route in
  this card before side effects.
- Operations denial remains the exact generic JSON 404 shipped by the route.
- Cron tests prove deterministic dedupe-key inputs without pretending a mock
  proves uniqueness in PostgreSQL.
- Bootstrap's in-transaction user recheck and Serializable option are both
  asserted, with no stale race decision added automatically.
- CSP reports remain intentionally unauthenticated, byte-bounded, schema-bound,
  and non-throwing.
- No production file changed.
</acceptance>
