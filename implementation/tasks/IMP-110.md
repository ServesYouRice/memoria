# IMP-110 - Optional full copy of saved pages

<objective>
A deployment that wants it can keep a picture and a PDF of each saved
page, so the page can be seen as it looked on the day it was saved.
</objective>

<context>
Approved by the owner on 2026-11-11 as the larger follow-up to IMP-094
(page text). Rival link savers do this, and its storage and server load is
their users' second most-voted complaint, so it must be optional. It needs
a headless browser, which runs differently from the rest of the app.
</context>

<files>
`docker-compose.yml`, `src/lib/outbox/`,
`src/lib/services/link-enrichment.ts`, `src/lib/utils/ssrf-protection.ts`,
`docs/operations/resource-budgets.md`, `tests/integration/`.
</files>

<executor_constraints>
- Off by default. It runs as its own optional worker process and compose
  profile; the standard and the small set-up do not include it.
- The browser must not be able to reach private or internal addresses, for
  the page itself or anything the page loads. Captures have time, size and
  count limits, are stored through the existing object storage, and count
  toward the person's storage quota.
- Jobs go through the outbox and are safe to run twice.
</executor_constraints>

<acceptance>
- With the option on, a saved link gets a picture and a PDF, shown from
  the bookmark next to "Read saved copy".
- With the option off, nothing changes and nothing extra runs.
- A page that points at an internal address is refused.
- Copies are deleted with the item and included in the account export.
</acceptance>

<verification>
`pnpm test:file` for the new tests; `pnpm gate fast`;
`pnpm gate integration` and `pnpm gate container` on the dev machine.
</verification>
