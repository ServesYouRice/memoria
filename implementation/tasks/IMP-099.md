# IMP-099 - Sign in with an existing login system

<objective>
Someone who runs Memoria on their own server can let people sign in with
the login system they already use, at no charge.
</objective>

<context>
Approved by the owner on 2026-11-11: people who host their own tools want
one login for all of them, and some rivals charge for it. Memoria signs in
with Better Auth 1.7.17 (`src/lib/auth/server.ts`) using email and
password, passkeys and two-step codes. There is no single sign-on.
Registration has three modes (open, invite, closed).
</context>

<files>
`src/lib/auth/server.ts`, `src/features/auth/components/LoginForm.tsx`,
`src/proxy.ts`, `README.md`, `docs/operations/`, `tests/`.
</files>

<executor_constraints>
- Use the standard OpenID Connect flow through Better Auth's own support
  for it; read the documentation of the installed version first.
- Off by default and configured by environment (issuer address, client id,
  secret, button label). Secrets never reach the browser or the logs.
- Registration modes still apply: in "closed" and "invite" mode a new
  person cannot get an account just by signing in this way.
- An existing account is joined only when the login system confirms a
  verified email that matches. Production-shaped tests cover this.
</executor_constraints>

<acceptance>
- With the settings in place, the sign-in page shows "Sign in with
  <name>" and it works end to end against a test login server.
- Without the settings, nothing changes.
- A person can still add a passkey or two-step codes afterwards.
- The hosting guide explains the set-up in plain steps.
</acceptance>

<verification>
`pnpm test:file` for the new auth tests; `pnpm gate fast`;
`pnpm gate e2e` on the dev machine against a local test login server.
</verification>
