# IMP-057 - Cover account credential and deletion routes

<objective>
Changing a password provably invalidates every existing session, and account
deletion is gated, redacted, and non-destructive to other owners' content.
</objective>

<files>
`src/app/api/v1/users/change-password/route.ts`,
`src/app/api/v1/users/account/route.ts`, and new tests under `tests/api/`.
</files>

<context>
Neither route is referenced by any existing test. Both are irreversible from the
user's point of view and both carry invariants that are easy to break silently
during unrelated refactors.

`change-password` rotates `sessionVersion` and deletes `Session` rows inside a
single `prisma.$transaction`, then calls `invalidateSessionVersion`. All three
must happen together; losing any one leaves a valid cookie alive after a password
change, which is the exact failure a password change exists to prevent.

`account` exposes a `GET` export and a `DELETE`. The export selects fields
explicitly and must never grow to include `passwordHash` or `sessionVersion`; an
explicit assertion is the only thing that will stop a future `select` widening.
The `DELETE` path reassigns items the user authored on another owner's canvas to
that canvas owner before deleting, so content contributed elsewhere survives.

Use a mocked Prisma client. Do not reach for a real database here; the
transaction body can be asserted by capturing the callback.
</context>

<steps>
1. Cover `change-password`: a wrong current password returns 400 and performs no
   write; reusing the current password as the new one is rejected; a weak new
   password is rejected by `validatePasswordStrength`; an account with no
   `passwordHash` is rejected.
2. On the success path, assert all three effects together: `sessionVersion`
   increments, `session.deleteMany` runs for that user inside the same
   transaction callback, and `invalidateSessionVersion` is called afterwards.
3. Cover the account export: assert the response omits `passwordHash` and
   `sessionVersion`, and that the headers set `Cache-Control: private, no-store`.
   Write the assertion so that adding a credential field to the `select` fails
   the test.
4. Cover account deletion: the `confirmation` literal `"DELETE"` is required; a
   wrong password opens no transaction; and an item authored by the deleted user
   on another owner's canvas is reassigned to that owner rather than removed.
</steps>

<acceptance>
- A test fails if any one of the three session-invalidation effects is dropped.
- A test fails if the account export `select` is widened to a credential field.
- No test in this card requires a live PostgreSQL instance.
</acceptance>

<verification>
`pnpm test:file` on the new files; `pnpm test -- --run`; `pnpm lint`;
`pnpm type-check`.
</verification>
