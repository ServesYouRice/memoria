# IMP-033 — Revocable public share links

<objective>
Turning public sharing off permanently invalidates the distributed URL, and an
owner can rotate a leaked link while sharing stays on.
</objective>

<files>
`src/app/api/v1/canvases/[canvasId]/public/route.ts`,
`src/app/api/v1/share/[token]/route.ts`,
`src/features/canvas/components/ShareDialog.tsx`, `prisma/schema.prisma`.
</files>

<steps>
1. On DELETE, clear `Canvas.shareToken` in the same update that sets
   `isPublic: false`. Do not preserve the old token for re-enable.
2. On POST, mint a fresh `nanoid(16)` whenever no token exists. Keep the
   existing token only while the canvas is already public.
3. Add an explicit owner "reset link" action that rotates the token on a public
   canvas, and record the rotation as an activity event.
4. In the share UI, state that disabling or resetting permanently breaks the old
   URL, and require confirmation before either action.
5. Invalidate the canvas cache on every token change so a revoked token stops
   resolving immediately.
6. Test disable-then-re-enable, reset while public, a revoked token returning
   not-found, and concurrent enable requests.
</steps>

<acceptance>
- A token captured before disabling never resolves again after re-enabling.
- Rotation is available without disabling public access first.
</acceptance>

<verification>
Real-DB share-route tests; targeted UI test; `pnpm type-check`; `pnpm lint`.
</verification>
