# IMP-047 - Make operations recoverable and observable

<objective>
The reference stack separates liveness from authenticated readiness, proves
email/outbox delivery, schedules monitored off-host backups with restore
evidence, and exposes actionable operations signals without leaking internals.
</objective>

<files>
Health/readiness/status routes and UI, Compose/Docker runtime, outbox worker and
providers, setup/smoke scripts, backup tooling/runbook, metrics/Sentry/alert
configuration and operations tests.
</files>

<context>
Corrects Opus PROD-05 through PROD-07 and strengthens PROD-09 through PROD-11
with Codex DEP-03 through DEP-08, PERF-06, and UI-02. `/api/health` is deliberate
process liveness and Compose already has a healthcheck, contrary to Opus. The
actual defects are the crashing public status client, readiness not controlling
the stack, unbounded outbox leases/provider calls, unproved sender setup,
unscheduled same-host recovery, and absent alerts.
</context>

<steps>
1. Keep public `/api/health` minimal liveness, update stale architecture copy,
   and make the public status page consume a sanitized, runtime-validated
   contract without exposing dependency details.
2. Make internal Compose/orchestrator traffic gating call authenticated
   readiness; define which dependency failures remove traffic versus degrade a
   feature. Add init/zombie reaping if the chosen container runtime needs it.
3. Give each outbox handler a deadline, per-job lease ownership/renewal,
   idempotent side effects, bounded concurrency, graceful shutdown, and queue
   age/dead-letter/lease-loss metrics.
4. Require a verified sender/domain and a controlled delivery probe during
   self-host setup; pass generated operations credentials into smoke correctly.
5. Schedule hourly encrypted/versioned off-host database and object backups,
   check freshness independently, alert on failure/age, and run an isolated
   restore drill for the exact candidate with measured RPO/RTO.
6. Supply a minimal scraper/dashboard/alert profile for readiness, HTTP errors,
   Redis/login safety, WebSockets, outbox, backup age, storage, and AI budgets;
   wire client Sentry only when explicitly configured.
7. Align CI and the production image on a supported LTS runtime or record and
   test an explicit support decision.
</steps>

<acceptance>
- Liveness, sanitized public status, and protected readiness are distinct and
  the reference stack removes an unready app from dependent traffic.
- Provider hangs cannot outlive ownership silently; verification/recovery email
  delivery is proven from the configured sender.
- Off-host backups and freshness alerts run automatically, and a clean restore
  meets recorded RPO/RTO for database plus objects.
- Every critical operational failure has a metric, threshold, owner, and
  exercised alert path.
</acceptance>

<verification>
Outbox timeout/lease/restart tests; email capture/provider probe; dependency
transition smoke; backup/freshness/restore drill; alert-rule tests;
`pnpm type-check`; `pnpm lint`; `pnpm build`; `pnpm smoke`.
</verification>
