# IMP-065 - Cover comment authorization by visibility and role

<objective>
Comment collection and item handlers enforce the shipped owner/share/public and
author/owner capability matrix, including cross-item comment IDs, before reads
or mutations escape their allowed scope.
</objective>

<files>
`src/app/api/v1/items/[itemId]/comments/route.ts`,
`src/app/api/v1/items/[itemId]/comments/[commentId]/route.ts`, and a new
`tests/api/comments-authorization.test.ts`.
</files>

<context>
Neither comment route is imported by an existing test. These handlers are not
owner-only. Collection GET permits an owner, any signed-in share recipient, or
an anonymous caller on a public canvas. Collection POST requires a session and
owner or COMMENT/EDIT share. Item GET requires a session and then permits an
owner, author, share recipient, or public-canvas viewer. PATCH is author-only;
DELETE is author-or-canvas-owner.

The item route also checks `comment.itemId === itemId`. That cross-resource
binding is a security invariant: a valid comment ID cannot be addressed through
a different item path.
</context>

<executor_constraints>
- Call the real GET/POST/PATCH/DELETE exports with mocked Auth.js, Prisma,
  activity logging, and sanitization dependencies as needed. Do not mock the
  route module or copy its role calculation into the test subject.
- Use one explicit persona fixture per capability: owner, author, VIEW share,
  COMMENT share, EDIT share, unrelated signed-in user, and anonymous caller.
- Assert zero comment read/create/update and zero activity logging on denied
  paths as applicable.
- Treat production files as read-only. Stop and add one exact `DEC-` row if the
  current handler violates the matrix in `<context>`.
</executor_constraints>

<steps>
1. Collection GET: prove owner and share recipients can list; an anonymous
   caller can list only when `canvas.isPublic` is true; and a private outsider
   reaches neither comment list nor count. Retain pagination predicates
   `itemId` and `deletedAt: null` in allowed queries.
2. Collection POST: prove missing session, VIEW share, and unrelated user cause
   no create or activity log, while owner, COMMENT share, and EDIT share can
   create. Assert the created row always uses the session user and path item ID.
3. Item GET: prove a missing session is rejected even for a public canvas, then
   cover owner/author/share/public visibility and private-outsider denial for a
   signed-in user.
4. Item PATCH: only the comment author may update. A canvas owner, share
   recipient, or unrelated user who is not the author performs no update.
   Item DELETE: author and canvas owner may soft-delete; other share recipients
   and outsiders may not.
5. For GET, PATCH, and DELETE, supply a comment whose `itemId` differs from the
   path and assert a not-found response plus zero mutation. Also prove an
   already-deleted comment is not exposed.
</steps>

<acceptance>
- Every exported comment method is exercised through the real handler.
- Tests encode the actual role/public matrix, not a blanket owner-only rule.
- Author-only edit and author-or-owner delete are independently proven.
- A comment ID cannot be read or mutated through another item's path.
- Denied requests perform no comment mutation or activity side effect.
- No production file changed.
</acceptance>

<verification>
`pnpm test:file tests/api/comments-authorization.test.ts`;
`pnpm test -- --run`; `pnpm lint`; `pnpm type-check`.
</verification>
