# IMP-113 - PDFs on the canvas: upload, read, search and ask

<objective>
A person can put a PDF on a canvas, open it, and find or ask about the
words inside it.
</objective>

<context>
Approved by the owner on 2026-11-11 with the competitor review ("richer
PDF items"). Today uploads accept images only, plus audio for voice notes
(`src/lib/uploads/file-types.ts`); there is no PDF or file item, and no
library that reads PDF text (`jspdf` only writes PDFs). IMP-094 adds the
store for saved text and makes search and "Ask" read it; this card reuses
that store instead of building a second one.
</context>

<executor_constraints>
- A PDF is recognised from its first bytes, never from the file name or
  the type the browser claims.
- A PDF is untrusted: it is stored privately, served only as a download or
  in the browser's own viewer in a new tab with safe headers, and never
  drawn inside the app page. The CSP stays as it is.
- Text is read in an outbox job that is safe to run twice, with limits on
  file size, page count and time, written into the resource budgets
  document. The reader is a maintained library that runs in Node without
  a browser or a native build (for example `pdfjs-dist`).
- The text is shown as plain text only and marked as data wherever it is
  given to AI or agents.
- PDFs count toward the person's upload allowance; keep the stated launch
  limits and `tests/unit/launch-surface-contract.test.ts` truthful.
- A new item type needs a Prisma migration and the same server checks as
  other items. Reading scanned pages (pictures of text) is out of scope.
</executor_constraints>

<acceptance>
- Dropping or choosing a PDF puts a card on the canvas with its name, page
  count and an "Open" action; people with view access can open it.
- Search and "Ask" find words that appear only inside the PDF.
- A PDF with no readable text, too many pages or too large says so in
  plain words and is still stored if it is within the size limit.
- A file that only claims to be a PDF is refused.
- The PDF and its text are deleted with the item and are part of the
  account export.
</acceptance>
