# IMP-129 - Shared-link and setup pages carry the Memoria name and a way on

<objective>
A visitor who opens a shared canvas, a broken link, or the finished setup
page sees whose app this is, reads the same words as on the sign-in page,
and always has a next step.
</objective>

<context>
Found in the UI audit of 2026-11-14.
- `/share/<token>` (public read-only canvas): the top bar has no Memoria
  logo; it says "(Read Only)", "Sign In" and "Sign Up" in Title Case; the
  sign-in page says "Sign in" and "Create account".
- A wrong or switched-off share link shows only a red box and a button
  "Go to Home", with no logo.
- `/setup` after setup is finished shows one grey box ("Initial setup is
  disabled because this instance already has at least one user.") and no
  link anywhere. It is a dead end.
Rule used (WCAG 3.2.4): same thing, same look, same words.
</context>

<files>
`src/app/share/[token]/page.tsx`, `src/app/setup/page.tsx`,
`src/app/share-invitations/[token]/InvitationResponseContent.tsx`,
`src/app/embed/[token]/EmbedViewer.tsx` (read only: do NOT add a logo or
links inside embeds), `src/components/MemoriaLogo.tsx`,
`tests/e2e/embeds.spec.ts`, `tests/e2e/launch-surface.spec.ts`.
</files>

<executor_constraints>
- Do not change who may see a shared canvas, token checks, or any API
  call.
- Do not change the embed page (`/embed/<token>`): it is shown inside
  other people's websites and must stay bare.
- Error text must not say whether a canvas exists. Keep the current
  generic error wording from the server.
</executor_constraints>

<steps>
1. `/share/<token>` top bar: add `<MemoriaLogo size={28} />` as the first
   item, as a link to `/` with `aria-label="Memoria home"`.
2. Same file, text changes (Old -> New):
   - `(Read Only)` -> `View only`, shown as a small outlined MUI `Chip`
     next to the canvas name instead of text in brackets
   - `Shared Canvas` (fallback name) -> `Shared canvas`
   - `Sign In` -> `Sign in`
   - `Sign Up` -> `Create account`
   - tooltips `Zoom In` / `Zoom Out` -> `Zoom in` / `Zoom out`
3. Same file, the error screen (the branch `if (error)`): show the logo
   and the word "Memoria" above the message, keep the `Alert`, and replace
   the button `Go to Home` with two buttons: contained `Go to Memoria`
   (`href="/"`) and outlined `Sign in` (`href="/auth/login"`).
4. `/setup` when setup is no longer available: keep the sentence but
   reword it to `Setup is already done on this installation.` and add a
   contained button `Go to sign in` (`href="/auth/login"`) under it. Show
   the logo above it.
5. `InvitationResponseContent.tsx`: when it shows an error or a finished
   state, make sure there is a button to continue: `Sign in`
   (`/auth/login`) when signed out, `Go to my canvases` (`/dashboard`)
   when signed in. Add one if it is missing.
6. Update tests that look for `Sign In`, `Sign Up`, `Read Only` or
   `Go to Home` (`grep -rnE "Sign Up|Sign In|Read Only|Go to Home" tests`).
</steps>

<acceptance>
- `/share/<valid token>` shows the Memoria logo linking to `/`, a "View
  only" chip, and buttons "Sign in" and "Create account".
- `/share/<wrong token>` shows the logo, the error message, and the
  buttons "Go to Memoria" and "Sign in".
- `/setup` on an installation that already has a user shows a "Go to sign
  in" button that opens `/auth/login`.
- `/embed/<token>` looks exactly as before.
- At 390px wide the share page top bar does not overlap or scroll
  sideways.
</acceptance>

</verification>
