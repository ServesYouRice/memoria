# IMP-109 - One item on several canvases

<objective>
The same note or link can sit on more than one canvas. Change it once and
it changes everywhere.
</objective>

<context>
Approved by the owner on 2026-11-11: this is the signature feature of the
leading personal visual-notes app, and the biggest job on the list. Today
a `CanvasItem` belongs to exactly one canvas, each canvas has its own live
document on the sync server, and limits, sharing, version history, trash
and exports all assume one item, one canvas.
</context>

<files>
`prisma/schema.prisma`, `src/lib/collaboration/`,
`src/app/api/v1/canvas-items/`, `src/lib/policy/capacity.ts`,
`src/lib/services/archive.ts`, `src/features/canvas/components/`,
`tests/integration/`.
</files>

<executor_constraints>
- Settle the data design and the sync design first and consult a
  higher-tier model on them before coding; build it in small steps that
  each pass the checks.
- Content lives once; each canvas holds only where the item sits. Schema
  changes need Prisma migrations and PostgreSQL tests.
- Permissions: only the owner can place an item on another canvas, and
  only onto canvases they own. Anyone who can see a canvas sees the item
  there. It can be edited where the person may edit the item's home
  canvas; elsewhere it is read-only with "Open original".
- Each placement counts toward that canvas's item limit.
</executor_constraints>

<acceptance>
- An item's menu offers "Also show on..." and lists the owner's canvases.
- An edit on one canvas appears on the others within a few seconds, also
  for people working there live.
- The item shows which canvases it is on. Removing it from one canvas
  leaves the others; deleting the original says where else it will
  disappear and sends it to the trash once.
- Search lists the item once. Version restore, trash, export and sharing
  each have a test for a shared item.
</acceptance>

<verification>
`pnpm test:file` for the new tests; `pnpm gate fast`;
`pnpm gate integration` and `pnpm gate e2e` on the dev machine.
</verification>
