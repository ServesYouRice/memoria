# IMP-048 - Bound resource cost at supported scale

<objective>
Canvas loading, viewport persistence, thumbnails, AI, export, and other large
account paths have explicit byte/time/concurrency budgets and measured behavior
at the advertised launch limits.
</objective>

<files>
Canvas data/virtualization/accessibility hooks, viewport persistence,
thumbnail generation/jobs, AI routes/service, usage policy, account export,
metrics and performance/load tests.
</files>

<context>
Combines Opus PERF-02/03/06/10-13, SEC-08, and LOG-18 with Codex PERF-01/02/03
and capacity findings. Corrections: AI summarize is count-bounded at 2,000 but
queries twice what it uses; account export lacks a content-byte bound and is
both expensive and incomplete. Konva drawing is culled, but network hydration
and the accessible organizer still load the full canvas. Opus's proposed
parallel offset paging is unsafe; IMP-040's cursor contract is prerequisite.
</context>

<steps>
1. Make viewport/cursor loading the primary data path while preserving
   lightweight off-screen geometry needed for search, fit, selection, export,
   reconnect, and accessibility. Paginate the accessible organizer.
2. Reset viewport initialization on `canvasId`, catch storage failures, and
   persist local/server viewport state only at a throttled idle/gesture boundary.
3. Schedule thumbnail generation from stable revisions off the interaction
   path, avoid per-render O(n) revision strings, and prove generated assets are
   displayed and lifecycle-cleaned.
4. Add an operator AI capability switch, atomic per-user token/cost/concurrency
   budgets, bounded prompts, typed provider failures, redacted logging, usage UI,
   metrics, and alert thresholds.
5. Query only the AI items consumed. Replace synchronous account export with a
   complete versioned, checksummed, cancellable streaming/background archive
   including documented user data and authorized upload objects.
6. Retune route/principal budgets only after avoidable invalidations and cursor
   traffic are removed; define budgets from measured normal and hostile flows.
7. Establish regression budgets for 500/1,000/2,000-item canvases, event-loop
   lag, pan frame time, memory, payloads, export, and 50+ collaboration clients.
</steps>

<acceptance>
- Supported large canvases become interactive and remain within documented
  memory/payload/frame/event-loop budgets without silently omitting items.
- Viewport and thumbnail persistence do not block pointer interaction or leak
  state across canvases.
- AI spend and export resource use are atomically bounded, observable, and
  user/operator understandable; export is complete for its declared manifest.
</acceptance>

<verification>
Canvas/load/export/AI quota benchmarks and concurrency tests; thumbnail lifecycle
tests; viewport navigation/storage tests; `pnpm type-check`; `pnpm lint`;
`pnpm build`; bundle budget check.
</verification>
