# IMP-010 — Safe templates and duplication

<objective>
Follow DEC-003: either hide templates/duplication cleanly, or make cloning
atomic and self-contained.
</objective>

<steps>
1. If `hide`, remove launch UI/actions and return an explicit disabled response;
   preserve stored data.
2. If `repair`, choose one template manifest/category model for built-ins and
   saved templates.
3. Clone in one transaction using an old-to-new item ID map. Rewrite arrows,
   connections, typed references, workspace ownership, and copied asset rows/
   objects. Define comments/history metadata explicitly.
4. Exclude templates from normal canvas lists; make deletion semantics truthful.
5. Normalize blank optional fields and share category validation across API/UI.
6. Test arrows, images, source deletion, rollback, categories, and default form.
</steps>

<acceptance>
- A cloned canvas never reads an object or item owned only by the source.
- Default template actions succeed, or the feature is absent and gated.
</acceptance>

<verification>
Real-DB template tests; targeted UI tests; `pnpm type-check`; `pnpm lint`.
</verification>
