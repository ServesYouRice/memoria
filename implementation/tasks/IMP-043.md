# IMP-043 - Realtime split and replica-ready processes

<objective>
The presence/sync realtime service runs separately from the Next.js app, and
the app and sync server can each run two replicas correctly; production keeps
one until it is needed.
</objective>

<context>
Handbook: rolling updates for stateless apps; the sync server needs
Hocuspocus's Redis extension for a second replica. Presence fan-out over Redis
already exists. Leases, rate limits, and job claims must hold across replicas
(the outbox already claims with `SKIP LOCKED`).
</context>

<files>
`server.ts`, `src/lib/collaboration/`, `src/lib/rate-limit*`, `Caddyfile`,
`docker-compose.yml`, `ARCHITECTURE.md`.
</files>

<steps>
1. Move WebSocket upgrades out of the Next.js process into the realtime
   service; route `/api/collaboration/*` to it.
2. Enable the Hocuspocus Redis extension and make per-user/per-canvas limits
   Redis-backed.
3. Add a two-replica compose profile and a test that connects clients to
   different replicas.
</steps>

<acceptance>
- Clients on different replicas see each other's presence and edits.
- Rate and connection limits hold across replicas.
- Single-replica production behaviour is unchanged.
</acceptance>

<verification>
`pnpm test -- --run`; integration suite; a two-replica E2E run;
`pnpm build`; `pnpm smoke`.
</verification>
