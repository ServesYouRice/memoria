# IMP-086 - Settings: a side menu instead of one long page

<objective>
People find a setting in one click instead of scrolling. Today Settings is
one page about 6,000px tall with twelve stacked sections.
</objective>

<context>
From the 2026-11-11 UI review. `src/app/settings/SettingsContent.tsx` stacks
Profile, Change password, Sign-in security, Preferences, Notifications,
Keyboard shortcuts, AI provider, Agent control center, AI usage, Developer
settings, Your data and Danger zone (parts live in `AiProviderSettings`,
`AutoFileSettings`, `LinkEnrichmentSettings`, `NotificationPreferences`,
`WeeklyRecapSettings` and `SecuritySettings`). "Sign out" is repeated inside
Danger zone although it is already in the account menu.
</context>

<files>
`src/app/settings/`, `src/features/auth/components/SecuritySettings.tsx`,
`tests/unit/settings-change-password.test.tsx`,
`tests/unit/settings-export-cancel.test.tsx`.
</files>

<executor_constraints>
No setting is removed and no server behaviour changes. Existing links to
`/settings` keep working.
</executor_constraints>

<acceptance>
- A side menu (tabs on a phone) with six groups: Account; Sign-in and
  security; Appearance (preferences, keyboard shortcuts); Notifications
  (with the weekly recap); AI assistant (provider, usage, auto-file, link
  details, agents, developer settings); Your data (export, delete account).
- Each group has its own address so links and the Back button work;
  `/settings` opens Account. Only the open group is shown.
- A greyed-out button says why in a short line beside it.
- Each group opens with one plain sentence; "Sign out" is only in the
  account menu.
- The two settings unit tests pass.
</acceptance>

</verification>
