# IMP-141 - An empty canvas shows a first step

<objective>
A canvas with nothing on it shows a short hint in the middle: a title,
one line and two buttons ("Add a note", "Add a link"). It disappears as
soon as the first item exists.
</objective>

<context>
Found in the UI audit of 2026-11-14. Every other empty page in the app
has a title, one sentence and a button (the shared `EmptyState`
component). The most important empty page, a brand-new canvas, shows a
blank grid and nothing else.
Rule used (GitHub Primer): an empty screen needs a title, one line and
one main action.
Two things the audit sketch showed that must NOT be built, because the
app cannot do them today:
- "Double-click the canvas to drop a note": there is no such handler.
- "Use a template": templates can only be picked when a canvas is
  created, not applied to an existing one.
</context>

<files>
`src/features/canvas/components/CanvasBoard.tsx` (the `Box` with
`ref={stageContainerRef}`; `totalItemCount`; `canEdit`;
`setNoteDialogOpen`; `setBookmarkDialogOpen`; `isPresentationMode`;
`viewMode`), `src/components/layout/EmptyState.tsx`, new
`src/features/canvas/components/CanvasEmptyHint.tsx`.
</files>

<executor_constraints>
- The hint must not block the canvas: its wrapper uses
  `pointerEvents: "none"`; only the two buttons use
  `pointerEvents: "auto"`. Panning, zooming and the toolbar keep
  working underneath and around it.
- Do not show the hint while items are still loading, or it will flash
  on every canvas. Find the loading flag of the data that feeds
  `totalItemCount` and wait for the first load to finish.
- The hint is ordinary page markup, not drawn on the canvas, so it
  never appears in thumbnails or exports.
- Do not promise an action the app does not have.
</executor_constraints>

<steps>
1. Create `CanvasEmptyHint.tsx` with props `canEdit`, `onAddNote`,
   `onAddLink`. It renders the shared `EmptyState` inside a centred
   box (max width 360px, `bgcolor: "background.paper"`):
   - when `canEdit` is true: title `Start anywhere`, description
     `Add a note or a link, then drag it wherever you like.`, and two
     buttons: `Add a note` (contained) and `Add a link` (outlined);
   - when `canEdit` is false: title `Nothing here yet`, description
     `Nothing has been added to this canvas.`, no buttons.
2. In `CanvasBoard.tsx`, inside the stage container box, render
   `<CanvasEmptyHint>` when all of these are true: the free-layout view
   is showing (`viewMode === "manual"`), presentation mode is off, the
   first load of items has finished, and `totalItemCount === 0`.
3. Wire the buttons: `Add a note` does exactly what the toolbar's
   `Note` button does (today `setNoteDialogOpen(true)`); `Add a link`
   does what the toolbar's `Link` button does (today
   `setBookmarkDialogOpen(true)`). Call the same functions so later
   changes to those buttons carry over.
4. Place the hint so it does not sit under the bottom toolbar on a
   phone: centre it in the space above the toolbar.
5. Tests: `tests/unit/canvas-empty-hint.test.tsx`: editors see the
   title, the line and both buttons, and each button calls its
   callback; viewers see `Nothing here yet` and no buttons. If
   `CanvasBoard` has a render test, add a case that the hint is absent
   when `totalItemCount` is 1.
</steps>

<acceptance>
- Opening a new canvas shows `Start anywhere` with `Add a note` and
  `Add a link`; clicking either opens the same thing as the toolbar
  button.
- After the first note is added the hint is gone; deleting every item
  brings it back.
- A view-only visitor sees `Nothing here yet` and no buttons.
- A canvas with items never shows the hint, not even briefly while it
  loads.
- At 390x844 the hint and the toolbar do not overlap.
</acceptance>
