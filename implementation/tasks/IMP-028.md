# IMP-028 — Edge and operations hardening

<objective>
Reduce operational disclosure and security ambiguity without duplicating
controls that already exist.
</objective>

<files>
`src/app/api/health/route.ts`, `src/app/api/metrics/route.ts`,
`src/middleware/security-headers.ts`, `src/lib/security/headers.ts`,
`src/middleware/cors.ts`, `src/lib/logger/index.ts`,
`src/lib/utils/ssrf-protection.ts`, `src/lib/api/api-key.ts`,
`src/lib/api/api-key-auth.ts`.
</files>

<steps>
1. Split minimal public liveness from internal authenticated/network-restricted
   readiness and metrics. Configure traffic removal separately from restart.
2. Preserve the existing production HSTS middleware and add a response test.
   Remove or set legacy `X-XSS-Protection` to `0`.
3. Reject wildcard credentialed CORS and warn when allowed origins diverge from
   `AUTH_URL`.
4. Use allowlisted structured logging plus recursive secret scrubbing tests for
   nested, capitalized, error, and stringified values.
5. Add hostile SSRF fixtures for alternate IPv4 notation, mapped IPv6, redirects,
   and DNS rebinding; pin connections to the vetted address where required.
6. Migrate remaining plaintext legacy API keys, then remove the legacy compare.
</steps>

<acceptance>
- Public probes reveal no dependency/process internals.
- HSTS is emitted once in production and secret/SSRF regression tests pass.
</acceptance>

<verification>
Security/request-boundary tests; `pnpm type-check`; `pnpm lint`; production smoke.
</verification>
