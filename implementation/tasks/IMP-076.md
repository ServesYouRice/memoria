# IMP-076 - Bell shows no badge when nothing is new

<objective>
The notification bell shows a red count only when there is something unread.
Today a red "0" appears after a full page load.
</objective>

<context>
Found in the 2026-11-11 UI review on a local dev build (not yet checked on a
production build). `AppShell.tsx` renders
`<Badge badgeContent={unreadNotifications} color="error" max={99}
invisible={unreadNotifications === 0}>`. After a full load the badge has the
`MuiBadge-invisible` class, but its hide rule
(`transform: scale(0) translate(var(--Badge-translate))`) computes to `none`
because the variable is unset, so the "0" stays visible. After in-app
navigation it hides correctly. Simplest fix: do not render the count bubble
at all when the count is zero.
</context>

<files>
`src/components/layout/AppShell.tsx`,
`tests/unit/app-shell-accessibility.test.tsx`.
</files>

<acceptance>
- With zero unread notifications no badge is visible after a full page load
  and after in-app navigation, in light and dark.
- With unread notifications the count shows; above 99 it shows "99+".
- The bell's accessible name still says whether anything is unread.
- A unit test covers the zero case.
</acceptance>

<verification>
`pnpm test:file tests/unit/app-shell-accessibility.test.tsx`;
`pnpm gate fast`; a production-build screenshot of the top bar after a hard
reload with zero unread.
</verification>
