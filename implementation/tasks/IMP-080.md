# IMP-080 - Screens use theme colours, not hand-typed ones

<objective>
Colours come from one place, so dark mode and the brand apply everywhere.
Today 116 colours are typed by hand into 24 screen files and ignore both.
</objective>

<context>
Counted in the 2026-11-11 UI review: six-digit hex colours in non-test
`.tsx` files under `src/app`, `src/features` and `src/components`. Heaviest:
`ReadonlyCanvasItemLayer.tsx` (35), `BookmarkItem.tsx`, `ImageItem.tsx` and
`PollItem.tsx` (8 each), `EmbedItem.tsx` (7), `FrameItem.tsx` (4),
`NoteItem.tsx`. The command palette highlights its selected row in stock
blue (`rgba(25, 118, 210, 0.12)` / `#1976d2` in
`src/components/command-palette.css`). Canvas items are drawn with Konva and
cannot read MUI `sx`; they need one small shared palette fed by the theme
and the light/dark mode.
</context>

<files>
`src/lib/theme.ts`, `src/components/command-palette.css`,
`src/features/canvas/components/`, `src/features/`, `src/app/`,
`tests/unit/`.
</files>

<executor_constraints>
Colours a user picks (drawing and note colours) are content, not theme, and
stay as stored. No layout changes in this card.
</executor_constraints>

<acceptance>
- Screen files hold no hard-coded hex or rgb colours outside the theme, the
  shared canvas palette and a short written allowlist.
- The command palette's selected row uses the brand colour, light and dark.
- A check (lint rule or source-scanning unit test) fails when a new
  hard-coded colour appears outside the allowlist.
- Dark mode shows no leftover light boxes on the dashboard, a canvas, the
  shared read-only view, settings and search.
</acceptance>

`pnpm test:file <new guard test>`; `pnpm gate fast`; `pnpm gate e2e` on the
dev machine; dark-mode screenshots of the five screens named above.
</verification>
