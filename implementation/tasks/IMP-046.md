# IMP-046 - Make the launch surface truthful and accessible

<objective>
Every visible launch action is supported, notifications render notification
state, canvas/search/share composition has one accessible contract, and public
copy matches enforced product limits and evidence.
</objective>

<files>
Dashboard, notification, canvas, share-dialog, shell, landing, theme CSS and
their route/component/browser tests.
</files>

<context>
`/templates` is an intentional launch gate, while duplicate controls still
expose disabled entry points. The accessible panel is duplicated on editable
and public routes. `/notifications` is reachable, but it currently reads
activities rather than presenting real notification state.
</context>

<steps>
1. Drive templates/duplication/polls from one capability registry and remove
   every disabled launch entry point and claim while retaining server auth.
2. Connect `/notifications`, the bell badge, read state, actions, and Settings
   preferences to notification APIs; honor preferences at dispatch and label
   any retained activity feed as Activity.
3. Render exactly one accessible item panel per editable/public canvas route and
   add route-composition assertions for unique landmarks, IDs, and item rows.
4. Define in-canvas search behavior for text/content versus structural context;
   do not unmount board structure in a way that reads as deletion.
5. Add skip navigation, `aria-current`, desktop navigation landmarks, and
   programmatic/mobile-safe share-dialog controls and confirmations.
6. Align Tiptap/command-palette CSS with explicit app theme selection and test
   opposite OS/app theme combinations.
7. Guard Enter creation against duplicate submits, preserve the shipped typed
   mutation feedback, and use the authoritative totals/loaded-only response
   contract already present in the current source.
8. Replace unlimited/free-forever/social-proof/enterprise/export claims with
   measured capabilities and enforced launch limits.
</steps>

<acceptance>
- No visible launch action calls a deliberately disabled route.
- Notification unread/read/preferences/actions work end to end, and activity is
  not presented as notification state.
- Canvas/share routes contain one accessible organizer, pass keyboard/mobile
  composition checks, and search preserves understandable structure.
- Theme and public copy match the selected settings and shipped capabilities.
</acceptance>

<verification>
Focused component/route tests; 320/375/768/1024/1440 Playwright scenarios;
axe plus keyboard assertions; both selected themes against opposite OS theme;
`pnpm type-check`; `pnpm lint`; targeted public-copy assertions.
</verification>
