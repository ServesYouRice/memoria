# IMP-073 - Prefix every Redis key and channel with `memoria:`

<objective>
Memoria works on the cluster's shared Valkey, whose ACL user for Memoria may
touch only keys and pub/sub channels under `memoria:`.
</objective>

<context>
Found while drafting IMP-056 (infra PR ServesYouRice/Infra#4). Today the keys
are unprefixed (`ratelimit:*`, `unfurl:*`, `api-key*`, `clip-batch*`,
`status*`) and so is the channel `collaboration:sync:documents`; under the
ACL these get NOPERM while PING and readiness still pass, so the failure is
silent. `src/lib/cache/unfurl-cache.ts` also calls `KEYS`, which the ACL
refuses. ioredis `keyPrefix` alone does not cover pub/sub channels.
</context>

<files>
Redis clients and callers under `src/lib/` (rate limit, unfurl cache, API
keys, clip batches, status, collaboration fan-out), `docker-compose*.yml`,
`.env.example`.
</files>

<acceptance>
- One configurable prefix (`REDIS_KEY_PREFIX`, default `memoria:`) applies to
  every key and every published or subscribed channel.
- No `KEYS`; scans use `SCAN` with the prefix.
- A test against a real Redis/Valkey with an ACL user limited to `memoria:*`
  and `&memoria:*` exercises rate limits, caches and the collaboration channel.
</acceptance>

<verification>
`pnpm test -- --run`; `pnpm gate integration`; `pnpm gate e2e`.
</verification>
