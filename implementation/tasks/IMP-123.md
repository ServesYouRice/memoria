# IMP-123 - One name for two-step codes

<objective>
The extra sign-in code feature has one name everywhere a person can read
it: "two-step codes".
</objective>

<context>
Found in the UI audit of 2026-11-14. The same feature is called "two-step
codes" in the Settings menu, "two-factor authentication" on the security
screen and at sign-in, and "Authenticator app" in one heading. The owner
already uses "two-step codes" (see DEC-017 in `../KANBAN.md`), so that is
the name to keep. Rule used: one word per idea.
</context>

<files>
`src/features/auth/components/SecuritySettings.tsx` (about 13 places),
`src/features/auth/components/LoginForm.tsx` (3 places),
`src/app/settings/SettingsContent.tsx`, `src/app/settings/sections.ts`,
`tests/e2e/sign-in-security.spec.ts`.
</files>

<executor_constraints>
- Change words a person reads (text, `aria-label`, toast and error
  messages). Do not rename code: variables, functions, API routes, Better
  Auth plugin names (`twoFactor`), database fields and test ids stay.
- Do not change how sign-in or setup works.
- "authenticator app" may stay inside a sentence that tells the person
  which kind of app to install (for example "Scan this with an
  authenticator app"). It must not be used as the feature's name or as a
  heading.
</executor_constraints>

<steps>
1. Run `grep -rnoiE "two-factor[a-z ]*|2FA|authenticator app|two-step[a-z ]*" src --include=*.tsx --include=*.ts`
   and read every match.
2. For each match that a person can read, rewrite it with these words:
   - the feature: `two-step codes`
   - status on: `Two-step codes are on`
   - status off: `Two-step codes are off`
   - turning it on: `Turn on two-step codes`
   - turning it off: `Turn off two-step codes`
   - at sign-in: `Enter your two-step code`
   - an error at sign-in: `That two-step code did not work. Try again.`
   - a heading that says `Authenticator app` becomes `Two-step codes`.
3. Update tests that look for the old words (start with
   `tests/e2e/sign-in-security.spec.ts` and
   `grep -rniE "two-factor|authenticator app" tests`).
</steps>

<acceptance>
- `grep -rniE "two-factor|2FA" src --include=*.tsx` shows no text that a
  person can read (code identifiers may remain).
- No heading or button uses "Authenticator app" as the feature's name.
- Turning two-step codes on and off, and signing in with a code, still
  work.
</acceptance>

<verification>
`pnpm lint`; `pnpm type-check`; `pnpm test -- --run`;
`node scripts/run-e2e.mjs --project=chromium tests/e2e/sign-in-security.spec.ts`
(this test is also the subject of IMP-119; if it fails for the reason
described there, say so in the report instead of changing it).
</verification>
