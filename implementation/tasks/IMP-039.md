# IMP-039 - Cloudflare R2 as the production object store

<objective>
Production uploads, thumbnails, exports, and backups work against Cloudflare R2
with no code change beyond configuration, while local and self-host stacks keep
SeaweedFS.
</objective>

<context>
Handbook: memoria uses the shared R2 account (one bucket) and skips its bundled
object store in production. Recent AWS SDK v3 releases send CRC32 checksums by
default, which R2 does not fully accept on every operation; the client must
only send checksums when the operation requires them.
</context>

<files>
`src/app/api/v1/upload/route.ts` (`getS3Client`), every other `new S3Client(`
call site, `src/lib/env.ts`, `.env.example`, `docs/operations/`,
`scripts/backup-database.sh`.
</files>

<steps>
1. Create S3 clients through one shared factory that sets
   `requestChecksumCalculation` and `responseChecksumValidation` to
   `WHEN_REQUIRED`, `region: "auto"` when the endpoint is R2, and path-style
   addressing only where the endpoint needs it.
2. Make the backup upload path use the same settings (AWS CLI env or flags).
3. Document the R2 variables (endpoint, bucket, keys, public/private URL
   handling) beside the SeaweedFS defaults.
</steps>

<acceptance>
- One client factory; no direct `new S3Client(` outside it.
- Unit tests pin the checksum and region settings for R2 and SeaweedFS
  endpoints.
- Upload, private-image read, export download, and backup run against an
  S3-compatible service in the existing integration or smoke path.
</acceptance>

<verification>
`pnpm test -- --run`; `pnpm type-check`; `pnpm lint`; `pnpm build`;
`pnpm smoke`.
</verification>
