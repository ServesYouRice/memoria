<assessment>
The Opus audit is strongest where it traces client/API contract drift and local
hot paths. It independently confirms the byte-truncation bug, public-share
envelope/pagination mismatch, missing thumbnails, cursor flood, authentication
ordering, optimistic mutation races, and several accessibility gaps. Its
production verdict is still no-go, but its blocker list is not reliable as-is:
it promotes deliberate product choices and unmeasured costs to blockers, and it
misses several more serious deployment and security failures found by the
independent audit.

Other material corrections:

- SEC-06's cross-account query-cache scenario is not reachable through the
  shipped sign-out actions: every call uses redirecting `signOut`, which causes
  a document navigation. Cache clearing is defense in depth, not a demonstrated
  leak.
- SEC-13 is false for ordinary self-hosting. `@vercel/analytics` loads
  `/_vercel/insights/script.js` from the current origin; without Vercel's edge
  route it fails locally rather than beaconing directly to Vercel.
- LOG-15 is false: `useCanvasItemsWithPolling` exists but has no caller. The
  active board uses normal queries plus committed WebSocket events.
- LOG-16 is false under the production contract: when `REDIS_URL` exists,
  ioredis constructs a reconnecting client synchronously and the subscriber is
  duplicated from it even if the first connection is unavailable.
- LOG-10 identifies an availability tradeoff, but its fail-open remedy is not
  acceptable without a bounded authorization lease. Revoked access must remain
  fail-closed.
- LOG-18 overstates the AI query as unbounded; launch limits cap it at 2,000
  items. The extra fetch is wasteful. Account export remains materially
  unbounded by content bytes and is tracked separately.
- UI-06 is incomplete: duplicate accessible panels exist on both editable and
  public canvas routes, as the independent audit found.
- UI-13 is false as written because mobile users can reach the activity list at
  `/notifications`; that route is itself wrongly implemented as activity rather
  than notifications.
- UI-15c is unreachable for valid durable items because create, geometry, and
  batch schemas require positive finite width and height.
- PERF-11's `pageCount < 100` guard can be reached when byte truncation accepts
  very few items, and parallel offset requests are not a safe remedy under
  concurrent writes. Use an authoritative cursor.
- PERF-12 is no longer merely "verify": Konva drawing is culled, but the client
  still fetches the full canvas and mounts the full accessible list, currently
  twice. Network, memory, and assistive-technology cost still scale with all
  items.
- PROD-02 contradicts the audit's own "no commands were executed" scope while
  claiming observed push/test retries. Its runtime evidence is not accepted.
- PROD-07 is false for the reference deployment: `docker-compose.yml` already
  defines the app healthcheck. The real issue is that it probes liveness rather
  than protected readiness.
- The SEC-02 registration note incorrectly says password hashing occurs before
  the duplicate lookup; current source hashes only after that lookup.

High-risk omissions from Opus, independently traced and promoted:

- Fresh self-host setup preserves repository-known operations and backup HMAC
  secrets; Compose also drops registration, trusted-proxy, and auth-rate
  settings and supplies no supported HTTPS/WSS ingress (IMP-042).
- Host validation is vulnerable to DNS rebinding because validation and fetch
  resolve separately; the advertised unfurl kill switch is unused (IMP-043).
- JSON/item bodies as well as multipart bodies lack enforceable byte/structure
  limits, and raster uploads lack decoded-dimension controls (IMP-043).
- `pnpm audit --prod --audit-level=high` was rerun on 2026-08-10 and still fails
  with 5 High and 5 Moderate advisories (IMP-043).
- The public status component crashes on the intentional liveness payload, the
  notification page reads activities instead of notifications, and gated
  Duplicate actions always fail (IMP-046/IMP-047).
- Outbox batches can outlive their leases, setup does not prove a verified email
  sender, backups are neither scheduled nor monitored off-host, and the stack
  has no actionable alert loop (IMP-047).
</assessment>
