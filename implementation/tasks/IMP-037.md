# IMP-037 - Search, sharing, and mutation dialogs

<objective>
Search, public-link sharing, and mutation dialogs present server-authoritative
results and preserve recoverable user input when an operation fails.
</objective>

<context>
Reuse the problem-detail/search contracts from IMP-029 and
the revocable-link contract from IMP-033, archived under
`../archive/2026-08-01/tasks/`.
</context>

<files>
`src/components/GlobalSearchDialog.tsx`, `src/app/search/`,
`src/features/canvas/components/CanvasDialogs.tsx`,
`src/features/canvas/components/ShareDialog.tsx`,
`src/lib/api/fetch-client.ts`, `src/lib/api/error-utils.ts`, `tests/`.
</files>

<steps>
1. Standardize dialog pending/error/success behavior: await mutations and
   clipboard/export actions, retain input on failure, and expose safe problem
   detail, request ID, and retry timing where useful.
2. Display server total counts, type/tag facets, and readable snippets for every
   supported search result type; remove unsupported filter claims.
3. Add owner-visible public-link reset, permanent-revocation language, and
   confirmation before disabling or rotating a link.
4. Test malformed errors, 429 timing, rejected dialog actions, complete search
   facets, and disable/re-enable/reset share journeys.
</steps>

<acceptance>
- Rate limits and failed mutations never appear as success or generic data loss.
- Search totals and facets describe the complete server result set.
- An owner can rotate a public link without first disabling sharing.
- The UI states that disabling or resetting permanently invalidates the old URL.
</acceptance>

<verification>
Targeted dialog/search/share UI tests; `pnpm type-check`; `pnpm lint`.
</verification>
