# IMP-031 — Runtime collaboration efficiency

<objective>
Remove avoidable per-request/connection load while preserving fast revocation
and smooth presence.
</objective>

<files>
`src/lib/api/session-cache.ts`, `src/lib/collaboration/websocket-server.ts`,
`src/lib/cache/redis-client.ts`, `src/lib/rate-limit/stores/redis.ts`,
`src/lib/hooks/use-collaboration.ts`, `server.ts`.
</files>

<steps>
1. Cache `sessionVersion` in Redis for the accepted short revocation window and
   invalidate on password/account/session changes.
2. Batch WebSocket authorization revalidation by canvas/user or honor the lease
   instead of forcing two queries per connection every heartbeat.
3. Coalesce cursor snapshots on a bounded ticker and send deltas where possible;
   drop excess cursor noise instead of closing healthy sessions.
4. Reuse the shared Redis client/config for rate limiting and remove misleading
   alternate connection settings.
5. Fix dev upgrade coexistence and rate-limit identity behavior.
6. Load-test request QPS, 20-client cursor traffic, revocation latency, Redis
   reconnect, and process loss.
</steps>

<acceptance>
- Revocation stays within the declared window.
- Cursor fanout and auth queries grow within measured budgets.
</acceptance>

<verification>
Redis/WebSocket integration tests; load artifact; type/lint.
</verification>
