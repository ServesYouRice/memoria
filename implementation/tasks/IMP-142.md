# IMP-142 - Double-click a note and type on it (no pop-up form)

<objective>
Changing a sticky note no longer opens a big pop-up. Double-click
(or double-tap, or Enter) puts a text cursor on the note itself; the
board stays visible; changes save as you type, as they do today.
</objective>

<context>
Found in the UI audit of 2026-11-14. Editing a note is the most common
action in the app. Today it opens the dialog "Edit Note", which covers
the board the person is thinking on.
Rule used: type straight onto the note, as other canvas tools do
(tldraw, Excalidraw).
How it works today:
- `CanvasBoard.tsx`: `handleActivateItem` -> `handleNoteDoubleClick`
  -> `setEditingNoteItem(item)` + `setEditNoteDialogOpen(true)`.
- `EditNoteDialog.tsx` has two modes. Live mode (`SharedNoteDialog`):
  used when the canvas document is open and writable
  (`sharedFragment` is not null) and the item is a NOTE; it shows
  `<RichTextEditor collaboration={{ fragment }} />`, a tag field and
  the line "Changes save as you type and appear for everyone on this
  canvas." Form mode: used otherwise (and for TEXT items); it has a
  Save button.
- Notes are drawn on a canvas element by `NoteItem.tsx` at
  `item.positionX`, `item.positionY`, `item.width`, `item.height`. The
  board's pan is `position` and its zoom is `zoom`.
- `RichTextEditor` already has its own small formatting bar.
- Canvas shortcuts already ignore keys typed in an editor
  (`shouldIgnoreGlobalShortcut` from `src/lib/keyboard/shortcuts.ts`,
  called in `use-canvas-keyboard.ts`).
This card only changes where the live editor appears. It reuses the
same editor and the same shared text, so saving and co-editing do not
change.
</context>

<executor_constraints>
- Do not write a second way of saving. Use the same shared text
  (`documentSession.noteFragment(item.id)`) and the same
  `RichTextEditor` that `SharedNoteDialog` uses.
- Keep `EditNoteDialog` working. It stays as the fallback and as the
  place for tags.
- Keep every permission check (`capabilities.canEditItems`). A viewer
  must not get an editor.
- Typing in the note must never trigger canvas shortcuts (Delete,
  arrows, Space, "/"). Test this.
- If you are a small model and the co-editing code is unclear, ask an
  advisor model before changing anything in `src/lib/collaboration/` or
  `use-canvas-document.ts`. This card should not need changes there.
</executor_constraints>

<steps>
1. Add a pure helper `noteScreenRect(item, position, zoom)` in
   `note-screen-rect.ts` that returns where the note is on screen,
   relative to the stage container:
   `left = item.positionX * zoom + position.x`,
   `top = item.positionY * zoom + position.y`,
   `width = item.width * zoom`, `height = item.height * zoom`.
2. Decide the mode in `handleNoteDoubleClick`. Edit in place only when
   ALL are true; otherwise open the dialog exactly as today:
   - the item is a NOTE (not TEXT);
   - live editing is available (the same test `EditNoteDialog` uses for
     `sharedFragment`);
   - the note's on-screen width (`item.width * zoom`) is at least
     160px.
3. Create `NoteInlineEditor.tsx`. It is rendered inside the stage
   container box (the one with `ref={stageContainerRef}`), positioned
   absolutely with `noteScreenRect`. Build it at the note's real size
   (`item.width` x `item.height`) and apply
   `transform: scale(zoom)` with `transformOrigin: "top left"`, so the
   text is the same size as on the canvas. Give it the note's own look:
   background and text colour from `noteColorsFor(item.content, mode)`,
   padding, corner radius and font size from `NOTE_STYLE`. Its height
   may grow with the text (minimum = the note's height); it scrolls
   inside itself rather than leaving the screen.
4. Inside it render
   `<RichTextEditor key={fragmentKey(fragment)} collaboration={{ fragment }} ... />`
   the same way `SharedNoteDialog` does (move `fragmentKey` to a shared
   place instead of copying it). Remove the editor's own border here so
   it reads as the note. Put the cursor in the text, at the end, when
   it opens.
5. Under the note show a small bar with two buttons: `Tags` (closes the
   in-place editor and opens the existing dialog for this note) and
   `Done`. Add `aria-label="Editing note"` and `role="group"` on the
   wrapper.
6. Closing: `Done`, the Escape key, or a click or tap anywhere outside
   the editor closes it. Nothing needs saving. Focus goes back to where
   it came from (the canvas, or the item's row in the item list).
7. While the editor is open it follows the note: recompute the
   position on every pan, zoom or move of the note. If the note is
   deleted by someone else, or live editing stops being available,
   close the editor.
8. The item list for keyboard and screen-reader users calls the same
   `handleActivateItem`, so Enter on a row now opens the in-place
   editor too. Update the e2e helpers `openSharedNote` in
   `tests/e2e/collaborative-editing.spec.ts` and
   `tests/e2e/collaboration-replicas.spec.ts` to look for the
   `Editing note` group instead of the `Edit Note` dialog (named
   `Edit note` if IMP-122 landed first). Do not remove any check from
   those tests.
9. Tests:
   - `tests/unit/note-screen-rect.test.ts`: the maths at zoom 1, 0.5
     and 2 with a panned board;
   - `tests/unit/note-inline-editor.test.tsx`: in-place mode for a wide
     NOTE with live editing; dialog for a TEXT item, for a note under
     160px on screen, and when live editing is off; Escape and outside
     click close it; `Tags` opens the dialog; pressing Delete or
     Backspace while typing does not call the delete handler;
   - e2e (extend `collaborative-editing.spec.ts`): two browsers type on
     the same note in place and end with the same text.
</steps>

<acceptance>
- Double-clicking a note at normal zoom shows a text cursor on the
  note; the rest of the board stays visible and no dialog opens.
- Text typed there appears for a second person on the same canvas, as
  it did in the dialog.
- Escape, `Done` or clicking the board ends editing; the note shows the
  new text.
- Zoomed far out (note under 160px wide), for TEXT items, and when live
  editing is unavailable, the old dialog opens as before.
- Tags can still be changed (through `Tags`).
- Backspace, Delete, arrows and Space while typing change only the
  text.
- Enter on a note in the item list opens the same in-place editor.
</acceptance>
