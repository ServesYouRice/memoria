# IMP-035 - Canvas recovery and collaboration UI

<objective>
Canvas users can see and recover from image failures, unsaved/conflicting edits,
and collaboration reconnects while remote committed deltas converge without a
full-canvas polling loop.
</objective>

<context>
Reuse the backend and hook contracts completed by IMP-001,
IMP-007, and IMP-017 under `../archive/2026-08-01/tasks/`. HTTP/Prisma
remains the durable write authority.
</context>

<files>
`src/features/canvas/components/ImageItem.tsx`,
`src/features/canvas/components/CanvasHeader.tsx`,
`src/lib/hooks/use-autosave.ts`, `src/lib/hooks/use-canvas-items.ts`,
`src/lib/hooks/use-collaboration.ts`, `src/stores/canvasStore.ts`, `tests/`.
</files>

<steps>
1. Render a visible filename/icon fallback and retry action when a private image
   fails to load.
2. Expose truthful `saving`, `saved`, `offline/retrying`, `conflict`, and
   `failed` states without labeling rejected optimistic state as durable.
3. Merge versioned committed item events and tombstones into client state;
   recover gaps by bounded cursor replay or an explicit snapshot reload.
4. Cover in-flight edits, retry, navigation, conflicts, remote deletion,
   reconnect/replay, and revocation with focused and two-browser tests.
</steps>

<acceptance>
- Failed images remain identifiable and retryable.
- No rejected or queued delta is presented as saved.
- A second editor observes committed edits and deletions within the declared
  collaboration target.
- Reconnect converges without downloading the full active set on every tick.
</acceptance>

<verification>
Targeted canvas tests; two-browser collaboration scenario; `pnpm type-check`;
`pnpm lint`.
</verification>
