# IMP-045 - Make collaboration transport truthful and bounded

<objective>
Remote cursors are actually visible and remain live under normal pointer use,
revoked clients stop reconnecting, committed events are coalesced, and
long-running WebSocket state has bounded admission and expiry behavior.
</objective>

<files>
`src/features/canvas/components/CanvasBoard.tsx`, cursor UI,
`src/lib/hooks/use-collaboration.ts`, `src/lib/hooks/use-canvas-items.ts`,
`src/lib/collaboration/websocket-server.ts`, collaboration tests and load tests.
</files>

<context>
Confirms Opus LOG-02, LOG-11, LOG-12, PERF-05, PERF-08, and PERF-09. Independent
source tracing found a larger gap: received cursor positions are used only for
follow mode and never rendered as remote pointers. LOG-15 is false because the
polling hook has no caller; LOG-16 is false because ioredis constructs a
reconnecting client when `REDIS_URL` is configured. Authorization refresh must
remain fail-closed after a bounded lease; Opus's unconditional fail-open advice
is rejected.
</context>

<steps>
1. Coalesce client cursor sends to the server tick, give ephemeral cursor frames
   a separate budget, and ensure they cannot close/starve chat or reactions.
2. Render accessible, named remote cursors with stable per-user identity; repeat
   colors must remain distinguishable.
3. Treat policy/revocation close codes and failed upgrades as terminal with a
   visible access message; retain jittered bounded recovery for transient codes.
4. Sweep upgrade budgets, delete rejected empty canvas sets, and add TTL/lease
   expiry for remote presence/cursor entries after instance loss.
5. Batch committed item-event hydration rather than issuing one HTTP read per
   event and maintain O(1) admission counters per user/client.
6. Batch authorization refresh work and define the consecutive-failure/lease
   policy so a database blip avoids a herd without extending revoked access
   indefinitely.
</steps>

<acceptance>
- Sustained pointer movement for more than a minute keeps named remote cursors,
  chat, and reactions functional without exceeding the documented budget.
- Revoked clients stop retrying; transient clients recover with bounded jitter.
- Peer loss removes ghost presence, connection maps remain bounded, and large
  event bursts do not create per-client request explosions.
</acceptance>

<verification>
Fake-timer cursor/budget/reconnect tests; two-instance Redis presence-expiry and
revocation tests; committed-event burst test; WebSocket capacity profile;
`pnpm type-check`; `pnpm lint`.
</verification>
