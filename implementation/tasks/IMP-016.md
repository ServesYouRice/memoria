# IMP-016 — Durable upload lifecycle

<objective>
Upload/database/object deletion is crash-recoverable, quota-safe, and memory
bounded.
</objective>

<files>
`src/lib/uploads/private-storage.ts`, `src/app/api/v1/upload/route.ts`,
`src/app/api/v1/uploads/[assetId]/route.ts`, `prisma/schema.prisma`,
`src/app/api/v1/users/account/route.ts`,
`src/app/api/v1/canvases/[canvasId]/route.ts`.
</files>

<steps>
1. Model pending, active, deleting, deleted, and failed/reconciling lifecycle
   states. Record intent before object work and finalize transactionally where
   possible.
2. Stream uploads to quarantine with byte, media, dimension, and concurrency
   limits; activate only after required validation/scanning.
3. Maintain an authoritative atomic per-user quota counter. Reconcile counters
   and object inventory on a bounded schedule.
4. Enqueue idempotent physical deletion after DB state changes. Map missing
   objects to the correct not-found state.
5. Cover canvas/account deletion and template copy ownership. Keep backups aware
   of lifecycle state.
6. Test crash points, concurrent quota use, duplicate deletes, missing objects,
   maximum-size memory, and reconciliation.
</steps>

<acceptance>
- A crash cannot leave an untracked permanent object or a permanently broken
  active row without reconciliation.
- Concurrent uploads cannot exceed quota.
</acceptance>

<verification>
Real S3-compatible + PostgreSQL integration tests; `pnpm type-check`; `pnpm lint`.
</verification>
