# IMP-060 - Cover ownership enforcement on remaining v1 CRUD routes

<objective>
A signed-in user who does not own a workspace, comment, connection, trashed item,
or notification cannot read, update, or delete it.
</objective>

<files>
`src/app/api/v1/workspaces/route.ts`,
`src/app/api/v1/workspaces/[workspaceId]/route.ts`,
`src/app/api/v1/items/[itemId]/comments/route.ts`,
`src/app/api/v1/items/[itemId]/comments/[commentId]/route.ts`,
`src/app/api/v1/canvases/[canvasId]/connections/route.ts`,
`src/app/api/v1/canvases/[canvasId]/connections/[connectionId]/route.ts`,
`src/app/api/v1/trash/route.ts`, `src/app/api/v1/notifications/route.ts`,
and new tests under `tests/api/`.
</files>

<context>
Plain CRUD routes with no exotic dependencies, none of them referenced by a test.
They are the cheapest remaining coverage in the application and they all share
one invariant, which is why they are grouped.

`AGENTS.md` states that HTTP authorization must hold even where the UI prevents
the action, and that UI capability checks are not a security boundary. These
routes are exactly where that rule is currently unverified.

Scope is ownership only. Do not add validation, pagination, or response-shape
coverage here; if a route turns out to lack an ownership check entirely, that is
a finding to report, not a fix to make inside a test card.
</context>

<steps>
1. For each route and each exported method, assert that a signed-in non-owner
   receives the route's own denial status and that no mutation occurs.
2. Assert the owner path succeeds for the same request, so the denial is proven
   to come from ownership rather than from an unrelated failure.
3. Keep the persona setup in one shared helper, so adding a route later costs one
   table row rather than a new file.
4. Report any route with no ownership check as a security finding with a `DEC-`
   row. Do not add the check under this card.
</steps>

<acceptance>
- Every route and method listed has both a denied non-owner case and an allowed
  owner case.
- A denial is proven by the absence of the write, not only by the status code.
- Any missing ownership check is reported rather than patched.
</acceptance>

<verification>
`pnpm test:file` on the new files; `pnpm test -- --run`; `pnpm lint`;
`pnpm type-check`.
</verification>
