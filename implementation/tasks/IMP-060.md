# IMP-060 - Cover tenant scoping for workspaces, trash, and notifications

<objective>
Workspace, trash, and notification handlers scope every query and mutation to
the authenticated principal, with non-owner/non-recipient requests unable to
return or mutate another user's data.
</objective>

<files>
`src/app/api/v1/workspaces/route.ts`,
`src/app/api/v1/workspaces/[workspaceId]/route.ts`,
`src/app/api/v1/trash/route.ts`, `src/app/api/v1/notifications/route.ts`, and a
new `tests/api/tenant-owned-routes.test.ts`.
</files>

<context>
None of these route modules is imported by an existing test. They all enforce a
strict user boundary: workspaces and trashed items belong to the owning user,
while notifications belong to their recipient.

Comments and connections are deliberately outside this card: shared users may
read or comment according to role, public canvases expose the comment
collection, and canvas shares may read or edit connections. Those capability
matrices live in IMP-065 and IMP-066, with disjoint test files.
</context>

<executor_constraints>
- Import and call the real route exports. Mock auth, Prisma, capacity/mutation
  locks, and cache invalidation at their external boundaries; never mock a route
  or recreate its authorization in a test helper.
- Use exact owner/outsider IDs. Assert query predicates and absent writes, not
  only response statuses.
- Source routes are read-only. If a handler lacks the tenant predicate described
  below, stop and add one `DEC-` row with the observed query or mutation.
- Do not add comment or connection cases; those belong to IMP-065/066.
</executor_constraints>

<steps>
1. Cover workspace collection GET and POST. GET count/findMany must both use
   `{ userId }`; POST must pass the same user to the capacity check and create
   data inside its transaction. Missing auth performs none of that work.
2. Cover workspace item GET, PATCH, and DELETE with missing, outsider-owned, and
   owner-owned rows. An outsider may incur the initial lookup but receives no
   workspace/canvas data and performs no update, canvas unassignment, or delete.
   On owner DELETE, assert both transaction operations retain `workspaceId` and
   `userId` scoping where applicable.
3. Cover trash GET by asserting both list and count predicates require a deleted
   item whose canvas belongs to the current user. For PATCH, a failed
   `requireItemOwnership` performs no transaction; success uses the requested
   version plus `deletedAt: { not: null }`, increments version, and invalidates
   only the returned item's canvas.
4. Cover notification GET and PATCH. All list/count predicates use
   `recipientId: userId`; mark-read uses both the requested IDs and the same
   recipient predicate. Simulate IDs owned by another user with `updateMany`
   returning zero and assert the response cannot imply they were updated.
5. Include one owner/recipient success per method family so denials cannot pass
   merely because the fixture or handler is otherwise invalid.
</steps>

<acceptance>
- Every workspace collection/item, trash, and notification export is exercised
  through its real handler.
- Outsiders receive no tenant data and cause no mutation beyond expected
  authorization/ownership reads.
- Every list/count/update predicate carries the correct `userId` or
  `recipientId` scope.
- Optimistic trash restore retains its owner check, version predicate, and
  deleted-state predicate.
- No production file changed.
</acceptance>

<verification>
`pnpm test:file tests/api/tenant-owned-routes.test.ts`;
`pnpm test -- --run`; `pnpm lint`; `pnpm type-check`.
</verification>
