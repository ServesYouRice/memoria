# IMP-060 - Built-in AI runs on any saved provider, not only OpenAI

<objective>
Tags, summaries, chat, generate and pile sorting use the AI provider and key the owner saves in Settings (Anthropic/Claude, OpenAI, Gemini, OpenRouter or an OpenAI-compatible/local endpoint), with `OPENAI_API_KEY` kept only as a fallback.
</objective>

<files>
`src/lib/ai/service.ts`, `src/lib/agents/providers.ts`, `ModelCredential` in `prisma/schema.prisma`, `src/app/api/v1/ai/*`, `src/app/settings/SettingsContent.tsx`, `src/lib/env.ts`
</files>

<acceptance>
- `generateText` goes through one small provider adapter with OpenAI-compatible and Anthropic Messages implementations (Gemini and OpenRouter through their OpenAI-compatible endpoints); there are no provider checks scattered across routes.
- Settings lets the owner pick a provider, a model and a key; the key is stored encrypted in the existing `ModelCredential` table and is never returned to the browser.
- Lookup order: the user's saved credential first, then server env (`OPENAI_API_KEY`, plus a new `ANTHROPIC_API_KEY`), then a clear "AI not configured" error.
- Existing token, cost and concurrency budgets apply to every provider.
- The suggested Anthropic models in `providers.ts` are current.
</acceptance>

<verification>
`pnpm test -- --run` with unit tests per adapter (mocked HTTP) and for the credential lookup order; `pnpm lint`; `pnpm type-check`; `pnpm build`.
</verification>
