# IMP-125 - Small readability and markup fixes found by the accessibility check

<objective>
The automatic accessibility check (axe) reports no problems on Settings,
Search and the canvas header, and the Trash empty page no longer shouts.
</objective>

<context>
Found in the UI audit of 2026-11-14 with axe-core 4.14 on the running app.
Exact findings:
1. Text too faint. The green "Live" label in the canvas header (11px text)
   has contrast 4.47:1 in the light theme and about 3:1 in the dark theme.
   The rule for small text is at least 4.5:1 (WCAG 1.4.3).
2. Text too faint. On Settings -> Account, the helper text under the
   locked email field ("Your email address cannot be changed.") is #9e9e9e
   on white: 2.67:1.
3. List markup. MUI `ListItemButton` links sit directly inside a `List`
   (`<ul>` with `<a>` children) in the Settings menu
   (`SettingsNav`) and in the search results list.
4. List markup. `ListItem` (`<li>`) is used without a `List` parent in
   `WeeklyRecapSettings.tsx` (2), `AutoFileSettings.tsx` (1) and
   `LinkEnrichmentSettings.tsx` (2).
5. The Trash page, when empty, shows a large filled blue button "Back to
   the dashboard". A filled button is for the page's main action; leaving
   the page is not it.
6. The Trash page stretches its rows across the whole screen
   (`<AppShell>` in `src/app/trash/page.tsx`). Its sibling list pages
   (Notifications, Reminders, Search, Weekly recap) use
   `<AppShell readingWidth="md">`, so Trash is the odd one out.
</context>

<executor_constraints>

- Do not change brand colours in `src/lib/theme.ts` for the whole app;
  fix the specific elements.
</executor_constraints>

<steps>
1. "Live" label: make its text at least 4.5:1 against its own background
   in both themes. Simplest way: keep the chip's tinted background and set
   the label colour to `success.dark` in light mode and `success.light` in
   dark mode (use `theme.palette.mode` or the `appColor` helper already
   used in this file), and raise the font size from 11 to 12. Check the
   other status labels in `statusConfig` (Connecting, Reconnecting,
   Offline) the same way.
2. Email helper text: the field is read-only, not broken. Replace
   `disabled` on the email `TextField` with
   `slotProps={{ htmlInput: { readOnly: true } }}` so MUI stops greying the
   helper text, and keep the helper text. If a test relies on `disabled`,
   update it to check `readOnly`.
3. Settings menu and search results: wrap each `ListItemButton` in
   `<ListItem disablePadding>` so every child of the list is an `<li>`.
4. In `WeeklyRecapSettings.tsx`, `AutoFileSettings.tsx` and
   `LinkEnrichmentSettings.tsx` add `component="div"` to each `ListItem`
   that has no `List` parent.
5. Trash empty state: change the "Back to the dashboard" button from
   `variant="contained"` to `variant="text"`.
6. Trash page width: in `src/app/trash/page.tsx` change `<AppShell>` to
   `<AppShell readingWidth="md">`, the same as
   `src/app/reminders/page.tsx`.
7. Add `tests/unit/settings-list-markup.test.tsx`: render `SettingsNav`'s
   parent or the three small settings components and assert that no `<li>`
   is rendered outside a `<ul>`/`<ol>` and no `<ul>` has a direct child
   that is not an `<li>`. Mock network hooks the way neighbouring settings
   tests do.
</steps>

<acceptance>
- "Live" (and the other status labels) measure at least 4.5:1 in light and
  dark themes. State the measured ratios in the commit message.
- The email helper text measures at least 4.5:1.
- No `<ul>` on `/settings/*` or `/search` has a direct child other than
  `<li>`; no `<li>` lacks a list parent.
- The Trash empty page has no filled button.
- On a wide screen the Trash list is as wide as the Reminders list.
</acceptance>
