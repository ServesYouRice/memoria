# IMP-124 - Settings tidy-up: password field, headings, shortcuts

<objective>
Three small Settings annoyances are gone: the password form asks for the
new password once (with a show/hide eye), no heading is repeated, and
keyboard shortcuts have their own entry instead of hiding under Appearance.
</objective>

<context>
Found in the UI audit of 2026-11-14.
- "Change password" asks for the new password twice and has no way to see
  what was typed. The sign-in form already has a show/hide eye. Rule used
  (GOV.UK password pattern): one field plus show/hide, no "type it again".
- Settings -> Notifications shows the heading "Notifications" and directly
  under it a card also titled "Notifications".
- Keyboard shortcuts are listed under "Appearance", where nobody looks.
</context>

<files>
`src/app/settings/SettingsContent.tsx` (password form near "Change
password"; `AppearanceGroup`; `NotificationsGroup`),
`src/app/settings/sections.ts`,
`src/features/auth/components/LoginForm.tsx` (copy the show/hide pattern,
do not edit), `tests/unit/` and `tests/e2e/` files that mention settings.
</files>

<executor_constraints>
- Do not change the password rules or the API call that saves a password.
- Keep every existing settings address working (`/settings`,
  `/settings/security`, `/settings/appearance`, ...).
- Keep `aria-current="page"` on the selected settings entry.
</executor_constraints>

<steps>
Part A - password form (`SettingsContent.tsx`, section "Change password")
1. Remove the "Confirm new password" field, the `confirmPassword` state,
   and the "Passwords do not match" checks and messages.
2. The Save button is disabled only while `currentPassword` or
   `newPassword` is empty, or while saving.
3. Add a show/hide eye button to "Current password" and to "New password".
   Copy the pattern from `LoginForm.tsx` (`showPassword` state,
   `Visibility` / `VisibilityOff` icons, `aria-label` "Show password" /
   "Hide password"). Each field has its own state.
4. Keep the helper text `Minimum 10 characters` on "New password".

Part B - repeated heading
5. In `NotificationsGroup`, change the section `title` from
   `Notifications` to `What Memoria tells you about`. Keep
   `id="notifications"` so old links still land there.

Part C - shortcuts get their own entry
6. In `src/app/settings/sections.ts` add this entry directly after the
   `appearance` entry:
   `{ id: "shortcuts", path: "/settings/shortcuts", label: "Keyboard
   shortcuts", intro: "The keys that make common actions faster." }`
7. In the same file change the `appearance` intro to
   `Choose light or dark.`
8. In `SettingsContent.tsx` move the whole "Keyboard shortcuts"
   `SettingsSection` out of `AppearanceGroup` into a new component
   `ShortcutsGroup`, set that section's `title` to `Shortcut list`, and
   render it with `{section === "shortcuts" && <ShortcutsGroup />}` next
   to the other groups.
9. Search `tests/` for `Confirm new password`, `Passwords do not match`,
   `see the keyboard shortcuts` and for tests that count the settings
   sections (`grep -rn "SETTINGS_SECTIONS" tests`). Update them to the new
   behaviour: one more section than before, with shortcuts at
   `/settings/shortcuts`.
</steps>

<acceptance>
- "Change password" has exactly two fields: "Current password" and "New
  password". Each has a working show/hide button with an `aria-label`.
- Changing a password with a valid current and new password still works.
- `/settings/notifications` shows the word "Notifications" as a heading
  once.
- `/settings/shortcuts` shows the shortcut list; `/settings/appearance`
  no longer shows it; the Settings menu lists "Keyboard shortcuts" after
  "Appearance".
</acceptance>
