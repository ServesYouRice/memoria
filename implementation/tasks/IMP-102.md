# IMP-102 - Setting up your own AI key is easy

<objective>
Someone who has never used an AI key can switch AI on in a few minutes and
knows straight away whether it works.
</objective>

<context>
Approved by the owner on 2026-11-11: AI on your own key suits people who
host their own tools but is a hurdle for everyone else, so the set-up has
to be very easy. `AiProviderSettings.tsx` shows provider, model, address
and key fields with a save button. A saved key is stored as unverified
(`/api/v1/ai/provider`), so a wrong key is only discovered later, when a
feature fails and the chip reads "Saved key was rejected".
</context>

<files>
`src/app/settings/AiProviderSettings.tsx`,
`src/app/api/v1/ai/provider/route.ts`,
`src/lib/ai/provider-resolution.ts`, `tests/api/ai-routes.test.ts`.
</files>

<executor_constraints>
The key stays write-only and is never logged or shown again. The check of
a custom address keeps the existing safety test. The trial request is tiny
and counts against the same budgets as any other AI request.
</executor_constraints>

<acceptance>
- The set-up is three plain steps: pick a provider, get a key (with a link
  to that provider's own key page), paste it.
- Saving tests the key with one small request and says in plain words
  whether it works or what is wrong: wrong key, no credit, wrong address,
  or model not available.
- The page states clearly whether AI is on and what it is used for.
- Where a feature needs AI and none is set up, the message links to this
  set-up.
</acceptance>

<verification>
`pnpm test:file tests/api/ai-routes.test.ts` and the new tests;
`pnpm gate fast`.
</verification>
