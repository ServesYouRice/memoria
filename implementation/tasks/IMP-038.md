# IMP-038 - Production browser and operations gate

<objective>
The remaining launch journeys run against a production build and real services,
and the production operations smoke proves the candidate starts and exposes only
the intended health surface.
</objective>

<context>
Blocked on the four client-completion cards IMP-034 through IMP-037.
The real-PostgreSQL foundation from IMP-019 and edge controls from IMP-028 are
archived under `../archive/2026-08-01/tasks/`.
</context>

<files>

`.github/workflows/ci.yml`, `docker-compose.yml`, `scripts/smoke.mjs`,
`scripts/lib/smoke.mjs`, `package.json`.
</files>

<steps>
1. Run Playwright against the production build with PostgreSQL, Redis,
   S3-compatible storage, and captured test email.
2. Cover password reset, session revocation, upload/private-image recovery,
   sharing and public-link revocation, canvas recovery, export, and account
   deletion in addition to the auth and collaboration scenarios owned by the
   prerequisite cards.
3. Wire deterministic seed/cleanup, retained failure artifacts, and the complete
   browser suite into CI without replacing real-service claims with mocks.
4. Run the production smoke for liveness, protected readiness/metrics, headers,
   migrations, worker lifecycle, and representative durable traffic.
</steps>

<acceptance>
- Production-only auth and client behavior is exercised in CI.
- The suite fails on real constraint, cascade, transaction, storage, or session
  regressions relevant to the covered journeys.
- A green smoke proves the candidate image booted, ran migrations separately,
  served traffic, and did not disclose protected readiness or metrics.
</acceptance>

<verification>
`pnpm test -- --run`; real-PostgreSQL integration suite;
`pnpm test:e2e`; `pnpm type-check`; `pnpm lint`; `pnpm build`; `pnpm smoke`.
