# IMP-015 — Durable email and webhook delivery

<objective>
Verification email and approved external actions use the outbox; v1 webhooks
follow DEC-002.
</objective>

<steps>
1. Enqueue verification email in the registration/token transaction. Expose a
   truthful queued state; retries must not create duplicate active tokens.
2. For webhooks, either gate external execution off or enqueue a minimized,
   signed delivery intent in the action transaction.
3. Send idempotency/delivery IDs, persist response class and attempt metadata,
   and retry only retryable failures. Define terminal success semantics.
4. Add operator replay/cancel visibility without exposing secrets or bodies.
5. Test worker restart, duplicate delivery, timeout, 4xx/5xx, signature,
   registration recovery, and redaction.
</steps>

<acceptance>
- A committed registration always has a durable delivery intent.
- A committed external action is either gated off or durably deliverable.
</acceptance>

<verification>
Real-DB outbox/email/webhook tests; `pnpm type-check`; `pnpm lint`.
</verification>
