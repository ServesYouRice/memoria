# IMP-137 - Each canvas card has a "..." menu: rename, duplicate, move, delete

<objective>
Every canvas card on the dashboard has a "..." button that opens a menu
with Rename, Duplicate, Move to workspace and Delete. This is the first
place in the app where an existing canvas can be moved into a workspace.
</objective>

<context>
Found in the UI audit of 2026-11-14 (two findings):
- Rename and delete are hidden. A card only shows a Duplicate icon.
  Renaming needs the canvas to be opened; deleting needs "Select" mode.
- A canvas you already have cannot be moved into a workspace. You can
  create a workspace and start a new canvas inside it, nothing more.
  The server already supports the move: `PATCH /api/v1/canvases/[id]`
  accepts `workspaceId` (a workspace id, or `null` for none) and checks
  that the workspace belongs to the caller. The hook
  `useAssignCanvasToWorkspace` in `src/lib/hooks/use-workspaces.ts`
  already calls it and is used nowhere.
</context>

<files>
`src/features/dashboard/components/DashboardContent.tsx` (the `corner`
prop of `CanvasCard`, `handleDuplicate`, the delete dialog),
`src/features/dashboard/components/CanvasCard.tsx`,
`src/lib/hooks/use-canvases.ts` (`useUpdateCanvas`),
`src/lib/hooks/use-workspaces.ts` (`useWorkspaces`,
`useAssignCanvasToWorkspace`), new
`src/features/dashboard/components/CanvasCardMenu.tsx`,
`tests/unit/dashboard-selection-scope.test.tsx`,
`tests/unit/dashboard-bulk-delete.test.tsx`.
</files>

<executor_constraints>
- No server changes. Use the existing routes and hooks.
- The card itself is a link (`href`). Clicking the "..." button or a
  menu entry must not open the canvas: call `event.preventDefault()`
  and `event.stopPropagation()` on those clicks.
- In selection mode the corner stays a checkbox, as today.
- Do not add this menu to "Shared with me" cards: those canvases belong
  to someone else.
- The "..." button is at least 44x44px on touch screens
  (`TOUCH_TARGET` in `src/lib/theme.ts`).
</executor_constraints>

<steps>
1. Create `CanvasCardMenu.tsx`: an icon button (`MoreHoriz` icon,
   `aria-label` = `Options for <canvas name>`, `aria-haspopup="menu"`)
   that opens a MUI `Menu` with these entries, in this order:
   `Rename`, `Duplicate`, `Move to workspace`, a divider, `Delete`.
   Props: the canvas (`id`, `name`, `workspaceId`) and the callbacks
   `onRename`, `onDuplicate`, `onMove(workspaceId | null)`, `onDelete`.
2. In `DashboardContent.tsx` replace the Duplicate icon button in
   `corner` with `<CanvasCardMenu>`. `Duplicate` calls the existing
   `handleDuplicate`.
3. `Rename` opens a small dialog titled `Rename canvas` with one field
   `Name` (starts with the current name, selected; required; at most
   255 characters) and buttons `Cancel` and `Save`. Save calls
   `useUpdateCanvas().mutateAsync({ canvasId, data: { name } })`, closes
   the dialog and shows the toast `Renamed`. Enter saves; an empty name
   shows `Enter a name`.
4. `Move to workspace` opens a second list (a nested menu or a small
   dialog titled `Move to workspace`; a dialog is fine and is easier on
   phones) with:
   - `No workspace` first;
   - one row per workspace from `useWorkspaces()`, by name;
   - a tick on the row where the canvas is now.
   Picking a row calls
   `useAssignCanvasToWorkspace().mutateAsync({ canvasId, workspaceId })`
   (`null` for `No workspace`), then shows `Moved to <workspace name>`
   or `Removed from workspace`. On failure show the error text.
   When the person has no workspaces, show the line `You have no
   workspaces yet.` and a link `Create a workspace` to `/workspaces`.
5. Make sure the canvas lists refresh after a move: after success
   invalidate the `canvasKeys.list()` queries (add this to the hook's
   `onSuccess` if it only refreshes workspace queries today).
6. `Delete` opens the same confirmation dialog that multi-select uses,
   for this one canvas (set the selection to just this canvas id, or
   pass the ids to the dialog). Do not write a second dialog. If
   IMP-133 has already landed (the dialog says "Move to Trash"), label
   this entry `Move to Trash`; otherwise label it `Delete`.
7. Tests: add `tests/unit/canvas-card-menu.test.tsx`:
   - the menu lists the four entries in order;
   - clicking "..." does not follow the card link;
   - Rename sends the new name;
   - Move sends the chosen `workspaceId`, and `null` for `No workspace`;
   - Delete opens the confirmation for exactly that canvas.
   Update dashboard tests that looked for the `Duplicate <name>` button.
</steps>

<acceptance>
- Every dashboard card shows "..."; its menu reads Rename, Duplicate,
  Move to workspace, Delete (or Move to Trash).
- A canvas moved to workspace "Work" appears at
  `/dashboard?workspace=<Work id>` without a reload, and the tick in
  the move list follows it.
- Rename changes the card title without opening the canvas.
- Keyboard: Tab reaches "...", Enter opens the menu, arrow keys move,
  Escape closes and returns focus to "...".
- "Shared with me" cards are unchanged.
</acceptance>
