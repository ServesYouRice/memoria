# IMP-042 - Make self-host configuration enforceable

<objective>
A clean self-host install generates every security-sensitive secret, passes
every supported operator setting to the right process, and ships one tested
HTTPS/WSS proxy topology with explicit body and operations-route policy.
</objective>

<files>
`.env.example`, `src/lib/env.ts`, `scripts/setup.mjs`, `scripts/doctor.mjs`,
`docker-compose.yml`, supported ingress configuration, deployment docs and
clean-install tests.
</files>

<context>
Promotes Codex SEC-01, DEP-01, DEP-02, and MAINT-01, which Opus missed. Current
setup preserves repository-known `INTERNAL_OPERATIONS_TOKEN` and
`BACKUP_MANIFEST_HMAC_KEY`; Compose drops `REGISTRATION_MODE`,
`TRUSTED_PROXY_CIDRS`, and `AUTH_RATE_LIMIT_MAX_REQUESTS`, and its `PORT`
contract disagrees with the fixed container port.
</context>

<steps>
1. Generate independent operations, backup-HMAC, and recovery-profile secrets;
   reject known placeholders in runtime validation and doctor, with a rotation
   runbook for existing installs.
2. Establish one typed configuration registry or exhaustive assertions covering
   template, setup, doctor, app, worker, scheduler, and Compose pass-through.
3. Separate host port from the fixed container port and prove all registration,
   proxy, rate, upload, email, storage, and operations settings inside the
   running services.
4. Add one supported TLS reverse proxy with WebSocket upgrade, trusted-forwarded
   address policy, JSON/multipart body caps, timeouts, and protected operations
   routing.
5. Make setup verify the public HTTPS/WSS path before declaring completion.
</steps>

<acceptance>
- No repository-known secret authenticates or validates a fresh production
  install, and every supported setting has one tested path to its consumer.
- Registration modes and per-client rate identity work through the reference
  proxy; oversized bodies are rejected before Next.js parsing.
- The reference deployment is reachable through documented HTTPS/WSS without
  exposing protected operations details.
</acceptance>

<verification>
Clean-install secret test; `docker compose config` assertions; proxy/auth/body
limit production E2E; documentation assertions added by this card;
`pnpm type-check`; `pnpm lint`.
</verification>
