# IMP-042 - Real co-editing with Yjs and a Hocuspocus sync server

<objective>
Several people edit the same canvas and note text at once, changes merge
without loss, and every document update is persisted by a dedicated sync
server.
</objective>

<context>
Handbook target: Yjs documents, a Hocuspocus sync server as its own process
from the same image (like the worker and scheduler), TipTap's Yjs collaboration
extension for note text. Offline editing and snapshot-based version history
follow from the same model. Durable writes must stay authorized and validated
server-side: the sync server checks canvas access on connect and on a refresh
interval, rejects updates from view/comment roles, and validates decoded item
shapes with the existing Zod schemas before persisting. The current presence
socket and HTTP item routes keep working during rollout.
</context>

<files>
`server.ts`, `src/lib/collaboration/`, `src/features/canvas/`,
`prisma/schema.prisma`, `docker-compose.yml`, `Dockerfile`, `ARCHITECTURE.md`.
</files>

<steps>
1. Design the document shape (one Y.Doc per canvas; items and rich text) and
   the mapping to `CanvasItem` rows used by search, export, agents and the
   accessible item list.
2. Add the sync server entry point with auth, role checks, update validation,
   PostgreSQL persistence, and a health endpoint.
3. Wire the client canvas and TipTap editor to the shared document; keep
   version snapshots from Yjs state.
4. Migrate existing canvases into documents and keep `CanvasItem` rows in step.
</steps>

<acceptance>
- Two browsers editing the same item and the same note text converge.
- A viewer cannot change the document; revoked access disconnects.
- Restarting the sync server loses no acknowledged edit.
- Exports, agents, and the HTTP API see the same state as the canvas.
</acceptance>
