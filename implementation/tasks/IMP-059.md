# IMP-059 - Firefox and WebKit pass `pnpm gate e2e`

<objective>
The E2E gate passes on all three Playwright projects, not only Chromium, so
cards whose verification names `pnpm gate e2e` can close.
</objective>

<context>
The first all-browser run (2026-11-02) failed 13 Firefox/WebKit specs. Two
causes are fixed: the shared auth rate limit in `docker-compose.e2e.yml`
ran out before WebKit started, and the embed spec asserted Chromium-only
framing errors and a Chromium-only permission. Five failures remain:

- Firefox `embeds.spec.ts`: test timeout (60s); the stuck step is not yet
  identified (the trace shows the owner page on the dashboard).
- WebKit `auth-recovery.spec.ts`: the forgot-password email field is empty
  ("Invalid email address") right after `fill`; likely hydration resetting
  the controlled input. Check whether real Safari users can lose input too.
- WebKit `offline-editing.spec.ts`: the reload while offline renders a
  blank page; check Playwright WebKit service-worker support first.
- WebKit `sign-in-security.spec.ts`: test timeout on the settings page
  while turning on two-factor.
</context>

<files>
`tests/e2e/`, `playwright.config.ts`, `docker-compose.e2e.yml`,
`src/app/auth/forgot-password/page.tsx`
</files>

<acceptance>
- `pnpm gate e2e` passes. A spec may skip a browser only when the browser or
  Playwright cannot run the scenario; the skip names the reason.
- App bugs found on the way are fixed, not skipped.
</acceptance>

<verification>
`pnpm gate e2e`.
</verification>
