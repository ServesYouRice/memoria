# IMP-059 - Cover agent request authentication and credential modes

<objective>
The agent API's actual credential modes are regression-covered: ordinary agent
routes accept an authorized user session or active integration token, management
routes reject integration actors, ingest requires an integration actor, and MCP
authenticates tool execution without blocking its public protocol handshake.
</objective>

<files>
`src/lib/agents/auth.ts`, `src/app/api/agent/v1/actions/route.ts`,
`src/app/api/agent/v1/canvases/route.ts`, `src/app/api/agent/v1/items/route.ts`,
`src/app/api/agent/v1/knowledge/route.ts`, `src/app/api/agent/v1/mcp/route.ts`,
`src/app/api/agent/v1/providers/route.ts`,
`src/app/api/agent/v1/integrations/route.ts`,
`src/app/api/agent/v1/integrations/ingest/route.ts`, a new
`tests/unit/agent-auth.test.ts`, and a new
`tests/api/agent-route-auth.test.ts`.
</files>

<context>
None of the eight route modules or `resolveAgentRequestContext` is imported by
an existing test. These routes use user sessions or `mat_` integration tokens
from `src/lib/agents/auth.ts`; they do not consume `x-api-key`. Integration
accounts have active/inactive status rather than an expiry field.

MCP also has a deliberate exception: `initialize`, `notifications/initialized`,
`ping`, and `tools/list` do not resolve an actor, while `tools/call` does. Tests
must preserve that protocol split rather than force every MCP message to 401.
</context>

<executor_constraints>
- Unit-test the real `resolveAgentRequestContext` with mocked Prisma,
  `getCachedSession`, and Argon2. Route tests may mock that helper to isolate
  whether each real handler invokes it before its own data/service work.
- Use valid minimal query/body fixtures so an unrelated parser does not reject
  a request before the authentication boundary under test.
- Authorization lookups and best-effort `lastSeenAt` writes are expected in the
  helper suite. In route tests, assert against each handler's downstream models
  and services rather than the entire Prisma client.
- Do not invent token expiry, `x-api-key` support, or a requirement that public
  MCP discovery methods authenticate.
- Treat production files as read-only. Stop and add one exact `DEC-` row if a
  route reaches protected work without its documented actor context.
</executor_constraints>

<steps>
1. Cover integration-token resolution through the real helper. Assert Bearer
   and `x-agent-token` extraction; prefix/suffix plus active integration/profile
   predicates; no session fallback when a supplied token is invalid; Argon2
   false/invalid-hash rejection; and the returned integration actor context for
   a verified token. With no session, an `x-api-key` header alone must not
   become an agent credential.
2. Cover session resolution: a missing session is unauthorized; an unrequested
   profile yields a user context with `agentProfile: null`; a requested profile
   is owner-scoped through `getOwnedAgentProfile`; and
   `requireAgentProfile: true` rejects its absence. Prove
   `allowUserSession: false` rejects a valid session instead of using it for
   ingest.
3. Table-test the actual protected method exports with real handlers and a
   rejecting mocked resolver: actions GET/POST, canvases GET, items GET/POST,
   knowledge GET/POST, providers GET/POST, integrations GET/POST, and ingest
   POST. Assert the expected error contract and zero route-specific reads,
   writes, encryption, or service calls.
4. Cover the credential-mode branches with a minimal success-shaped context:
   providers and integrations reject `actorType: "integration"` before their
   list/create work; ingest calls the resolver with
   `{ allowUserSession: false, requireAgentProfile: true }`; and ordinary routes
   pass the resolved `userId`/profile to their first scoped operation. One
   representative route success per mode is sufficient; business behavior is
   outside this card.
5. Call the real MCP POST with `initialize`, `notifications/initialized`,
   `ping`, and `tools/list`, proving none resolves an actor. Then call
   `tools/call` with a valid minimal JSON-RPC envelope and make the resolver
   reject; assert the JSON-RPC unauthorized error code and zero tool execution.
</steps>

<acceptance>
- All 13 HTTP method exports are represented through real handlers: the 12
  route-level cases in step 3 plus MCP POST's public/protected split in step 5.
- Active integration/account predicates and Argon2 verification are asserted
  against the credential contract actually used by these routes.
- User-only management routes and integration-only ingest cannot swap actor
  modes.
- MCP discovery remains public while `tools/call` cannot execute without a
  resolved actor.
- Rejection is proven by absent protected work, not only an HTTP status.
- No production file changed.
</acceptance>
