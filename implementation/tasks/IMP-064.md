# IMP-064 - Cover AI route authorization and request boundaries

<objective>
Every shipped AI POST route rejects missing sessions and invalid bounded input
before database or provider work, and the canvas-scoped routes prove ownership
before invoking AI services.
</objective>

<files>
`src/app/api/ai/generate/route.ts`, `src/app/api/v1/ai/chat/route.ts`,
`src/app/api/v1/ai/generate/route.ts`,
`src/app/api/v1/ai/serendipity/route.ts`,
`src/app/api/v1/ai/summarize/route.ts`, `src/app/api/v1/ai/tags/route.ts`,
`src/lib/validation/ai.ts`, and a new `tests/api/ai-routes.test.ts`.
</files>

<context>
None of the six AI route modules is imported by a unit, API, or integration
test. Five contain implementations; `/api/ai/generate` is a
compatibility re-export of `/api/v1/ai/generate`.

All implementations use `withAuthValidation`. Generate, chat, and tags call the
AI service directly after validation. Summarize and serendipity also read a
canvas and must reject a non-owner before calling their AI service.

Scope is the current HTTP boundary only. IMP-048 owns the operator capability
switch, token/cost/concurrency budgets, provider policy, and any production
changes. Do not invent those contracts here and do not mark IMP-048 complete
from these tests.
</context>

<executor_constraints>
- Call each real exported POST handler. Mock session-cache/auth dependencies,
  Prisma, and AI service functions; do not mock `withAuthValidation`, the route
  module, or the Zod schemas.
- No test may call an external model, network endpoint, Redis, or PostgreSQL.
- Use one table for repeated unauthenticated and invalid-body invariants, with a
  valid fixture named for each route.
- Assert that rejected requests make zero provider calls and, where applicable,
  zero canvas queries.
- If any route reaches a provider without a session, accepts input outside the
  declared schema bounds, or lets a non-owner reach a provider, stop and add one
  `DEC-` row. Do not fix production code under this card.
</executor_constraints>

<steps>
1. Build valid fixtures directly from the declared schemas: generate prompt;
   chat message plus one of the three personas; tag content; and CUID canvas IDs
   for summarize/serendipity. Keep the fixtures small and deterministic.
2. Table-test all five v1 implementations with no cached session. Assert 401
   and no AI service or Prisma call. Exercise the compatibility generate route
   once and prove it preserves the same unauthenticated contract.
3. Table-test invalid input before provider work: empty and over-5,000-character
   prompt/message/content, over-4,000-character system text, temperature outside
   0..2, invalid persona, over-20,000-character context, malformed canvas ID,
   more than 20 keywords, and a keyword over 100 characters. Each case must
   return the validation status and make zero provider calls.
4. Cover one valid generate, chat, and tag request each. Assert the service is
   called with the parsed fields and the response envelope is exactly
   `{ result }` or `{ tags }` as applicable.
5. Cover summarize with missing canvas, another user's canvas, and an owned
   canvas. The first two cases must not call `summarizeCanvas`; for the owner
   case, assert the Prisma query requests only non-deleted items, the service
   receives the items returned by that query, and the route returns
   `{ summary }`.
6. Cover serendipity with a denied canvas and an owned canvas. Denial must occur
   before `findSerendipitousItems`; the owner call must receive the session user,
   canvas ID, bounded keywords, and optional email and return `{ results }`.
</steps>

<acceptance>
- Every AI route module is imported by the suite, including the compatibility
  re-export.
- Missing sessions and invalid input never reach Prisma or an AI service.
- Summarize and serendipity prove ownership before provider work.
- Valid route responses match their explicit envelopes.
- Tests are hermetic and no production file changed.
- AI budget/capability work remains owned by IMP-048.
</acceptance>
