# IMP-130 - "Organised list" shows a real list of the canvas items

<objective>
The canvas tab "Organised list" shows every item on the canvas as a list
that can be filtered and sorted. The AI organiser screen that is there
today moves below it, closed by default, and its headline text is in
plain words.
</objective>

<context>
Found in the UI audit of 2026-11-14 (the top problem). The tab's own
tooltip says "See every item as a list you can sort, filter and use by
keyboard". What opens instead is `CanvasOrganizerView`: a banner
"Organizer Lens - Derived structure, not live mutation" and counters such
as "Derived entities 0" and "Audited change sets 0". There is no list.
A real list already exists: `CanvasItemListView` (rows with Edit and
Delete buttons, full keyboard support). Today it is only rendered inside
`CanvasAccessiblePanel`, which is hidden until a screen-reader or
keyboard user opens it.
How the tab is wired: `CanvasBoard.tsx` holds
`viewMode: "manual" | "organizer"`. `"manual"` is "Free layout".
`"organizer"` is "Organised list" and renders `<CanvasOrganizerView>`.
Rule used: a label must match what opens, in words people use.
</context>

<files>
`src/features/canvas/components/CanvasBoard.tsx` (the block
`viewMode === "organizer" ? (<CanvasOrganizerView ...`; and the
`<CanvasAccessiblePanel ...>` call just above it, which shows which
handlers to pass), `src/features/canvas/components/CanvasItemListView.tsx`
(`CanvasItemListViewProps`, `describeItemHeading`, `describeItemDetail`),
`src/features/canvas/components/CanvasOrganizerView.tsx` (banner near
"Organizer Lens"; counters near `label: "Manual items"`),
`src/types/canvas.ts` (`CanvasItem`, `ItemType`),
`tests/unit/canvas-item-list-row-buttons.test.tsx` (test pattern),
`tests/unit/canvas-organizer-view-*.test.tsx`.
</files>

<executor_constraints>
- Do not change `CanvasItemListView`'s keyboard behaviour or its props
  that already exist. You may add optional props.
- Do not remove `CanvasAccessiblePanel`; it stays for "Free layout".
- Do not change any API call, permission check or the data
  `CanvasOrganizerView` loads. Inside that file change text only.
- Filtering and sorting happen in the browser on the items already
  loaded (`allItems`). Do not add an API parameter.
- Keep the internal value `"organizer"`; only what it shows changes.
</executor_constraints>

<steps>
1. Create `src/features/canvas/components/CanvasOrganisedList.tsx`. Props:
   everything `CanvasItemListViewProps` has, plus `canvasId: string` and
   `itemCount: number`. It renders, top to bottom:
   a. A row of controls:
      - a text field labelled `Filter items`. Typing keeps only items
        whose `describeItemHeading(item)` or tags contain the typed text
        (ignore upper/lower case);
      - a select labelled `Type` with `All types` plus one option for
        each item type that is present in the list (use the same type
        names the list rows already show);
      - a select labelled `Sort by` with: `Recently updated` (default,
        `updatedAt` newest first), `Oldest first` (`createdAt` oldest
        first), `Name A to Z` (by `describeItemHeading`), `Type`.
      - a line of text `Showing X of Y items` with `role="status"`.
   b. `<CanvasItemListView>` with the filtered and sorted items and all
      the handlers passed through unchanged.
   c. When the filter leaves nothing: the text `No items match.` and a
      button `Clear filter`.
   d. A MUI `Accordion`, closed by default, with the summary text
      `AI organiser`. Inside it render
      `<CanvasOrganizerView canvasId={canvasId} items={items}
      itemCount={itemCount} />` (the unfiltered items).
2. In `CanvasBoard.tsx` replace `<CanvasOrganizerView .../>` in the
   `viewMode === "organizer"` branch with `<CanvasOrganisedList>`. Pass
   `items={allItems}`, `itemCount={totalItemCount}`, `canvasId`, and the
   same `capabilities`, `selectedItemIds`, `onSelectItem`,
   `onActivateItem`, `onNudgeItem`, `onDeleteItem`, `onCreateItem`,
   `canvasName` values that `<CanvasAccessiblePanel>` receives a few
   lines above.
3. The list area scrolls on its own (`overflow: auto`, `flexGrow: 1`) and
   has side padding, so long lists do not push the header away.
4. Plain words inside `CanvasOrganizerView.tsx` (Old -> New):
   - `Organizer Lens` -> `AI organiser`
   - `Derived structure, not live mutation` -> `What AI has worked out
     about this canvas`
   - the paragraph starting `This tab is the agent-organized view` ->
     `A read-only summary made by AI helpers. Your notes are not changed
     here. Approve or undo AI changes in Settings, under AI assistant.`
   - button `Open agent console` -> `Open AI settings`
   - counters: `Manual items` -> `Your items`; `Derived entities` ->
     `Things AI found`; `Derived relations` -> `Links AI found`;
     `Open suggestions` -> `Suggestions waiting`; `Audited change sets`
     -> `AI changes made`
   - section titles: `Derived entities` -> `Things AI found`;
     `Derived relations` -> `Links AI found`; `Proposal queue` ->
     `Suggestions waiting`; `Audited writes` -> `AI changes made`
   - the sentence starting `Stable semantic records connected back to
     source items` -> `Each one links back to the notes it came from.`
5. Tests:
   - add `tests/unit/canvas-organised-list.test.tsx` covering: all items
     listed by default; typing in "Filter items" narrows the list and
     updates "Showing X of Y items"; each "Sort by" option orders rows as
     described; "Clear filter" restores the list; the "AI organiser"
     accordion is closed at first;
   - update `tests/unit/canvas-organizer-view-*.test.tsx` and any other
     test that looks for the old words in step 4.
</steps>

<acceptance>
- Opening "Organised list" on a canvas with 7 items shows 7 rows without
  any further click, on desktop and at 390px wide.
- Filter, type and sort work as described in step 1a and never call the
  server.
- Pressing Enter on a row or its Edit button opens the item for editing;
  Delete moves it to Trash (same as before in the hidden list).
- The AI organiser content is still reachable by opening the "AI
  organiser" accordion.
- None of these strings remain on screen: `Organizer Lens`, `Derived
  structure, not live mutation`, `Derived entities`, `Audited change
  sets`, `Proposal queue`, `Audited writes`.
- A read-only viewer sees the list but no Edit or Delete buttons (this is
  already how `capabilities` works; do not weaken it).
</acceptance>
