# IMP-138 - Activity names the canvas, groups repeats and stays small

<objective>
The dashboard's activity box says which canvas each line is about,
joins repeated lines into one ("added 7 items to Lisbon weekend"), and
shows five lines with a button for the rest.
</objective>

<context>
Found in the UI audit of 2026-11-14. Today the box "Recent Activity"
takes about a quarter of the dashboard and repeats
"added an item to a canvas" many times.
Why the canvas name is missing: `getActivityMessage` in
`activity-utils.tsx` prints the stored `canvasName`, or "a canvas" when
it is empty. `logActivity` accepts `canvasName`, but the item routes do
not pass it:
- `src/app/api/v1/canvas-items/route.ts` (`ITEM_CREATED`)
- `src/app/api/v1/canvas-items/[itemId]/route.ts` (`ITEM_UPDATED` and
  `ITEM_DELETED`)
- `src/lib/ai/pile-transform.ts`
Rows already stored have no name, so the list API must fill it in too.
</context>

<files>
`src/app/api/v1/activities/route.ts`, `src/lib/activity.ts`, the three
files named above,
`src/features/dashboard/components/activity-utils.tsx`,
`src/features/dashboard/components/ActivityFeed.tsx`,
`src/features/dashboard/components/DashboardContent.tsx`
(`<ActivityFeed limit={15} ...>`), `src/lib/hooks/use-activities.ts`,
`tests/unit/dashboard-activity-feed.test.tsx`.
</files>

<executor_constraints>
- No schema change. `Activity.canvasName` already exists.
- The activities route must keep returning only the caller's own rows.
  When filling in a missing name, look up only canvases the caller can
  open; never reveal the name of a canvas they cannot open.
- `getActivityMessage` is also used by the notifications page. Keep its
  one-row behaviour working there.
- Activity logging must never fail the request (keep the try/catch in
  `logActivity`).
</executor_constraints>

<steps>
1. New rows: in the three item routes and in `pile-transform.ts`, pass
   `canvasName` to `logActivity`. Read the name in the query that
   already loads or checks the canvas (add `name: true` to its
   `select`); do not add a second query when one already runs.
2. Old rows: in `GET /api/v1/activities`, for rows with a `canvasId`
   but no `canvasName`, look up the names in one extra query for all
   such ids on the page (canvases the caller owns or that are shared
   with them) and fill `canvasName` in the response. A canvas that no
   longer exists keeps no name.
3. Wording when there is still no name (canvas deleted): use
   `a deleted canvas` instead of `a canvas` for item rows.
4. Grouping. Add `groupActivities(activities)` to `activity-utils.tsx`.
   Neighbouring rows join into one group when they have the same
   `type`, the same `canvasId`, the type is `ITEM_CREATED`,
   `ITEM_UPDATED` or `ITEM_DELETED`, and each row is less than 60
   minutes from the next. A group shows the newest time and this text
   (N is the number of rows, name in the quote marks already used):
   - `added N items to "name"`
   - `updated N items in "name"`
   - `deleted N items from "name"`
   One row alone keeps today's text (`added an item to "name"`).
5. `ActivityFeed.tsx`:
   - title `Recent Activity` (or `Recent activity` if IMP-122 landed
     first) -> `Latest activity`;
   - render groups, not single rows;
   - show the first 5 groups; when there are more, show a button
     `Show all activity` that reveals the rest; after that the existing
     `Load more activity` button appears as today when the server has
     more;
   - the empty text stays `No recent activity`.
6. Tests: extend `tests/unit/dashboard-activity-feed.test.tsx`:
   seven `ITEM_CREATED` rows for one canvas within an hour render as
   one line `added 7 items to "Lisbon weekend"`; rows for two canvases
   stay apart; only 5 lines show before `Show all activity`; a row
   without a name reads `a deleted canvas`. Add an API test: a row
   stored without `canvasName` comes back with the canvas name; a row
   for a canvas the caller cannot open comes back without one.
</steps>

<acceptance>
- After adding 7 notes to "Lisbon weekend", the dashboard shows one
  line: `Added 7 items to "Lisbon weekend"` (the feed capitalises the
  first letter, as today), linking to that canvas.
- No line says "a canvas" for a canvas that still exists.
- The activity box shows at most 5 lines until `Show all activity` is
  pressed.
- The notifications page still renders its activity lines.
</acceptance>
