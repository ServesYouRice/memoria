# IMP-040 - Complete bounded response contracts

<objective>
Authenticated canvases, public shares, dashboard cards, and status consumers
use shared runtime-validated contracts and cannot silently omit durable items or
read fields the server never returned.
</objective>

<files>
`src/lib/api/bounded-response.ts`, `src/lib/api/response-schemas.ts`,
`src/app/api/v1/canvas-items/route.ts`, `src/app/api/v1/share/[token]/route.ts`,
`src/app/share/[token]/page.tsx`, `src/app/api/v1/canvases/route.ts`,
`src/lib/hooks/use-canvas-items.ts`, `src/lib/hooks/use-canvases.ts`,
dashboard/shared canvas cards and contract tests.
</files>

<context>
Reconciles Opus LOG-01, PERF-01, UI-01, UI-03, UI-04, UI-07, and LOG-20 with
Codex LOG-01/02, PERF-04, MAINT-03, and TEST-03. LOG-01 is High rather than
Critical because PostgreSQL rows are not destroyed. The quadratic encoder is a
coupled hot-path defect, not a separately proven outage blocker.
</context>

<steps>
1. Replace pre-truncation offset metadata with a stable authoritative
   continuation cursor based on the last row actually serialized. Prove every
   item is returned exactly once across byte boundaries and concurrent inserts.
2. Encode each item once and accumulate exact UTF-8 bytes in linear time while
   preserving the response budget and output validation.
3. Export inferred response types from runtime schemas and parse them at client
   fetch boundaries; remove `any` and hand-written drift from the affected
   hooks/pages.
4. Make the public share page consume nested canvas metadata and follow
   continuation until its completeness contract is met. Preserve title,
   viewport, errors, and revocation behavior.
5. Render private thumbnail endpoints using `thumbnailRevision` cache busting
   on dashboard/shared cards; remove the vestigial base64 thumbnail client type.
6. Use server pagination totals for dashboard counts and label loaded-only bulk
   selection truthfully.
</steps>

<acceptance>
- Large authenticated and public canvases never report completion while items
  are omitted by count or byte budget.
- Route and client fixtures share one runtime schema, and wrong envelope or
  thumbnail fields fail tests/type checking.
- Public shares show the saved name/viewport and all supported items; cards show
  authorized thumbnails with a safe fallback.
</acceptance>

<verification>
Focused response/route/component tests including byte-truncated and >50-item
canvases; real-PostgreSQL pagination test; `pnpm type-check`; `pnpm lint`.
</verification>
