# IMP-040 - Local verification instead of hosted CI

<objective>
Every check that `.github/workflows/ci.yml` runs today has a local, documented
command, and the repository no longer depends on GitHub Actions.
</objective>

<context>
Owner constraint (handbook): no GitHub Actions or other hosted CI; verification
stays local; a platform's own git integration may deploy. Unit tests read the
workflow file (`tests/unit/runtime-alignment.test.ts`,
`tests/unit/pre-push-test-selector.test.ts`), so the workflow and those tests
change together.
</context>

<files>
`.github/workflows/ci.yml`, `.husky/`, `package.json` scripts,
`tests/unit/runtime-alignment.test.ts`,
`tests/unit/pre-push-test-selector.test.ts`, `README.md`, `AGENTS.md`,
`implementation/KANBAN.md` (gate status line).
</files>

<steps>
1. List every job and step in `ci.yml`, including Firefox and WebKit E2E.
2. Add one local gate script (for example `pnpm gate`) that runs them in order,
   with the browser and service-backed parts as an explicit opt-in stage.
3. Point the runtime-alignment test at the new source of truth (package.json,
   Dockerfile, gate script) instead of the workflow file.
4. Remove the workflow and update docs that mention CI.
</steps>

<acceptance>
- No check is lost: each former CI step maps to a local command.
- Tests that pinned workflow content now pin the gate script and still fail on
  Node or pnpm drift.
- `.github/workflows/` is gone or holds nothing that runs on push.
</acceptance>

<verification>
`pnpm test -- --run`; `pnpm lint`; `pnpm type-check`; the new gate script.
</verification>
