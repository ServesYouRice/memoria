# IMP-105 - A timer everyone on the canvas sees

<objective>
When someone starts the timer, everyone working on that canvas sees the
same countdown.
</objective>

<context>
Approved by the owner on 2026-11-11; this replaces the earlier decision
DEC-012 that the timer is personal. Today `MeetingTimer.tsx` runs in one
browser tab only and `src/lib/product-surfaces.ts` says so
(`MEETING_TIMER_SCOPE`, `MEETING_TIMER_DISCLOSURE`). WebSockets already
carry short-lived collaboration signals such as who is present.
</context>

<files>
`src/features/canvas/components/MeetingTimer.tsx`,
`src/lib/product-surfaces.ts`, `src/lib/collaboration/`, `tests/unit/`,
`tests/e2e/`.
</files>

<executor_constraints>
Share an end time, not ticks, so clocks agree and late joiners are right.
The timer is a short-lived signal: nothing is written to the database and
it ends when the last person leaves. Only editors can control it; the
server checks that.
</executor_constraints>

<acceptance>
- Start, pause and reset by an editor show for everyone on the canvas
  within a second.
- Someone who joins later sees the correct time left.
- Viewers see the timer and cannot control it.
- The wording next to the timer says it is shared.
</acceptance>

<verification>
`pnpm test:file` for the timer tests; `pnpm gate fast`; `pnpm gate e2e` on
the dev machine with two browsers on one canvas.
</verification>
