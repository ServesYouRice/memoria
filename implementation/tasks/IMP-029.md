# IMP-029 — Truthful client errors and search

<objective>
Client actions retain input on failure, explain retryable limits, and display
server-authoritative search counts/facets.
</objective>

<steps>
1. Parse RFC 7807 once in the shared fetch client. Preserve request ID, status,
   safe detail, and `Retry-After`; retry only safe/idempotent requests.
2. Standardize dialog pending/error/success behavior. Await mutations and
   clipboard/export actions; keep form input after failure.
3. Add server-side search type/tag facets and total count. Escape fallback
   wildcard characters, bound query/tags, and recover FTS capability after
   transient failure.
4. Show total/facets and snippets for every item type; remove unsupported tag
   claims.
5. Test 429 timing, malformed proxy responses, dialog rejection, wildcard
   queries, later-page facets, and degraded FTS recovery.
</steps>

<acceptance>
- Rate limits never appear as generic data loss.
- Search count and filters describe the complete server result set.
</acceptance>

<verification>
Fetch/dialog/search tests; real-DB search tests; type/lint.
</verification>
