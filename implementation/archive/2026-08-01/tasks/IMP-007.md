# IMP-007 — Lossless autosave and cache rollback

<objective>
Edits made during a save or outage remain queued, conflicts are typed, and the
UI never displays rejected optimistic state as saved.
</objective>

<files>
`src/lib/hooks/use-autosave.ts`, `src/lib/hooks/use-canvas-items.ts`,
`src/lib/api/fetch-client.ts`, `src/lib/errors.ts`, `src/stores/canvasStore.ts`,
`src/features/canvas/components/CanvasHeader.tsx`.
</files>

<steps>
1. Implement one serialized delta queue. Merge changes during an active request,
   flush again in `finally`, and restore failed deltas.
2. Advance only from the server-returned item version. Return an awaitable flush
   for navigation/unmount recovery.
3. Snapshot and restore every list/detail cache touched by optimistic updates.
   Reconcile lists after all failures.
4. Detect version conflict by status/problem code, never message text.
5. Expose `saving`, `saved`, `offline/retrying`, `conflict`, and `failed` states.
6. Add fake-timer tests for edits in flight, failure/retry, unmount, navigation,
   and conflict.
</steps>

<acceptance>
- No pending delta is dropped when a request overlaps or fails.
- Rejected data is rolled back or clearly retained as unsaved recovery state.
</acceptance>

<verification>
Targeted hook tests; `pnpm type-check`; `pnpm lint`.
</verification>
