# IMP-023 — Contract cleanup and decomposition

<objective>
After correctness contracts stabilize, reduce duplicated boundaries and split
large modules without changing behavior.
</objective>

<files>
`src/proxy.ts`, `src/lib/api/route-handler.ts`, `src/lib/errors.ts`,
`src/lib/logger/index.ts`, `sentry.server.config.ts`, `src/lib/rate-limit/`,
`src/features/canvas/components/CanvasBoard.tsx`,
`src/lib/agents/service-core.ts`.
</files>

<steps>
1. Standardize one request/correlation ID from proxy through RFC 7807, logs, and
   Sentry. Migrate hand-written route wrappers to the shared handler.
2. Add shared response validation for canvas/item/auth hot paths; remove
   unvalidated boundary `any` values.
3. Delete proven dead/legacy paths, including obsolete rate-limit/config and
   serverless deployment hints. Preserve migrations/data compatibility.
4. Extract `CanvasBoard` by session controller, mutation queue, transport,
   capability policy, item adapters, and dialog commands. Split agent service
   core by ownership/side-effect boundary.
5. Use characterization tests and render/load profiles before each extraction.
</steps>

<acceptance>
- No parallel authoritative path remains for rate limits, API errors, or item
  mutation.
- Refactors preserve contract tests and do not broaden scope.
</acceptance>

<verification>
Affected contract tests; `pnpm type-check`; `pnpm lint`; `pnpm build`.
</verification>
