# IMP-011 — Identity-safe undo and redo

<objective>
Follow DEC-004: hide undo/redo, or make every advertised command reversible
without changing item identity or breaking relations.
</objective>

<files>
`src/lib/hooks/use-canvas-history.ts`,
`src/features/canvas/hooks/use-canvas-item-handlers.ts`,
`src/features/canvas/hooks/use-canvas-keyboard.ts`,
`src/app/api/v1/canvas-items/[itemId]/route.ts`, `src/stores/canvasStore.ts`.
</files>

<steps>
1. If `hide`, remove shortcuts/buttons and reject unsupported command paths.
2. If `repair`, specify command invariants for create, edit, move, resize, and
   delete. Add a restore endpoint that reactivates the original ID/version and
   dependent relations transactionally.
3. Store server-returned IDs/versions in the command stack. Redo must target the
   current restored entity, not stale identifiers.
4. Integrate with the serialized queue from IMP-007 and batch operations.
5. Test connections, comments, knowledge links, conflicts, reload, and repeated
   undo/redo.
</steps>

<acceptance>
- Undo never recreates a deleted item with a new ID.
- A failed command leaves durable and visible state unchanged/recoverable.
</acceptance>

<verification>
Real-DB command tests; canvas interaction tests; `pnpm type-check`; `pnpm lint`.
</verification>
