# IMP-019 — Real-database and production-auth tests

<objective>
Critical stateful flows run against migrated PostgreSQL, and browser auth tests
exercise production verification behavior.
</objective>

<files>
`vitest.config.ts`, `playwright.config.ts`, `tests/`, `tests/setup.ts`,
`.github/workflows/ci.yml`, `prisma/migrations/`, `package.json`,
`docker-compose.yml`.
</files>

<steps>
1. Add a `tests/integration` Vitest project gated by an explicit test database.
   Apply migrations from zero; never use `db push`.
2. Cover account/canvas deletion, trash restore, version restore, template use,
   upload lifecycle, idempotency replay, outbox claims, and rollback constraints.
3. Run Playwright against the production build with captured test email. Cover
   registration, verification/resend/expiry, login, reset, session revocation,
   upload, sharing, recovery, export, and account deletion.
4. Keep unit mocks for narrow logic; use real services for persistence claims.
5. Wire both suites into CI with deterministic seed/cleanup and retained logs.
</steps>

<acceptance>
- Tests fail on real constraint/cascade/transaction regressions.
- Production-only auth behavior is exercised in CI.
</acceptance>

<verification>
Integration project; production Playwright suite; `pnpm type-check`; `pnpm lint`.
</verification>
