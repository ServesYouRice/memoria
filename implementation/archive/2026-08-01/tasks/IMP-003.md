# IMP-003 — Registration modes

<objective>
Self-host operators explicitly choose `open`, `invite`, or `closed`
registration; development remains easy.
</objective>

<context>
Read DEC-001 in `implementation/KANBAN.md` before editing.
</context>

<files>
`src/lib/env.ts`, `.env.example`, `scripts/doctor.mjs`, `scripts/setup.mjs`,
`src/app/api/v1/auth/register/route.ts`,
`src/features/auth/components/RegisterForm.tsx`, `src/app/auth/register/`.
</files>

<steps>
1. Add a validated registration-mode environment value to `.env.example` and
   diagnostics/setup scripts. Use the selected production default and `open`
   for development/test unless explicitly set.
2. Enforce the mode in the registration API before expensive work.
3. Hide or relabel registration UI for closed/invite modes.
4. For `invite`, consume an expiring single-use invite without leaking whether
   an email is invited.
5. Test every mode and bootstrap-owner behavior.
</steps>

<acceptance>
- API enforcement cannot be bypassed by calling the route directly.
- `pnpm doctor` reports an unsafe or missing production choice.
</acceptance>

<verification>
Targeted env/auth tests; `pnpm type-check`; `pnpm lint`.
</verification>
