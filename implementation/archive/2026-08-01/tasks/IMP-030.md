# IMP-030 — Canvas command correctness

<objective>
Batch actions, viewport state, and inserted-item placement have one atomic,
tested contract.
</objective>

<files>
`src/features/canvas/hooks/use-canvas-alignment.ts`,
`src/features/canvas/hooks/use-canvas-interaction.ts`,
`src/features/canvas/components/AlignmentToolbar.tsx`,
`src/app/api/v1/canvas-items/route.ts`, `src/lib/hooks/use-canvas-views.ts`,
`src/app/api/v1/canvases/[canvasId]/views/route.ts`,
`src/stores/canvasStore.ts`.
</files>

<steps>
1. Add idempotent transactional batch endpoints for align, distribute, delete,
   and multi-create with one authorization check and per-item versions.
2. Replace fire-and-forget UI loops with one recoverable command result and
   deterministic z-index assignment.
3. Centralize tested `screenToWorld`/`worldToScreen` transforms for every AI,
   template, paste, drop, and creation source.
4. Store personal viewport in local/device or `CanvasView` state. Do not update
   canvas content recency/activity for pan/zoom. Keep any published default
   viewport explicit.
5. Test partial-failure rollback, retry idempotency, zoom extremes, recency, and
   collaboration conflict.
</steps>

<acceptance>
- Batch operations commit fully or not at all.
- Pan/zoom does not reorder canvases or create activity rows.
- All creation sources land at the intended world coordinate.
</acceptance>

<verification>
Real-DB batch tests; transform/UI tests; type/lint.
</verification>
