# IMP-006 — WebSocket permission and admission boundary

<objective>
Only authorized principals connect and only permitted roles send closed-schema
collaboration messages, with bounded resource use.
</objective>

<files>
`src/lib/collaboration/websocket-server.ts`,
`src/lib/hooks/use-collaboration.ts`, `src/types/collaboration.ts`,
`server.ts`, `src/middleware/cors.ts`, `src/lib/env.ts`.
</files>

<steps>
1. Require a short-lived canvas-scoped ticket or active share capability for
   guest/public upgrades. Validate `Origin`.
2. Require COMMENT or higher for chat/reaction messages; keep VIEW read-only.
   Replace arbitrary records with explicit message schemas.
3. Add per-client, per-principal, per-canvas, and global upgrade/socket budgets
   using the trusted identity from IMP-004.
4. Publish every supported ephemeral message cross-instance or declare the
   single-instance limitation in code/config.
5. Test private/public admission, revocation, role matrix, malformed payloads,
   limits, reconnect, and non-collaboration dev upgrades.
</steps>

<acceptance>
- Canvas ID alone is insufficient for guest admission.
- VIEW/guest users cannot broadcast mutating/social payloads unless explicitly
  granted that capability.
</acceptance>

<verification>
WebSocket integration tests; `pnpm type-check`; `pnpm lint`.
</verification>
