# IMP-017 — Convergent item synchronization

<objective>
Two editors observe committed item changes and deletion tombstones without
reloading full canvases every five seconds.
</objective>

<context>
Read DEC-007. Keep HTTP/Prisma as write authority. A one-instance launch may use
delta polling first; multiple instances require shared fanout and leases.
</context>

<files>
`src/lib/hooks/use-canvas-items.ts`, `src/lib/hooks/use-collaboration.ts`,
`src/lib/collaboration/websocket-server.ts`, `src/types/collaboration.ts`,
`src/app/api/v1/canvas-items/route.ts`, `src/lib/cache/canvas-cache.ts`,
`prisma/schema.prisma`.
</files>

<steps>
1. Define a versioned committed event/delta envelope: event ID, canvas, actor,
   entity/version, operation, permission scope, and schema version.
2. Publish only after commit through the outbox/event boundary. Clients merge by
   version and fetch missing data; include soft-delete tombstones.
3. Replace full polling with cursor/delta polling as fallback. Bound replay and
   force a snapshot when the cursor is too old.
4. For multi-instance mode, fan out all supported events and use expiring
   presence leases.
5. Test two users, conflicts, reconnect/replay, revocation, deletion, process
   loss, and selected topology.
</steps>

<acceptance>
- A committed edit becomes visible to another client within the stated target.
- Reconnect converges without downloading the full active set on every tick.
</acceptance>

<verification>
Two-browser + real-DB tests; multi-instance tests when selected; type/lint.
</verification>
