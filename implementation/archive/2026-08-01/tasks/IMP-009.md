# IMP-009 — SSR, theme, shortcut, and error baseline

<objective>
Pages render meaningful HTML before hydration, text inputs accept `?`, and
loading/error UI makes no false durability claim.
</objective>

<files>
`src/app/layout.tsx`, `src/lib/theme-context.tsx`, `src/lib/nonce.ts`,
`src/components/GlobalShortcutsProvider.tsx`,
`src/lib/hooks/use-keyboard-shortcuts.ts`, `src/lib/keyboard/shortcuts.ts`,
`src/components/ErrorBoundary.tsx`,
`src/features/canvas/components/CanvasErrorBoundary.tsx`.
</files>

<steps>
1. Render children on the server with a deterministic theme. Reconcile stored
   preference before paint without returning `null` for the whole app; preserve
   CSP nonce behavior.
2. Ignore global shortcuts inside inputs, textareas, contenteditable elements,
   editors, and active dialogs unless explicitly allowed.
3. Replace “your work has been saved” with state-aware neutral error copy.
4. Add canvas-scoped error recovery, `global-error`, and loading UI for slow
   protected routes using existing skeletons where possible.
5. Test server HTML, theme hydration, editable shortcuts, and error boundaries.
</steps>

<acceptance>
- Public pages have meaningful body content with JavaScript disabled.
- Typing `?` in any editor/form inserts the character.
- Error UI never claims a save without evidence.
</acceptance>

<verification>
Targeted UI tests; `pnpm type-check`; `pnpm lint`; production build.
</verification>
