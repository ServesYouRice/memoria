# IMP-024 — Viewport-first canvas data path

<objective>
Authenticated and public canvases load bounded visible data instead of complete
item sets, while search/export/selection remain coherent.
</objective>

<files>
`src/lib/hooks/use-canvas-items.ts`, `src/lib/hooks/use-virtual-items.ts`,
`src/features/canvas/hooks/use-canvas-data.ts`,
`src/app/api/v1/canvas-items/route.ts`, `src/app/api/v1/share/[token]/route.ts`,
`src/lib/api/pagination.ts`, `src/lib/services/search.ts`.
</files>

<steps>
1. Specify tile/viewport cache keys, overlap, merge/version rules, tombstones,
   off-screen selection, connections, frames, reconnect, search, and export.
2. Make bounded spatial/cursor queries the primary authenticated and public data
   path. Return metadata separately and enforce response-byte budgets.
3. Add summary endpoints for list/search/export needs instead of silently
   downloading all full items.
4. Show partial/loading/error state during pan and when launch limits are hit.
5. Add deterministic 2k/10k-item fixtures and gate payload, latency, memory,
   pan/zoom interaction, reconnect, and concurrent-edit budgets.
</steps>

<acceptance>
- Opening or polling a large canvas does not fetch every full item.
- Public anonymous reads have pagination, rate, and byte bounds.
</acceptance>

<verification>
Real-DB spatial tests; browser/load budget suite; type/lint/build.
</verification>
