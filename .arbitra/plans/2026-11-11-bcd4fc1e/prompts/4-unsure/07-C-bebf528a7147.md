<claim>
Prisma cursor pagination can silently cut a section short if the cursor row is deleted during the export (medium)

Each section pages with Prisma's `cursor: { id }, skip: 1`, using the last row's id from the previous page. Prisma turns a cursor into a subquery that looks up the cursor row (`id >= (SELECT id ... WHERE id = $cursor)`). If that row has been deleted between pages, the subquery returns no row, the comparison is NULL, and the page comes back empty. `writePages` reads a short or empty page as the end of the section and moves on. The export runs for minutes while the user can still edit, and deleting a canvas cascades to its items and uploads, so the cursor row can disappear mid-export. The archive then ends up COMPLETED with a whole section silently missing, and the manifest counts match the cut-off data, so nobody notices.
</claim>
