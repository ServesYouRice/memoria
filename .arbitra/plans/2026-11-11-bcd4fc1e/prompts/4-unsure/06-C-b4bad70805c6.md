<claim>
Every canvas item mutation queues a publish job whose default publisher always throws when Redis is not configured (medium)

`recordCanvasItemEvent` and `recordCanvasItemEventsBatch` queue a `canvas.event.publish` outbox job for every item mutation and never check whether Redis is configured. The default publisher in `createCanvasEventHandler`, and the one in the restore handler, throws a plain Error when `getRedisClient()` returns null. `getRedisClient()` returns null whenever REDIS_URL is unset. The rest of the collaboration stack treats a missing Redis as a supported setup: the websocket server and `SharedConnectionAdmission` both handle a null client. Because the thrown Error has no `retryable: false` flag, `failOutboxJob` re-queues the job as PENDING until it reaches maxAttempts and is marked DEAD.
</claim>

</what_the_verifier_said>
