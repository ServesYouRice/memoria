<claim>
An item larger than the response byte budget returns an empty page with hasMore=true and nextCursor=null, so loading stops at that item (medium)

If the first candidate item on a page serializes to more than `byteBudget` (512 KiB minus the envelope), the loop breaks before accepting anything. `lastAccepted` is then undefined, so the response has `items: []`, `hasMore: true` and `nextCursor: null`. There is no cursor that skips past the oversized item. Clients fall back to `offset=items.length`, which asks for the same oversized item again, get an empty page, and `break`. The infinite query's `getNextPageParam` likewise stops when nextCursor is null. Every item after the oversized one in zIndex order is never delivered.
</claim>
