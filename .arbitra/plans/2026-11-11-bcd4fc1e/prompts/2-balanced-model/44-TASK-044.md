<goal>
Make useCanvasData skip persisting a viewport that equals the loaded or last-saved one, and make the canvas PATCH skip logging CANVAS_UPDATED when only defaultViewport changed.

This matters because it fixes:
- Owners save the viewport with a canvas PATCH after every pan or zoom, and each save logs a 'updated canvas' activity (medium)
  The viewport effect in useCanvasData runs whenever zoom or position changes. About 750 ms after the gesture settles, it calls updateCanvas({ defaultViewport }) if the user owns the canvas. That sends PATCH /api/v1/canvases/:id. The PATCH handler does not treat a viewport-only change differently: it updates the canvas row, clears the Redis canvas cache and writes a CANVAS_UPDATED Activity row on every call. The dashboard feed shows each row as "updated canvas X". The save also runs just from opening a canvas. The init effect (lines 187-196) moves zoom and position from their defaults to the stored viewport, which triggers the persist effect. Any canvas whose saved viewport is not the default therefore sends a PATCH with unchanged values and gets a fake 'updated' activity on every open.
</goal>
